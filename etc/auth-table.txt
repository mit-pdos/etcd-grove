# The client port's registrations and their access control (notes/auth-mediation-scope.md, stage M0):
# one row per method, hook or HTTP path that `etc/authmed` (etc/authmed/main.go) finds registered on
# etcd's client port at the pin, checked by etc/auth-mediation-check.py (in etc/gates.sh).
#
# A row: KEY CLASS STATUS SPECS VOCAB WHY...
#   KEY     a gRPC method's full name (/service/method), or hook:ORIGIN:EXPR, or http:ORIGIN:PATH
#   CLASS   public | authenticated | rbac | admin | mixed (the auth matrix's, notes/auth-matrix.md),
#           or - for a hook or an HTTP path
#   STATUS  e2e        the handler's proved spec states the row's check for the request's principal,
#                      at the server's entry point (and the gRPC wrapper carries it)
#           e2e-apply  the same, with the check stated at the apply layer
#           contract   the wrapper is proved; its effect is an inner operation taken as a contract
#                      whose precondition needs the guard's token
#           server     the server's entry point is proved, the gRPC wrapper is names-only
#           guard      only the guard's spec is proved
#           none       nothing past the request check
#           public     public by design (no check required)
#           excluded   not covered, by decision; WHY says which and where it is recorded
#   SPECS   comma-separated spec files under Spec/, without `.lean` (S/ = go_etcd_io/etcd/server/v3/
#           etcdserver/, R/ = S/api/v3rpc/, A/ = S/apply/), or -: each must declare its `<F>.spec`,
#           have a proof file with `theorem <F>.wp_proof` and no `sorry`, and be linked (a Link.lean,
#           Results.lean or *Linked.lean applies `<F>.wp_proof`); a row of status e2e, e2e-apply,
#           contract or server names at least two (the guard's and the handler's)
#   VOCAB   comma-separated names, or -: each must occur in the text of one of the row's specs (the
#           guard's vocabulary; what a spec means is reviewed once per row, the gate keeps it there)
#   WHY     free text; required for none and excluded; every issues/, nonissues/ or notes/ file it
#           names must exist
#
# The baseline etc/auth-mediation-baseline.txt records each row's status; `--check` refuses a row
# weaker than its baseline, and a registration without a row.

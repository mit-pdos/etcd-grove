- spec_slices_Sort.v
Q: Why does the Go code sort if it's not necessary for correctness?
A: For deterministic tests, not for correctness. Go randomises map
   iteration order, and campaign enumerates the voters from the map that
   JointConfig.IDs returns. Upstream commit 07c1ab6 ("raft/rafttest:
   introduce datadriven testing", Tobias Schottdorf, Aug 2019) replaced
   `for id := range r.prs.Voters.IDs()` with collect-then-sort in the same
   change that added the datadriven interaction tests (testdata/*.txt,
   e.g. testdata/campaign.txt). Those tests compare the printed log lines
   and outgoing message lists verbatim ("sent MsgVote request to 2", then
   to 3, ...), so the order vote requests are appended to r.msgs must be
   reproducible. 065fbde later swapped sort.Slice for slices.Sort.
   ProgressTracker.Visit, JointConfig/MajorityConfig String and friends
   sort for the same reason.
   Nothing in raft depends on the order: each vote request is independent
   and the receiver cannot tell what order its peers were asked in. The
   model says the same thing: step_campaign (protocol.v:226) takes any
   `peers ≡ₚ elements (cfg ∖ {[id]})`, and proof_raft__campaign.v uses only
   the permutation conjunct of wp_slices_Sort (line 175 onward), never
   sortedness. That is why the spec's postcondition can be permutation-only.

    Progress struct; the records in the goose output and in generatedproof
    aren't always the right abstraction for a proof to use. For instance, this
    is the case with the `raft` struct, because of slices and pointer-indirection.
    Basically, in the case of Progress, there should be a new `Progress.t`
    record that has the contents of a Inflights record. The Inflights record should be
    written to be as abstract as possible while enabling specs for the public
    methods in inflights.go. There are also some private Inflights methods:
    these might require some notion of `own_Inflights` that's private and more
    detailed than the public `own_Inflights`; e.g., to track the buffer length.

  + TODO: rename to "own_Progress" instead of "own_progress" to match the case
    of the Go type. This should be done consistently for all predicate names so
    it's easy to correlate Rocq definitions with the corresponding
    definitions/concepts in Go.

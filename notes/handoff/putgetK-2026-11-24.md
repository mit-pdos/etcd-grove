# Handoff: `putgetK_safe` (n-member putget across machines), 2026-11-24

## Goal
A top-level `Robust` theorem `putgetK_safe`: an etcd cluster of **any number n of members, each on a machine of
its own, plus one client machine**, no crash, over the net extension: no thread of any machine is stuck or
panics, so the client's `Get` after an acknowledged `Put` returns the `Put`'s value. It generalizes the
two-machine `putget_safe` (`Spec/github_com/mit_pdos/etcd_grove/examples/etcd/dist/putget/TopLevelRobustness.lean`,
branch `dist-putget-interim/2026-11-24`, now on `lean`). Plan and record: `notes/putget-dist-plan.md` §13 and
§13b (on this branch).

## Pitfalls
- **Builds go on the VM** (`/shared/tmp/vm/vmlake`), with a local `.lake/packages` copy at the manifest revs: the
  VM's own Perennial clone got corrupt after a pin bump ("could not resolve HEAD"). Exit 75 means the VM is
  unreachable: wait, don't build big locally.
- `wp_start` consumes the precondition's `isPkgInit` itself: write `wp_start as H`, not `⟨#Hpkg, H⟩`.
- IPM can't destruct a pure `→`; use `-∗` in preconditions.
- A `[HasExt netExt]` binder needs `open Net` (for its `ExtSemantics` instance).
- `decide` fails on goals mentioning the `GooseExts` instance variable; `dsimp only` record projections first.
- Never `pkill -f` a pattern that matches your own shell.
- Never write scratch to `/tmp` (a quota shared by all sessions).

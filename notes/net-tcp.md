# TCP at the `net` level: the extension, its specs, and the examples

Started 2026-11-12 (branch `net-tcp`). The goal: a semantics of Go's `net` TCP connections as a
GooseLang extension, generic Iris specs over network points-to resources, and a suite of minimal
programs that use `net.Conn` as real clients do (net/http, grpc-go), each verified end to end
with an adequacy theorem.

## The semantics, and why

The model's state is what the user asked for: the global state is every connection between
endpoints, each with the bytes sent and not yet received per direction, and a crash of a machine
does not clear them. The header of `Impl.lean` states every operation; the decisions behind it:

- **Global network, local listeners.** Connections are global (`TcpGlobal.conns`): DistLang's
  crash keeps the global state, so the bytes in flight survive the crash of either end, as they do
  in reality (the peer can still read what was sent before the crash). Listeners are the node's
  (`TcpLocal.lis`) and are dropped at a crash: a restarted process may listen again.
- **One out-pipe per end**: `sent` (every byte the end ever wrote), `rcvd` (how many of them the
  other end has read), `fin`. In flight = `sent.drop rcvd`. Keeping `sent` whole (not a queue) is
  what makes the ghost state simple: an end's written bytes are a monotone list (`tcpOut`,
  `tcpOutLb`), and a reader's position is a number (`tcpEnd`'s `r`).
- **Any operation may fail at any time**, and a read returns any nonzero number of the bytes in
  flight (up to the buffer): the guarantees are only what no failure can break (order, no
  invention, EOF only after the writer's FIN with nothing in flight).
- **Broken ends.** A failed read or write with no deadline set marks the end broken (Linux: an
  error on a socket with no deadline is a dead connection); a broken end's close sends no FIN. So
  EOF means the writer closed or shut down after all its writes succeeded (or with a deadline
  set). This is what makes "read until EOF" protocols (`halfclose`) provable.
- **No process exit.** Go's runtime FINs a process's sockets when it exits, which the model does
  not do; every example node ends with `wire.Forever()` (`examples/net/README.md`).
- **Addresses are plan strings**: the deployment's plan names each address and the host that may
  listen at it; `Listen` elsewhere or `Dial` of a string not in the plan is stuck (the trusted
  models only pass what the program does, and the adequacy theorem assumes the plan).
- **Handles are ids** inside `net`'s unexported structs (`conn.id`, `TCPListener.lid`), which a Go
  program cannot forge.

## The resources and specs

`Ghost.lean`'s header lists them: `tcpPlan a h`, `tcpPend a S` (the connections dialed to `a` and
not yet accepted: what makes dial and accept a per-address protocol), and per end `tcpEnd c s st
r`, `tcpOut c s bs f`, `tcpOutLb c s bs`, `tcpFin c s bs`, `tcpConnAt c a`; locally `tcpLis l a o`.
`tcpOut` is exclusive per end (`tcpOut_excl`, through a token), so a protocol can store "this
end's written bytes" in an invariant and know nobody else holds them.

The Go-level specs (`NetTcp/Spec/net/`) are logically atomic: `Dial`, `Accept` take an update
over the address's pending set; `Read`, `Write`, `Close` an update over the end's state and its
written bytes. A thread that owns its end supplies trivial updates (`wire.owned_write_au`,
`owned_close_au`, `owned_close_drop`); a protocol that shares an end supplies them from its
invariant.

## The proof pattern (echo)

`wire/Addr.lean`: the address's invariant `addrInv a Φ` holds `tcpPend a S` and, for each pending
connection, the dialer's deposit `Φ cn`; `dial_au` and `accept_au` are the atomic updates of
`Dial` and `Accept`. echo's deposit is the acceptor's fresh end and a token; one invariant
(`echoState`, a ghost map of token names) keeps, per connection, the acceptor's written bytes as a
prefix of the dialer's, which gives the client's check. `Results.lean` instantiates
`goose_dist_crash_adequacy` (Perennial `GooseLang/DistAdequacy.lean`) for the three nodes; the
global setup allocates the invariants from the network's start resources, each node's start gives
its host, and a crash keeps the host (the rest is persistent).

Two technical points: the protocol's definitions are stated over `GooseGlobalGS` (not `HeapGS`),
so the global setup, which has no local ghost state, can allocate them; a fancy update from such a
lemma is not seen as a modality by `imod` inside a node proof (its invariant instance is unfolded
differently), so the node file restates the few lemmas it `imod`s (echo's `client_check'`).

## Status

All proved end to end, with no `sorry` and no axiom of this repository; each `Results.lean` ends
with `#print axioms` of its theorem, which lists only Lean's three and the translation's
axiomatized Go types (`net.Dialer`, `sync.Map`, ..., which `etc/tcb-report.py` counts as
Perennial's), and for preface Perennial's `time.Now.wp_proof` (the only spec of `time.Now`).

## Changes made along the way

- **`wire.ReadFull` over a reader predicate** (2026-11-14). Its spec owned the end (`tcpEnd`); duplex
  reads an end its writer goroutine also uses. Now the caller supplies `P r` (its knowledge that
  `r` bytes have been read) and a persistent accessor `□ ∀ r, P r -∗ |={⊤,∅}=> ∃ st, tcpEnd .. st r
  ∗ ∀ st' r', tcpEnd .. st' r' ={∅,⊤}=∗ P r'`, used once per `Read`. A thread that owns its end uses
  `wire.ReadFull.owned` (`wire/ReadFullOwned.lean`, a corollary): the old statement, except that the
  end's state after a full read is no longer said to be unchanged (no caller needed it).
- **Listeners shared between threads** (2026-11-14). `tcpLisAt l a` (persistent; `Ghost.lean`: a
  second ghost map, of the listeners' addresses, whose entries never change) says the listener
  exists; `Listen` returns it. The extension's `Accept` is logically atomic over `tcpLis l a o ∗
  tcpPend a S` with a failure branch (both unchanged) and a success branch owed only when
  `o = true`; the update is opened only at the step that decides, since an `Accept` may first wait
  (which is why reducibility needs `tcpLisAt`, not the update). `LisClose` is logically atomic over
  `tcpLis`. Go level: `Listener.Accept.spec` takes `tcpLisAt` and that update; the new
  `Listener.Close.spec`; an owned listener's update is `wire.accept_lis_au`. So an `Accept` after
  `Close` provably fails, and a listener can sit in an invariant shared with a thread blocked in
  `Accept`.

## Known gaps (sound, could be sharper)

- No law from `tcpFin c s bs` to `tcpOutLb c s bs` (halfclose works around it with a length match
  and a lower bound); the FIN's ghost state could give it.
- `CloseRes` for `CloseWrite` (`canFail = true`) leaves the result free in its success branch, while
  the semantics returns `true` there (`CloseWriteStep`).
- `SetDeadline(time.Time{})` (clearing) records a deadline as setting one does (`dl` stays `true`),
  so after clearing, a failure still does not break the end: more behaviors than Go, sound.

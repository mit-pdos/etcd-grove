# TCP at the `net` level: the extension, its specs, and the examples

Started 2026-11-12 (branch `net-tcp`). The goal (the user's): a semantics of Go's `net` TCP
connections as a GooseLang extension, whose global state is the network's connections with their
sent-but-not-received bytes, kept across a machine's crash; generic Iris specs over network
points-to resources; and minimal programs that use `net.Conn` as real clients do (net/http,
grpc-go), each verified end to end with a distributed adequacy theorem.

## The semantics (v2.1, 2026-11-14)

**Only observable state** (the user, 2026-11-14: "make sure the semantics is not designed for proof
convenience. It should be easy to audit, and as a general principle, operational semantics and
specs should avoid unobservable state (e.g., the past operations are unobservable)";
`.claude/skills/spec/PRINCIPLES.md`). The global state is the plan (address → host) and the
connections; a connection is its address, whether accepted, two ends (`TcpEnd`: `closed`, a read
deadline, a write deadline) and two directions (`TcpDir`: the unread bytes, oldest first, and a
status `open | fin | cut`). A node's local state is its host and its listeners. No history.

**Each operation's outcome is a pure relation** on one end's state and one direction
(`ReadOutcome`/`ReadAvail`, `WriteOutcome`, `CloseOutcome`, `CloseWriteOutcome`, `DeadlineOutcome`);
the step looks the connection up, takes an outcome and writes it back, and the specs state the same
relations verbatim, so what an auditor checks against Linux is exactly what proofs get.

**Faults.** A connection may break at any read or write: the direction becomes `cut`, a prefix of
its unread bytes survives, and the read answers as on a broken direction (bytes, EOF or an error).
That covers resets, kernel timeouts, and the death of a peer's process (its kernel's FIN or reset:
`TestKilledWriterFin`, `TestKilledResetTakenByWrite`) or machine. So **EOF guarantees nothing**
beyond "no more bytes will come"; what a reader read is a prefix of what the writer wrote (order, no
invention), never a promise of completeness. Timeouts only with a deadline set, and they lose no
byte. A failing write appends a shorter prefix, or nothing (an empty write can fail:
`TestEmptyWrite`).

**Crashes** are node-local (an extension's crash relation sees only the node's local state): the
node's listeners are gone, connections stay; what the peers see of the dead node's connections is
covered by cuts. For the same reason (a step sees only its own node and the network) pending
connections belong to the address, not to a listener, and `Dial` does not check for a listener:
more behaviors than Linux (which refuses or resets), each sound.

**Handles**: ids inside `net`'s unexported structs; id 0 (a zero-value `TCPConn`/`TCPListener`)
names nothing, so a program using one is stuck (Go returns `EINVAL`).

**The deployment** (D13) every theorem assumes: a closed world (nothing outside the system uses the
plan's addresses), addresses that do not alias (canonical `IP:port`, no hostnames or wildcards),
ports outside the ephemeral range, and the target configuration (Linux 7.0 defaults, Go 1.27.3).

### History of the design

- **v1 (2026-11-12/13)**: each direction was "every byte ever sent" plus a read count, an end had a
  `broken` flag (a failure with no deadline) and a broken end sent no FIN, so EOF meant the writer
  had finished cleanly. I chose the history for proof convenience (a monotone list gave lower
  bounds directly) and did not raise it, though the user had asked for the unread bytes: the
  departure the principle above now rules out. A comparison with dsverify-lab's network model found
  two unsound points: EOF without a FIN after a reset was excluded, and a node crash was a machine
  crash (no FIN) while the examples ran on one machine, where a crash is a process kill, which FINs:
  halfclose's guarantee had no real deployment.
- **v2 (2026-11-14)**: the state above; the measured tests (`examples/net/semantics/`) refuted its
  first draft (a break returned only an error; a killed process's FIN gives a plain EOF), fixed by
  letting a break answer as a read of the broken direction.
- **v2.1 (2026-11-14)**: the soundness review (`notes/axiom-review/tcp-semantics.md`) refuted v2
  with a proved counterexample (an empty `Write` could only succeed), and found id 0 naming a
  connection end and the deployment unstated; all fixed.

## The resources and specs

`Ghost.lean`: `tcpEnd c s st` (the end's state), `tcpDir c s d` (the direction from end `s`,
exclusive), `tcpConnAt c a`, `tcpPend a S` (the connections dialed to `a` and not yet accepted),
`tcpPlan a h`, `tcpLis l a o` and `tcpLisAt l a` (persistent: the listener exists). The extension's
WPs and the Go-level `net` specs are logically atomic over them, with the outcome relations as their
post; a waiting operation (`Read`, `Accept`) opens its update only at the step that decides, so ends
and listeners can live in invariants shared by threads (duplex's reader and writer, shutdown's
blocked `Accept` and `Read`).

**What proofs add on top, as ghost state** (`wire/Stream.lean`, proved, not trusted): per direction,
the writer's written bytes and the reader's read bytes, tied to the unread bytes by `dirInv`
(`DirOk`: read ++ unread = written until a cut, a prefix after); `read_au` gives `sentLb` (what was
read was written). The examples' protocols are built from it. `wire.ReadFull`'s spec takes a reader
predicate of the bytes it read (the buffer's contents) and a per-`Read` accessor.

## The examples

All seven are proved end to end over v2.1 (`lake build`, 2026-11-14), each `<ex>_crash_safety` over
`goose_dist_crash_adequacy` with no `sorry` and no axiom of this repository; `#print axioms` lists
Lean's three, the translation's axiomatized Go types, and for preface Perennial's
`time.Now.wp_proof`.

| Example | Theorem | Nodes | Shape of the proof |
|---|---|---|---|
| echo | `echo_crash_safety` | 3 | the dialer's deposit; one invariant over a ghost map of names per connection (both directions' `dirInv` bodies, the server's written bytes a prefix of a lower bound of the client's); each direction's `inv` derived (`inv_alter`) |
| framed | `framed_crash_safety` | 3 | as echo, many writes: a ghost copy of the server's bytes for the serving thread |
| acceptloop | `acceptloop_crash_safety` | 2 | echo's protocol per connection; goroutines per connection and per call |
| duplex | `duplex_crash_safety` | 2 | the client's end shared by its writer goroutine and its `ReadFull` reader through an invariant |
| halfclose | `halfclose_crash_safety` | 2 | the reply is a prefix of the request (the check was weakened: EOF proves nothing) |
| preface | `preface_crash_safety` | 3 | deadlines set and cleared (`DeadlineOutcome`, Go's `Time.IsZero`) |
| shutdown | `shutdown_crash_safety` | 1 | a listener and an end shared with blocked goroutines; every operation after `Close` fails |

## Open

- `Conn.Read`'s count: `ReadOut` gives only `sint.nat k = min …` (so `k`'s sign is free when the
  minimum is 0), because Perennial's `wp_slice_copy` gives only that; a stronger copy spec in
  Perennial would pin it (`notes/perennial-changes.md`).
- The examples share local lemmas that belong in `wire/` (a `dial_au` whose deposit gets both new
  ends, a `dirInv` body without its `inv`, deriving a direction's `inv` from a ghost-map invariant).
- The examples run as one process in their Go tests; making each node a separate process, with the
  top-level theorem over those processes' programs, is next.

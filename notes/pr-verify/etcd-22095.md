## Verdict

The new compactor does what the PR says it does, as far as it is verified. It only ever issues
non-physical compactions (no defrag). Each one keeps the last `--auto-compaction-retention`
revisions of the revision the store reported, is at a positive revision, and is above the last
compaction that succeeded (or was already done). The goroutine does not panic. `Pause`, `Resume`
and `Stop` return, and the compactor meets the contract the server's apply loop already assumes of
`s.compactor`. `New` picks the right compactor for each mode. Every proof is finished, with no
`sorry`.

The proof does not cover *when* it compacts. Go's floats are opaque in the model, so the
projection, the rate estimate, the cooldown and the claim about staying under the quota are not
verified, and neither is termination after `Stop`. Tests show two gaps in exactly that part:

- `Size()` is the backend's file size, which compaction never lowers. Once the file has passed 70%
  of the quota (after a burst, or a store restored from a large snapshot), the mode compacts every
  minute whenever anything was written, whatever the growth rate. It never "backs off" again
  without a defrag.
- With the quota disabled (`--quota-backend-bytes` negative), the mode still steers to 70% of
  2 GiB.

There are also smaller issues:
- the logged "projected-time-to-high-water" overflows;
- `Stop` does not wait for the goroutine, so the PR's `embed` test can race under `-race` when it
  restores the tuning variables;
- a duration or negative `--auto-compaction-retention` is accepted in the new mode, as in the
  revision mode. That is existing code, recorded in `issues/`.

## The specs

All are in `Spec/go_etcd_io/etcd/server/v3/etcdserver/api/v3compactor/`, over
`Proof/.../v3compactor/Defs.lean`:

- **`isAutoPeriodic ac P`** (persistent): the fields `lg`, `clock`, `retention`, `maxBytes`, `rg`,
  `c`, `sg`, `ctx` and `cancel` at `↦□`; `ctx` a cancellable context with its `cancelSpec`; and
  `sync.isMutex ac.mu (∃ b, ac.paused ↦ b)`. Every access to `paused` is under the mutex
  (`Pause`, `Resume` and `Run`), so this is the whole shared-state invariant.
- **The callee contracts**, premises of `Run`'s spec rather than axioms:
  - `clockwork.isClock` (`Now` returns a time; `After` returns a channel of times, `isChanBag`);
  - `apSizeOk` (`Size()` returns some `int64`);
  - `apRevOk rg R` (`Rev()` returns `v ≥ 0` with a persistent `R v` the caller picks);
  - `apCompactOk c R T retention`. A `Compact(ctx, req)` is allowed only when `req` is a
    non-physical request at revision `r`, `0 < r`, `r + retention = v` for a `v` with `R v`, and
    `p < r` for the last `p` that `T` records. It returns an error `errors.Is` can classify, and
    `T p ∧ |==> T r`.
- **`AutoPeriodic.Run.spec`**: under the contracts, `apTuning` (the tuning variables are read-only),
  `apErrCompacted`, `T 0`, a non-nil logger and `0 ≤ retention`, `Run()` returns `()`. Its
  goroutine is safe (`wp_fork` requires no panic), and every `Compact` it issues meets
  `apCompactOk`'s precondition. Discharging that precondition is the heart of the proof:
  - the `rev <= 0 || rev <= prev` guard gives `0 < r` and `p < r`;
  - `rev := Rev() - retention`, with `v ≥ 0` and `retention ≥ 0`, gives `r + retention = v`
    without overflow;
  - `prev` advances (`T r`) exactly on `err == nil` or `errors.Is(err, mvcc.ErrCompacted)`.
- **`New.spec`**: `newResult`, as in the table. Its premise for the periodic mode,
  `10 ≤ |retention|`, comes from the periodic constructor's postulate.

None of these functions existed before, so there is no old spec to compare against or to check
against the old code.

## What the proof rests on

New axioms (trust boundary), each a names-only callee:
- `clockwork.NewRealClock.wp_proof`: returns an `isClock`. The real clock is `time.Now` /
  `time.After`, and `time.After`'s channel gets one time and is never closed.
- `zap.Float64.wp_proof`: returns a field, like the other zap field constructors.
- `v3compactor.newPeriodic.wp_proof` and `newRevision.wp_proof`: return a pointer. The periodic
  one has the premise `10 ≤ |retention|`, because below that the Go code divides by zero (review
  finding).
- Changed: `time.Duration.Seconds_ptr.wp_proof`, generalized to any fraction. It is a value method
  that only loads the variable.

New model assumption (not an axiom; an instance argument of `Run`'s spec and result):
`Float64ToInt64Semantics`. Go's `int64(f)` steps to an opaque function of the float's bits.
Perennial has no step for this conversion (`notes/STATUS.md`, `notes/decisions.md`). It is
consistent, and faithful to Go: the conversion never panics, truncates in range, and is
implementation-defined out of range. Only the logged `eta` and `highWater` depend on its value.

Existing trust base reused: etcd-grove's `errors.Is`, `fmt.Errorf`, `time.Time.IsZero` and
`Duration.Seconds` axioms, zap's `Int64`/`Duration`/`Error`/`Info`/`Warn`/`NewNop`, and
Perennial's `time.Now` (assumed) and `context` results. **No `sorry`.** `#print axioms` of
`compactor_new`, `compactor_run` and `compactorOk_autoPeriodic` (`Results.lean`, in the build
log) lists exactly these plus Perennial's axiomatized types.

## Findings

**In the PR** (each with a test in `notes/pr-verify/etcd-22095/`; the README has the commands):

1. **The size it steers by never goes down.** `AutoPeriodic` samples `Backend.Size()`, the bbolt
   file size, which compaction does not lower (`SizeInUse()` would). Once `Size()` is above
   `AutoPeriodicHighWater × quota`, `shouldCompact` stays true and the mode compacts at every
   cooldown (1 minute) whenever a revision was written: 10 compactions in 10 minutes at zero
   growth (`pr-head/autoperiodic_probe_test.go`). The PR's own `embed` test ends at 129.4 MiB
   against a 128 MiB high-water mark, that is, in this regime. "An idle store backs off" holds only
   while the file is below the high-water mark.
2. **A disabled quota is replaced by the 2 GiB default.** `NewServer` maps
   `QuotaBackendBytes <= 0` to `DefaultQuotaBytes`. A negative value means the quota is disabled
   (`storage.NewBackendQuota` returns a pass-through quota), but the mode still steers to 1.4 GiB
   (`reviewer/reviewer_embed_test.go`, `TestReviewerAutoPeriodicQuotaDisabled`).
3. **The logged projected time overflows.** Above the high-water mark the smoothed rate decays
   geometrically, so `time.Duration(float64(highWater-size)/rate) * time.Second` wraps. The log
   shows positive values and then `0s` where the true value is negative
   (`TestReviewerEtaOverflow`). This affects the log only.
4. **`Stop` does not wait for the goroutine,** which keeps reading the tuning variables. The PR's
   `embed` test restores them after `e.Close()` (deferred, last-in first-out), which is a data race
   under `-race` (`TestReviewerStopThenWriteTuningRace` reproduces the pattern).
5. **The new mode inherits the revision mode's retention parsing.** `5m` means 300,000,000,000
   revisions, so it never compacts. `-1h` is accepted, and every sample then fails with
   `ErrFutureRev`: there is no cooldown after a failure, so that is every 10 s
   (`pr-head/compaction_retention_probe_test.go`). `Run`'s spec records `0 ≤ retention` as a
   premise.

**In existing code**, in `issues/etcd-compaction-retention-duration.md`:
- in the revision mode, a duration retention is silently misread;
- a negative retention is accepted. In the periodic mode it makes the compactor spin and compact at
  the current revision (etcd#22396, open, rejects negative values);
- a periodic retention of 1–9 ns makes `New` panic with a division by zero at startup (found by the
  review: the periodic constructor's postulate first claimed it returns).

**Reviewer's open points** (not fixed, recorded):
- `apCompactOk`'s `T p ∧ |==> T r` lets `T` track only `Run`'s own `prev`, not the store's
  compacted revision. The callee must offer `T r` even on failure, because `errors.Is` is opaque
  (its spec returns any bool), so `Run` cannot tell the callee which case happened.
- Nothing says no compaction starts while the compactor is paused, nor anything about liveness or
  the goroutine ending after `Stop`.

## Draft review comment (for the user to edit and post)

> Thanks, this is a nice idea. A few things I noticed while testing it:
>
> 1. `Backend.Size()` is the bbolt file size, and compaction doesn't shrink it (only defrag
>    does). Once the file has crossed `AutoPeriodicHighWater * quota`, `shouldCompact` stays
>    true forever, so the mode compacts every `AutoPeriodicCooldown` whenever there was any
>    write, regardless of the growth rate. With a fake clock, a constant `Size()` of 800 against a
>    quota of 1000 and one write per sample, it compacts 10 times in 10 minutes. Would
>    `SizeInUse()` be the better signal (it drops as compaction frees pages)?
> 2. In `NewServer`, a negative `QuotaBackendBytes` means the quota is disabled
>    (`NewBackendQuota` returns a passthrough quota), but the compactor is given
>    `DefaultQuotaBytes`, so it still steers to ~1.4 GiB. Maybe skip the size trigger, or
>    document it, when the quota is disabled.
> 3. The `projected-time-to-high-water` log field can overflow: above the high-water mark the
>    smoothed rate decays toward 0 and `time.Duration(float64(highWater-size)/rate) *
>    time.Second` wraps (I saw positive values, then `0s`).
> 4. `Stop()` only cancels the context. The goroutine keeps reading `AutoPeriodicSampleInterval`
>    etc. for a moment, so `TestAutoPeriodicCompactionMode` restoring them after `e.Close()` can
>    trip the race detector.
> 5. `parseCompactionRetention` handles `auto-periodic` like `revision`, so `--auto-compaction-
>    retention=5m` becomes 300,000,000,000 revisions (never compacts), and `-1h` becomes a
>    negative retention (a future-revision compaction attempted every 10 s, since failures skip
>    the cooldown). That predates this PR for the revision mode, but it may be worth rejecting
>    non-integer and negative values for the revision-count modes.

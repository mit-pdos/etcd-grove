## 1. Summary of the Change

In `server/etcdserver/api/membership/cluster.go`, `(*RaftCluster).IsLocalMemberLearner` looks up `c.localID` in `c.members` under `c.RLock()`:

```go
func (c *RaftCluster) IsLocalMemberLearner() bool {
	c.Lock()
	defer c.Unlock()
	localMember, ok := c.members[c.localID]
	if !ok {
		c.lg.Debug(
			"failed to find local ID in cluster members; the member may have been removed",
			zap.String("cluster-id", c.cid.String()),
			zap.String("local-member-id", c.localID.String()),
		)
		return false
	}
	return localMember.IsLearner
}
```

Prior to PR `#22188`, the `!ok` branch called `c.lg.Panic(...)` before `return false`. However, when the local member is removed via `ConfChangeRemoveNode` in `EtcdServer.applyConfChange` (`server/etcdserver/server.go:1872`), `s.cluster.RemoveMember(id)` immediately deletes `c.localID` from `c.members` and inserts `c.removed[c.localID] = true`, while `EtcdServer.applyEntries` (`server/etcdserver/server.go:1225`) only schedules server shutdown asynchronously after a 1-second delay (`go s.stopWithDelay(10*100*time.Millisecond, ...)`).

During this window (and during shutdown), `IsLocalMemberLearner()` can be called when `c.members[c.localID]` is absent via two paths:
1. **Unguarded callers (`etcd-io/etcd#21966`)**:
   - `(*server).Status` in `server/etcdserver/api/v3rpc/maintenance.go:281` calls `s.isLearner()` (`EtcdServer.IsLearner()`) on every `Maintenance/Status` gRPC request without checking `IsMemberExist`.
   - `learnerCheck` (`/readyz/non_learner`) in `server/etcdserver/api/etcdhttp/health.go:440` calls `s.IsLearner()`.
   - `(*EtcdServer).waitLeader` in `server/etcdserver/v3_server.go:880` calls `!s.IsLearner()`.
2. **TOCTOU window in gRPC interceptors ([`issues/etcd-unary-interceptor-learner-removed.md`](../../issues/etcd-unary-interceptor-learner-removed.md))**:
   - `newUnaryInterceptor` (`server/etcdserver/api/v3rpc/interceptor.go:75`) and `newStreamInterceptor` (`interceptor.go:248`) evaluate `if s.IsMemberExist(s.MemberID()) && s.IsLearner()`. Because `IsMemberExist` and `IsLearner` acquire and release `c.Lock()` (`c.RLock()` in upstream Go) separately, a concurrent `RemoveMember` on the apply goroutine between the two calls caused `IsLocalMemberLearner()` to panic.

PR `#22188` replaces `c.lg.Panic(...)` with `c.lg.Debug(...)` so `IsLocalMemberLearner()` returns `false` cleanly when `c.localID` is absent from `c.members`.

## 3. Findings & Open Points

### Finding 1 (Minor / Semantic Caveat): Removed learner is reported as a non-learner during the 1-second `stopWithDelay` window
- **Location**: `server/etcdserver/api/membership/cluster.go:801-817`, `server/etcdserver/api/etcdhttp/health.go:440-446`, `server/etcdserver/server.go:1225`
- **Description**:
  When a local member that is an unpromoted **learner** (`IsLearner == true`) is removed from the cluster via `ConfChangeRemoveNode`:
  1. `s.cluster.RemoveMember(id)` immediately deletes `c.localID` from `c.members` (`cluster.go:467`).
  2. `applyEntries` schedules `go s.stopWithDelay(10*100*time.Millisecond, ...)` (`server.go:1225`), leaving the server running for 1 second before `s.Stop()` is called.
  3. During that 1-second window, `c.IsLocalMemberLearner()` now returns `false` instead of `true`.
  4. Consequently, the `/readyz/non_learner` health check (`learnerCheck` in `server/etcdserver/api/etcdhttp/health.go:440-446`, which checks only `if s.IsLearner()`) transitions from failing (`"local member is a learner"`) to succeeding (`200 OK`) for 1 second on a removed learner that was never promoted to a voting member.
  5. Note that `RaftCluster` does not store whether entries in `c.removed` (`map[types.ID]bool`) were learners or voting members, so `RaftCluster.IsLocalMemberLearner()` alone cannot distinguish a removed learner from a removed voting member unless `Member` metadata or a local-learner flag is retained on removal, or `/readyz/non_learner` also checks `s.IsMemberExist(s.MemberID())`.
- **Reproduction / Probe Test**:
  [`notes/pr-verify/etcd-22188/cluster_pr22188_probe_test.go`](etcd-22188/cluster_pr22188_probe_test.go) (`TestProbeRemovedLearnerReportedAsNonLearnerDuringShutdownWindow`), log in [`notes/pr-verify/etcd-22188/probe-test.log`](etcd-22188/probe-test.log).

### Note 2: Subsequent shutdown race in `Maintenance/Status` (`v3rpc/maintenance.go:282`)
- As noted by the PR author in the PR description, once `(*server).Status` in `server/etcdserver/api/v3rpc/maintenance.go:281` no longer panics at `s.isLearner()`, a concurrent `Maintenance/Status` RPC arriving after `s.Stop()` closes the bbolt backend can reach `s.StorageVersion()` (`maintenance.go:282`) -> `schema.DetectSchemaVersion` -> `bbolt.(*Tx).Bucket`, causing a nil-pointer dereference if the read transaction is used after backend teardown. Addressing that shutdown lifecycle race is appropriately left to a separate PR.

## 1. Summary of the Change

PR `etcd-io/etcd#21209` makes three changes:
1. **`client/v3/kubernetes/interface.go`**:
   - Adds `Keys(ctx context.Context, prefix string, opts KeysOptions) (KeysResponse, error)` to `kubernetes.Interface`.
   - Defines `KeysOptions{Revision int64}` and `KeysResponse{Keys [][]byte, Count int64, Revision int64}`.
2. **`client/v3/kubernetes/client.go`**:
   - Implements `(k Client) Keys(ctx context.Context, prefix string, opts KeysOptions) (resp KeysResponse, err error)`:
     ```go
     func (k Client) Keys(ctx context.Context, prefix string, opts KeysOptions) (resp KeysResponse, err error) {
     	rangeEnd := clientv3.GetPrefixRangeEnd(prefix)
     	rangeResp, err := k.KV.Get(ctx, prefix, clientv3.WithRange(rangeEnd), clientv3.WithKeysOnly(), clientv3.WithRev(opts.Revision))
     	if err != nil {
     		return resp, err
     	}
     	resp.Keys = make([][]byte, len(rangeResp.Kvs))
     	for i, kv := range rangeResp.Kvs {
     		resp.Keys[i] = kv.Key
     	}
     	resp.Count = rangeResp.Count
     	resp.Revision = rangeResp.Header.Revision
     	return resp, nil
     }
     ```
3. **`tests/robustness/traffic/kubernetes.go`**:
   - Adds `KubernetesCount` (3% weight) and `KubernetesKeys` (2% weight) to `KubernetesTraffic` read choices, calling `kc.Count(ctx, keyPrefix, kubernetes.CountOptions{})` and `kc.Keys(ctx, keyPrefix, kubernetes.KeysOptions{})`.

## 3. Findings & Open Points

### Finding 1 (Bug in Robustness Integration): `RecordingClient.Get` silently strips `WithCountOnly()`, so `KubernetesCount` never sends a count-only request
- **Location**: `tests/robustness/traffic/kubernetes.go:120-124`, `tests/robustness/client/client.go:94-120`
- **Description**:
  In `kubernetesTraffic.Read` (`tests/robustness/traffic/kubernetes.go:147`), `kc` is constructed as:
  ```go
  kc := kubernetes.Client{Client: &clientv3.Client{KV: c}}
  ```
  where `c` is `*client.RecordingClient`. When `KubernetesCount` is chosen, `t.Count` calls `kc.Count(ctx, keyPrefix, kubernetes.CountOptions{})`, which calls:
  ```go
  k.KV.Get(ctx, prefix, clientv3.WithPrefix(), clientv3.WithCountOnly())
  ```
  However, `(*RecordingClient).Get` in `tests/robustness/client/client.go:94-97` is implemented as:
  ```go
  func (c *RecordingClient) Get(ctx context.Context, key string, opts ...clientv3.OpOption) (*clientv3.GetResponse, error) {
  	op := clientv3.OpGet(key, opts...)
  	return c.Range(ctx, key, string(op.RangeBytes()), op.Rev(), op.Limit(), op.IsKeysOnly())
  }
  ```
  Because `RecordingClient.Get` does not inspect or forward `op.IsCountOnly()`, `c.Range` constructs `ops` without `clientv3.WithCountOnly()`, sends a full `Range` (fetching all keys and values!) to the etcd server, and records a full `Range` operation (`KeysOnly: false`, no `CountOnly`) in the Porcupine history (`c.kvOperations.AppendRange(...)`).
  Consequently, the 3% `KubernetesCount` traffic added by PR `#21209` never exercises `CountOnly` on the server when run under the robustness test harness.
- **Reproduction Test**:
  [`notes/pr-verify/etcd-21209/keys_pr21209_probe_test.go`](etcd-21209/keys_pr21209_probe_test.go) (`TestPR21209_RecordingClientStripsWithCountOnly`), log in [`notes/pr-verify/etcd-21209/probe-test.log`](etcd-21209/probe-test.log).

### Finding 2 (Minor / API Consistency): `Client.Keys` uses `WithRange(GetPrefixRangeEnd(prefix))` instead of `WithPrefix()`, failing with `ErrEmptyKey` when `prefix == ""`
- **Location**: `client/v3/kubernetes/client.go:83-85`
- **Description**:
  As highlighted by our formal specifications (`inRange pfx (prefixRangeEnd pfx)` in `Client.Keys.spec` vs `inRange (prefixStart pfx) (prefixRangeEnd pfx)` in `Client.Count.spec`):
  - `Client.Count` uses `clientv3.WithPrefix()`, which checks `if len(op.key) == 0 { op.key, op.end = []byte{0}, []byte{0} }`. Calling `Count(ctx, "", CountOptions{})` therefore queries `["\x00", "\x00")` (all keys) and succeeds.
  - `Client.Keys` instead computes `rangeEnd := clientv3.GetPrefixRangeEnd(prefix)` and passes `clientv3.WithRange(rangeEnd)` (copied from `Client.List`, which only needed `WithRange` because `List` replaces `rangeStart` with `opts.Continue` when paginating). Because `Keys` does not have a `Continue` option, using `WithRange(GetPrefixRangeEnd(prefix))` leaves `Key = ""` empty when `prefix == ""`, causing the etcd server (`checkRangeRequest` in `v3rpc/key.go`) to reject `Keys(ctx, "", KeysOptions{})` with `rpctypes.ErrEmptyKey`.
  - Using `clientv3.WithPrefix()` in `Client.Keys` (`k.KV.Get(ctx, prefix, clientv3.WithPrefix(), clientv3.WithKeysOnly(), clientv3.WithRev(opts.Revision))`) is both simpler and consistent with `Client.Count`.
- **Reproduction Test**:
  [`notes/pr-verify/etcd-21209/keys_pr21209_probe_test.go`](etcd-21209/keys_pr21209_probe_test.go) (`TestPR21209_EmptyPrefixKeysVsCount`), log in [`notes/pr-verify/etcd-21209/probe-test.log`](etcd-21209/probe-test.log).

### Finding 3 (Minor): Missing `RequestTimeout` in `kubernetesTraffic.Count` and `kubernetesTraffic.Keys`
- **Location**: `tests/robustness/traffic/kubernetes.go:189-199`
- **Description**:
  In `tests/robustness/traffic/kubernetes.go`, `List` (`line 197`) and `Write` (`line 219`) wrap each RPC in `context.WithTimeout(ctx, RequestTimeout)`, whereas `Count` and `Keys` pass the parent `ctx` directly without `RequestTimeout` (matching `Get`).

## 4. Draft Upstream Review Comment

1. In `tests/robustness/traffic/kubernetes.go`, `kubernetesTraffic.Read` constructs `kc := kubernetes.Client{Client: &clientv3.Client{KV: c}}` where `c` is `*client.RecordingClient`. When `KubernetesCount` runs, `kc.Count` calls `k.KV.Get(ctx, prefix, clientv3.WithPrefix(), clientv3.WithCountOnly())`, which invokes `(*RecordingClient).Get` (`tests/robustness/client/client.go:94-97`):
   ```go
   func (c *RecordingClient) Get(ctx context.Context, key string, opts ...clientv3.OpOption) (*clientv3.GetResponse, error) {
   	op := clientv3.OpGet(key, opts...)
   	return c.Range(ctx, key, string(op.RangeBytes()), op.Rev(), op.Limit(), op.IsKeysOnly())
   }
   ```
   Because `RecordingClient.Get` does not forward `op.IsCountOnly()`, `c.Range` drops `clientv3.WithCountOnly()` and executes a full `Range` (fetching all keys and values) instead of a count-only range. To actually exercise `CountOnly` in robustness tests, `RecordingClient` and the Porcupine history model (`AppendRange` / `RangeOptions`) need `CountOnly` support.
2. In `client/v3/kubernetes/client.go`, `Keys` does not support pagination (`Continue`), so it can use `clientv3.WithPrefix()` directly (just like `Count` right above it):
   ```go
   rangeResp, err := k.KV.Get(ctx, prefix, clientv3.WithPrefix(), clientv3.WithKeysOnly(), clientv3.WithRev(opts.Revision))
   ```
   Using `WithPrefix()` also avoids sending an empty `Key` (`ErrEmptyKey`) when `prefix == ""`.

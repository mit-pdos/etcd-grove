## 1. Summary of the PR

### The Bug Before the PR

When an `EtcdServer` follower applied an incoming Raft snapshot in `(*EtcdServer).applySnapshot` (`server/etcdserver/server.go`), after swapping `s.be = newbe` and releasing `s.bemu.Unlock()`, it called `s.restoreAlarms()`:

```go
func (s *EtcdServer) restoreAlarms() error {
	as, err := v3alarm.NewAlarmStore(s.lg, schema.NewAlarmBackend(s.lg, s.be))
	if err != nil {
		return err
	}
	s.alarmStore = as
	return nil
}
```

Meanwhile, concurrent gRPC and HTTP health-check goroutines (`maintenanceServer.Status`, `/health`, `/livez`, `/readyz`) read `s.alarmStore` via `(*EtcdServer).Alarms()` without any lock on `EtcdServer`:

```go
func (s *EtcdServer) Alarms() []*pb.AlarmMember {
	return s.alarmStore.Get(pb.AlarmType_NONE)
}
```

This caused three related data races under Go's memory model (all caught by `go test -race` in [`notes/pr-verify/etcd-22654/repro_test_before.log`](./etcd-22654/repro_test_before.log)):
1. **Pointer field race on `s.alarmStore`**: `(*EtcdServer).restoreAlarms()` wrote `s.alarmStore = as` on the apply goroutine while `(*EtcdServer).Alarms()` read `s.alarmStore` on a concurrent goroutine.
2. **Mutex initialization race on `a.mu`**: If `(*EtcdServer).Alarms()` observed the newly stored pointer `as` without a happens-before edge from `v3alarm.NewAlarmStore()`, its call to `a.Get(...) -> a.mu.Lock()` (`CompareAndSwapInt32` on `a.mu.state`) raced with `NewAlarmStore`'s struct allocation/zero-initialization of `ret := &AlarmStore{...}`.
3. **Map field initialization race on `a.types`**: Even after acquiring `a.mu.Lock()`, because `NewAlarmStore` initialized `ret.types = make(...)` and called `ret.restore()` *without* acquiring `ret.mu`, there was no release-acquire synchronization on `a.mu` ordering `NewAlarmStore`'s writes to `a.types` before `Get()`'s reads of `a.types`.

### The Fix in the PR

The PR makes three changes:
1. **`server/etcdserver/api/v3alarm/alarms.go` — Add `(*AlarmStore).Recover`**:
   ```go
   func (a *AlarmStore) Recover(be schema.AlarmBackend) error {
   	a.mu.Lock()
   	defer a.mu.Unlock()

   	a.be = be
   	a.types = make(map[pb.AlarmType]alarmSet)
   	return a.restore()
   }
   ```
   Under `a.mu` (the same mutex acquired by `Get`, `Activate`, and `Deactivate`), `Recover` updates `a.be` to the new `schema.AlarmBackend`, resets `a.types` to a fresh map, and runs `a.restore()`.
2. **`server/etcdserver/server.go` — Recover `s.alarmStore` in place in `applySnapshot`**:
   Replaces `if err := s.restoreAlarms(); err != nil` in `applySnapshot` with:
   ```go
   if err := s.alarmStore.Recover(schema.NewAlarmBackend(lg, newbe)); err != nil {
   	lg.Panic("failed to restore alarm store", zap.Error(err))
   }
   ```
   Now `s.restoreAlarms()` is called only once during `NewServer` before any concurrent reader starts, so the pointer field `s.alarmStore` is immutable after server construction.
3. **`server/etcdserver/server_test.go` & `tests/integration/v3_alarm_test.go`**:
   Initializes `srv.alarmStore` in the two unit tests (`TestSnapshotOrdering` and `TestConcurrentApplyAndSnapshotV3`) that construct a partial `EtcdServer` without `NewServer`, and adds the regression test `TestV3AlarmsDuringSnapshotInstall`.

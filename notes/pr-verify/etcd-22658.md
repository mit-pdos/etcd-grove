## 1. Executive Summary

`etcd-io/etcd#22658` fixes a nil-pointer dereference in `(*Client).SetEndpoints(eps ...string)` (`client/v3/client.go:177–185`) when called on a `*Client` constructed via `NewCtxClient(ctx, opts...)` (`client/v3/client.go:97–107`, used in-process by `v3client.New(s)` in `server/etcdserver/api/v3client/v3client.go:31`):

```go
func (c *Client) SetEndpoints(eps ...string) {
	c.epMu.Lock()
	defer c.epMu.Unlock()
	c.endpoints = eps

	if c.resolver != nil {
		c.resolver.SetEndpoints(eps)
	}
}
```

Prior to PR `#22658`, `NewCtxClient` left `c.resolver == nil`, while `SetEndpoints` unconditionally called `c.resolver.SetEndpoints(eps)` (`r.endpoints = endpoints` at `client/v3/internal/resolver/resolver.go:53`), causing an immediate `SIGSEGV` panic whenever `c.SetEndpoints(...)` or `c.Sync(ctx)` (which calls `c.SetEndpoints(eps...)` at `client/v3/client.go:204`) was invoked on a `NewCtxClient` client.

## 3. Related API Subtleties & Caveats

While PR `#22658` is completely sound and fixes `SetEndpoints` (and `Sync`) on `NewCtxClient`, formal modeling of `NewCtxClient`, `WithZapLogger`, `WithLogger`, and `SetEndpoints` highlighted two related API subtleties in `client/v3/client.go`:

1. **`(*Client).WithLogger(nil)` vs `NewCtxClient(ctx, WithZapLogger(nil))` (`client/v3/client.go:103–105, 135–138`)**:
   - `NewCtxClient` checks `if c.lg.Load() == nil { c.lg.Store(zap.NewNop()) }` after applying all `Option` functions, so `NewCtxClient(ctx, WithZapLogger(nil))` safely falls back to `zap.NewNop()` and satisfies `isClientLogger c`.
   - By contrast, the deprecated method `(*Client).WithLogger(lg *zap.Logger)` (`client.go:135–138`) unconditionally executes `c.lg.Store(lg)` without checking `if lg == nil`. Passing `nil` to `c.WithLogger(nil)` violates `isClientLogger c` and causes subsequent calls to `c.GetLogger().Debug(...)` (such as `c.Sync(ctx)` at `client.go:205`) to panic with a nil-pointer dereference.
2. **Calling `c.SetEndpoints()` with Zero Endpoints or Calling `c.dialWithBalancer()` on `NewCtxClient` (`client/v3/client.go:177–185, 313–330`)**:
   - `c.SetEndpoints()` permits an empty `eps` slice (`len(eps) == 0`). If `c.SetEndpoints()` is called with zero arguments on a client and `c.Dial(ep)` (`client.go:279–285`) or `c.dialWithBalancer()` (`client.go:313–317`) is subsequently called, `c.dial` (`client.go:329`: `authority(c.endpoints[0])`) and `c.dialWithBalancer` (`client.go:314`: `c.Endpoints()[0]`) panic with an out-of-bounds slice index `c.endpoints[0]`.
   - Likewise, `c.dialWithBalancer()` (`client.go:315`: `grpc.WithResolvers(c.resolver)`) wraps `c.resolver` (`(*EtcdManualResolver)(nil)` on a `NewCtxClient`) in a non-nil `resolver.Builder` interface, which panics inside `grpc.NewClient` when invoking `Scheme()` on the typed-nil receiver.

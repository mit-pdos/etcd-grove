## Verdict

The PR is right: it does what it says, and nothing else. As far as it was verified, it is safe.

With the fix, `closeRequireLeader` keeps every channel that survives paired with its own
subscriber's context. Without it, the proof needed #22291's premise `□ ∀ ch c c', R ch c -∗ R ch c'`
(etcd#22081). With it, the spec of `closeRequireLeader` is proved without that premise, both of
the PR alone and of the PR with #22291. There is no `sorry`, and no new axiom.

**#22087 does not fix the orphan bug etcd#22094.** It needs #22291 or #22253 as well.
- The PR alone still compacts an entry whose subscriptions all required a leader to zero channels,
  and leaves the entry in `l.keepAlives`. #22291's test `TestLessorCloseRequireLeaderRemovesOrphanedKeepAlive`
  fails at the PR head.
- So, of the PR alone, the spec holds only with the invariant's "every entry has a subscription"
  dropped.
- With #22291 on top, the full spec of #22291 holds without the premise: the invariant with
  non-emptiness, and each channel paired with its own context.

The two PRs are independent and compose cleanly: #22291's delete branch does not look at the
pairing, and #22087's compaction does not depend on the delete. Landing both fixes both bugs. It
also removes the regression the #22291 report noted, where with #22291 alone a plain subscriber's
lease stops being renewed at a second leader loss.

What is not covered is as for #22291:
- The spec is a safety spec. Its postcondition is `True`, so it does not say that the require-leader
  channels *are* closed, nor that a subscriber leaves only with its channel closed: Iris can drop a
  resource. It rules out "closed through another subscriber's context", not "dropped".
- The other functions over `keepAlives` are checked by reading, not proved.

## The specs

`Spec/go_etcd_io/etcd/client/v3/lessor__closeRequireLeader.lean`, over `lessor.muInv R l`
(`Proof/go_etcd_io/etcd/client/v3/InvLease.lean`).

- **Old** (`pr-verify/etcd-22291`):
  - Pre: `l.mu` with invariant `muInv`, where each entry is a non-empty list of subscriptions
    `(ch, ctx)` with one `R ch ctx` each. Also `closeOk` (`R ch c` lets `close(ch)` succeed when `c`
    requires a leader), and the premise `□ ∀ ch c c', R ch c -∗ R ch c'`.
  - Post: `True`.
  - Because of the premise, the context in `R` can be swapped at will. So `closeOk`'s condition was
    about whatever context ended up at a channel's index, not the subscriber's own.
- **New, PR + #22291** (commit dc2bb0753; copies in `notes/pr-verify/etcd-22087/with-22291/`): the
  same spec without the premise. The kept list is now exactly `subs.filter (not require-leader)`,
  each pair carrying its own `R ch ctx`.
- **New, PR alone** (this branch's tip): the same, without the premise, over the invariant without
  `subs ≠ []` (`lessor.kaOwn`).

**Why the new spec rejects the pinned code.** With `ka.ctxs[newIdx]`, the kept list is the kept
channels zipped with a prefix of the contexts. Re-establishing the invariant would need `R chB ctxA`
from `R chB ctxB`. For a caller's `R ch c := ⌜c = owner ch⌝`, and the subscriptions `[A
(require-leader), B (plain)]`, that is false. The premise used to supply exactly this. It is gone,
and so are the re-pairing lemmas (`lessor.repair` and the zip lemmas). The tests show the same:
`TestLessorCloseRequireLeaderKeepsPairing` and the PR's own test fail at the base and pass at the
head.

**Compatibility.** Dropping a premise weakens the precondition, so this part is compatible: the
new spec implies the old. Against #22291's spec, the PR-alone invariant is weaker (it allows empty
entries), so the two specs are not comparable there. That gap is etcd#22094, which this PR does not
claim to fix. The only caller, `recvKeepAliveLoop`, is untranslated, so no proof is affected.

**Proof changes.** In the compaction loop's invariant, the new context slice holds
`(filter …).map Prod.snd` instead of `(subs.map Prod.snd).take k`. The loop reads `ctxs[j]` at the
channel's index `j`, through the new lemma `lessor.compact_snd`. For the PR alone, #22291's delete
branch is gone, and so is the variable `id`. The compaction also runs when every subscription
required a leader: it makes zero-length slices and runs a loop that skips every entry, and its
proof needs no change for that case.

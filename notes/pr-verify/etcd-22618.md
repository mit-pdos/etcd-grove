## 1. Summary of the Change

In `cache/cache.go`, `Cache.watch(rev int64)` previously initialized `c.demux` lazily inside the `readyOnce.Do(...)` callback on the first watch response in `Cache.watchEvents`:

```go
// Before etcd#22618:
readyOnce.Do(func() {
    c.demux.Init(rev)
    c.ready.Set()
})
```

Because `c.demux.Register(storeW, rev)` ran at the top of the `for` loop in `Cache.watch(rev)` *before* `c.watchEvents` received its first response:
1. On any watch retry after a compaction or error where the new snapshot revision `R` (`rev = R + 1`) did not immediately follow the demux's previously observed `d.maxRev` (or when `d.maxRev == 0`), `c.demux.Init(rev)` called `d.purge()`.
2. `d.purge()` stopped every registered watcher in `d.activeWatchers` and `d.laggingWatchers` — including the `storeW` just registered for the current `watch(rev)` attempt.
3. Stopping `storeW` closed `storeW.respCh`, causing the `c.applyStorage(storeW)` goroutine to return `nil` and `close(applyErr)`.
4. `c.watchEvents` then selected `case err := <-applyErr:` (`err == nil`), called `c.ready.Reset()` (flipping `c.Ready()` back to `false`), and returned `nil` to `Cache.watch(rev)`.
5. `Cache.watch(rev)` looped to the next iteration of its inner `for` loop with the **same `readyOnce`** (already consumed in iteration 1), so `c.ready.Set()` never ran again and `c.Ready()` stayed `false` permanently (`WaitReady` blocked forever).

`etcd#22618` moves `c.demux.Init(rev)` to the start of `Cache.watch(rev)` before `readyOnce := sync.Once{}` and before the `for` loop registers `storeW`, leaving `readyOnce.Do(c.ready.Set)` in `Cache.watchEvents`. (This same code fix was independently applied on `goose-lean` in commit `64313a1f8a35601d9261d7eac9ba87b659c1723a` during the initial verification of `cache`.)

## 2. Formal Specification & Proof Strengthening

While `goose-lean` already contained the code change from `64313a1f8`, the existing proof on `lean` initialized `readyOnce` with trivial propositions (`sync.init_Once readyOnce_ptr iprop(True) iprop(True)`) and discarded the `readySeen` postconditions of `ready.Set` and `ready.Reset` in `Cache.watchEvents`.

On `pr-verify/etcd-22618`, we strengthened the specifications and proofs across the watch loop to formally verify the `ready` epoch transitions:

1. **[`Proof/go_etcd_io/etcd/cache/v3/InvReady.lean`](file:///shared/etcd-grove-pr/etcd-22618/Proof/go_etcd_io/etcd/cache/v3/InvReady.lean#L93-L100)**:
   - Added `instance readySeen_persistent` showing `readySeen γ e0 b` (`∃ e, readyEpochLb γ e ∗ ⌜e0 ≤ e ∧ readyParity e = b⌝`) is persistent, so it can serve as the persistent postcondition `Q` of `sync.isOnce ro P Q`.

2. **[`Spec/go_etcd_io/etcd/cache/v3/Cache__watchEvents.lean`](file:///shared/etcd-grove-pr/etcd-22618/Spec/go_etcd_io/etcd/cache/v3/Cache__watchEvents.lean#L45-L66) & [`Proof/go_etcd_io/etcd/cache/v3/Cache__watchEvents.lean`](file:///shared/etcd-grove-pr/etcd-22618/Proof/go_etcd_io/etcd/cache/v3/Cache__watchEvents.lean#L426-L618)**:
   - Parameterized `Cache.watchEvents.spec` by any starting `ready` epoch lower bound `e0 : Nat` (`readyEpochLb γr e0`) and `sync.isOnce ro (readyEpochLb γr e0) (readySeen γr e0 true)` (together with `CursorOk cf.pfx c0 (rev - W64 1)` established by `c.demux.Init(rev)`).
   - Strengthened the loop invariant `HI` of `Cache.watchEvents` with `"#Hrseen" ∷ (⌜n = 0⌝ ∨ readySeen γr e0 true)`, proving that after the first response (`n > 0`), `readyOnce.Do(c.ready.Set)` guarantees `c.ready` was set to `true` in an epoch `e ≥ e0`.
   - Strengthened the postcondition of `Cache.watchEvents.spec` so that:
     - When returning via `watchCh` with `resp.Err() != nil` or a `demux.Broadcast` error, both `readySeen γr e0 true` and `readySeen γr e0 false` hold (the watch marked `c.ready` ready in epoch `≥ e0` and then reset it on failure).
     - When returning via `<-applyErr`, `readySeen γr e0 false` holds.

3. **[`Spec/go_etcd_io/etcd/cache/v3/Cache__watch.lean`](file:///shared/etcd-grove-pr/etcd-22618/Spec/go_etcd_io/etcd/cache/v3/Cache__watch.lean#L43-L56) & [`Proof/go_etcd_io/etcd/cache/v3/Cache__watch.lean`](file:///shared/etcd-grove-pr/etcd-22618/Proof/go_etcd_io/etcd/cache/v3/Cache__watch.lean#L53-L169)**:

   - Verified that `c.demux.Init(rev)` runs *before* `c.demux.Register(storeW, rev)` (establishing `CursorOk cf.pfx (initCore c0 rev).1 (rev - W64 1)` via `initCore_ok` without stopping `storeW`) and that `readyOnce := sync.Once{}` is initialized for epoch `e0` via `sync.init_Once readyOnce_ptr (readyEpochLb γr e0) (readySeen γr e0 true)`.

4. **[`Spec/go_etcd_io/etcd/cache/v3/Cache__getWatch.lean`](file:///shared/etcd-grove-pr/etcd-22618/Spec/go_etcd_io/etcd/cache/v3/Cache__getWatch.lean#L31-L40), [`Proof/go_etcd_io/etcd/cache/v3/Cache__getWatch.lean`](file:///shared/etcd-grove-pr/etcd-22618/Proof/go_etcd_io/etcd/cache/v3/Cache__getWatch.lean#L29-L89), & [`Proof/go_etcd_io/etcd/cache/v3/Cache__getWatchLoop.lean`](file:///shared/etcd-grove-pr/etcd-22618/Proof/go_etcd_io/etcd/cache/v3/Cache__getWatchLoop.lean#L35-L80)**:

## 3. Residual Finding: Store Watcher Lag (`applyStorage` / `Cache.watch` Inner Loop)

Inspecting the second postcondition disjunct of `Cache.watchEvents.spec`:
```lean
(handoffConsumer γa true ∗ readySeen γr e0 false ∗
  ((P err ∗ Ws) ∨ (⌜err = GoInterface.nil⌝ ∗ Wc)))
```
highlights a subtle residual bug when `applyErr` is closed without an error (`err == nil`, `Wc`):
1. If a burst of events overflows `storeW.respCh` (`PerWatcherBufferSize`) and `d.history` (`HistoryWindowSize`) before `applyStorage(storeW)` drains them, `d.minRev` advances past `storeW`'s `nextRev` (`nextRev < d.minRev`).
2. On the next resync tick, `d.resyncLaggingWatchers()` (`cache/demux.go:330-333`) calls `storeW.Compact(nextRev)`, which sets `storeW.cancelResp` and closes `storeW.respCh`.
3. `Cache.applyStorage(storeW)` (`cache/cache.go:380-383`) reads `resp, ok := <-storeW.respCh` directly without checking `storeW.cancelResp`, so when `storeW.respCh` is closed it returns `nil`, closing `applyErr` without sending an error.
4. `Cache.watchEvents` receives `nil` from `applyErr`, calls `c.ready.Reset()` (`c.Ready()` becomes `false`), and returns `nil` to `Cache.watch(rev)`.
5. Because `err == nil`, `Cache.watch(rev)` does **not** return to `getWatch()` to resync via `c.get()`. Instead, it loops to the next iteration of its inner `for` loop with the **same stale `rev`** (`< d.minRev`) and the **same already-spent `readyOnce`**:
   - The newly registered `storeW` starts at `rev < d.minRev`, so it cannot be resynced from `d.history` and will be compacted again on the next resync tick.
   - `CreatedNotify` and `ProgressNotify` responses on the reopened upstream watch do not make the cache ready again (`c.Ready()` stays `false`) because `readyOnce` was already spent in iteration 1 before `c.ready.Reset()`.

We confirmed this behavior with [`store_watcher_lag_probe_test.go`](file:///shared/etcd-grove-pr/etcd-22618/notes/pr-verify/etcd-22618/store_watcher_lag_probe_test.go) (log in [`store_watcher_lag_probe.log`](file:///shared/etcd-grove-pr/etcd-22618/notes/pr-verify/etcd-22618/store_watcher_lag_probe.log)).

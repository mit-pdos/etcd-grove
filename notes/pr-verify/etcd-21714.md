# etcd-io/etcd#21714: verification report

- **PR**: etcd-io/etcd#21714, "client/v3: improve error messages to include endpoint information",
  https://github.com/etcd-io/etcd/pull/21714, head `73e84399187037908518032ff011057bf04d0c97` (one
  commit, merge base with `main` `5ef5d3c26`). Open; fixes issue #21709 (a duplicate PR, #21887,
  was closed in its favor).
- **What it does**, all in `client/v3/client.go`:
  - `newClient`'s dial failure returns
    `fmt.Errorf("etcdclient: dialing [%s] failed: %w", strings.Join(cfg.Endpoints, ";"), err)`
    instead of `err`;
  - its token failure (`getToken`, the `Authenticate` call for a user name and password) returns
    `fmt.Errorf("etcdclient: communicating with [%s] failed: %w", ...)` instead of `err`;
  - `ErrMutuallyExclusiveCfg`'s message gets the `etcdclient: ` prefix (same variable).
  The description: the endpoint list "improv[es] debuggability" of dial and token errors.
- **Verified at**: `mit-pdos/etcd-grove` branch `pr-etcd-21714-goose-lean` (worktree
  `~/etcd-pr/etcd-21714`), commit `dec48fa15` on the fork's `goose-lean` `09669450f`: the PR's
  diff, applied cleanly (no conflicts, no rewrite: the verified code is the PR's). `go build ./...`,
  `go vet` and `go test` of `client/v3` pass there.
- **This branch**: `pr-verify/etcd-21714` (worktree `/shared/etcd-grove-pr/etcd-21714`), off
  `lean` `51547df02`. The etcd pin is unchanged, so `etc/goose.py --check` fails here by design.

## Verdict

**The change does what it says, and it is safe for callers that test errors the way etcd's own code
does: proved, the two errors are now wrappers (`%w`) of the callee's error, so `errors.Is`/`errors.As`
still find the cause (`rpctypes.ErrAuthFailed`, `context.DeadlineExceeded`), and the message gains the
endpoint list. It is a user-visible API change all the same: `clientv3.New` no longer returns the
callee's error itself, so `err == rpctypes.ErrAuthFailed`, `err == context.DeadlineExceeded` and
`err.(rpctypes.EtcdError)` stop matching (shown by tests), and the PR has no CHANGELOG entry. Its
premise is also half outdated: since #21832 (client creation non-blocking, merged 2026-06-11) the
dial no longer connects, so an unreachable endpoint never produces the "dialing [...] failed" error;
the endpoint list shows up only when the dial options are invalid, or, for a client with a user name
and password, on the token request.**

- **Proved** (no `sorry`, `Proof/go_etcd_io/etcd/client/v3/newClient.lean`, `New.lean`): `newClient(cfg)`
  either returns no error and a client built (fields fixed from the dial on, a non-nil logger, a
  token only with a credential bundle, connection and services set), which is what the retry
  interceptor's proofs assumed of a client `New` built (`retryClientOk`, now established), or no
  client and an error whose `Error()` returns a string, of one of seven origins (`newClientErr`);
  for a failed dial, an error wrapping the dial's own error, and for a failed token request, an error
  wrapping the client error `getToken` returned. `errors.Is` on the wrapper walks to the cause
  (`errorIsTree_wrap`, `Spec/fmt/ErrorfWrap.lean`). `New` returns `ErrNoAvailableEndpoints` itself for
  no endpoints, else what `newClient` does (`Spec/go_etcd_io/etcd/client/v3/New.lean`,
  `clientv3.New.spec`).
- **The old code does not meet the new spec** in exactly those two places (it returned `inner`, a leaf
  error, not a wrapper of it); everywhere else the spec holds of both.
- **Not proved, shown by Go tests** (the model of `fmt` does not format): the message has the
  endpoints joined with `;` (`notes/pr-verify/etcd-21714/probe-head.log`).
- **Rests on** new trust-boundary axioms for `fmt.Errorf`'s `%w` (Go's `*fmt.wrapError`) and for the
  names-only callees of `newClient` (the dial, the service constructors, `Close`, `checkVersion`,
  `autoSync`, zap's logger construction, ...): see "Trust base".

## The spec, old and new

`Spec/go_etcd_io/etcd/client/v3/newClient.lean`, `newClient.spec`, with the error origins in
`Proof/go_etcd_io/etcd/client/v3/InvNewClient.lean`, `newClientErr`:

- **New** (the PR): a dial failure gives an error `e` with `fmt.wrapsErr e inner` for the dial's error
  `inner` (whose `Error()` returns a string), and a token failure one with `fmt.wrapsErr e inner` for
  `getToken`'s client error `inner` (`clientErrOk`: a leaf error grpc's `status` accepts, an
  `rpctypes.EtcdError` when typed). `fmt.wrapsErr e inner`: `e.Unwrap()` returns `inner`, `e` has no
  `Is`/`As` method.
- **Old**: the same two disjuncts with `e = inner`. The difference is compatible for a caller that
  tests with `errors.Is`/`errors.As` (`errorIsTree_wrap`: the wrapper's error tree is `inner`'s plus
  itself) and incompatible for one that compares with `==`, type-asserts, or matches the message
  exactly.

The other disjuncts (the same for both): `ErrMutuallyExclusiveCfg` itself (token with a user name or
password); an error of the logger's construction (no `Config.Logger`; the ghost mark `loggerErr`); the
size check (receive limit set and below the send limit); no endpoints (`errors.New`); an error of
`checkVersion` (`RejectOldCluster`; the mark `versionErr`).

The spec's premises: the caller's `Config` is read-only (`newClient` keeps `cfg.Endpoints` itself, not
a copy); its `Context` is nil or a context of Perennial's model; the package variables hold fixed
values (`newClientVars`, as the package's initialization is axiomatized).

## Findings

1. **A user-visible API change without a release note** (the PR): `New`'s dial and token errors are
   wrappers, not the callee's errors. `errors.Is`/`errors.As` callers (all of etcd's) are unaffected
   (proved: `errorIsTree_wrap`; tested); `==`, type assertions (`err.(rpctypes.EtcdError)`),
   `rpctypes.ErrorDesc`/`status.FromError(err).Message()` (now the whole wrapper text, so
   `rpctypes.Error(err)` no longer maps it back) change. Tests: `notes/pr-verify/etcd-21714/
   client_error_wrap_test.go`, `probe-base.log` against `probe-head.log`
   (`err == rpctypes.ErrAuthFailed`: true at base, false at head; `err == context.DeadlineExceeded`
   after an unreachable endpoint with credentials: true, false).
2. **`client/v3/doc.go` contradicts the code, more so with the PR** (`issues/etcd-client-doc-new-deadline.md`):
   its example tests `err == context.DeadlineExceeded` after `New` on a blackhole endpoint. Since
   #21832 `New` returns no error there (no credentials); with credentials the PR makes the `==`
   false. The PR does not update it.
3. **The dial-error message rarely appears** (the PR's premise): `TestPR21714UnreachableNoAuth`
   shows `New` succeeds on an unreachable endpoint; the first request then fails with
   `context deadline exceeded`, with no endpoint in it. The "dialing [...] failed" error needs
   invalid dial options (`TestPR21714DialError`: per-RPC credentials requiring transport security
   over an insecure connection). The useful case is the token request with credentials.
4. **Existing bug, recorded**: `issues/etcd-client-new-context-leak.md`: `newClient`'s logger-error
   and size-check returns do not cancel the client's context, which stays registered with its
   cancellable parent (or leaks a goroutine for a custom parent). `client_new_cancel_leak_test.go`
   fails at base and head (100 of 100 left). Not touched by the PR; same function.
5. **Existing bug, recorded** (the reviewer's): `issues/etcd-client-dial-endpoints-race.md`:
   `Client.Dial` reads `c.endpoints[0]` without `epMu`; `-race` reports it against `SetEndpoints`
   (`review_dial_race_test.go`).

No bug in the PR's code itself: the format strings are well-formed, `strings.Join` of the
configuration's endpoints is safe (read-only by the spec's premise), `%w` operands are non-nil.

## Reviewer

A fresh reviewer read the specs, axioms and invariants; its tests are in `notes/pr-verify/etcd-21714/`.
Resolved:
- *The error origins were vacuous for the default configuration* (no `Logger`: "logger error" admitted
  any error; same for `RejectOldCluster`). Fixed with the ghost marks `loggerErr`, `versionErr`.
- *Several postulates were false for clients with nil fields* (`review_postulates_test.go`: 8 panics).
  Fixed: `clientFixed` now carries non-nil `epMu` and `resolver`, a context of the model with its
  cancel function, non-empty endpoints and read-only dial options; `SetEndpoints` and
  `resolver.Close` require non-nil arguments, `resolver.New` returns non-nil.
- *The dial reads `Config.DialOptions`, which no spec made read-only* (`review_dialopts_race_test.go`).
  Fixed: a premise of `New`/`newClient`.
- *`%w` calls `Format`*: the `ErrorfWrap` axiom now states the no-`Formatter` assumption.
Open (recorded, not fixed):
- The message's content (the endpoint list, the prefix) is not proved: Perennial's model of `fmt`
  does not format; shown by tests only.
- The opaque `*tls.Config`, `*zap.Config` and `Logger` the caller passes are not owned by the spec
  (their types are names only); a caller writing them during `New` would race, as with the dial
  options.
- `clientBuiltAt` gives the service fields (`KV`, `Lease`, ...) read-only, so a caller replacing
  them after `New` (`tests/framework/integration/cluster_proxy.go`) is outside this spec.

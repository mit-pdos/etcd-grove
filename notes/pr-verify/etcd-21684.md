## Verdict

**At the gRPC layer the PR does what it says. For clientv3 users it does not deliver the retry it
claims.**

**What it fixes.**
- `EtcdServer.LeaseRenew` returns `lease.ErrNotPrimary` when the member thinks it leads but
  `ensureLeadership()` fails. That error now reaches the keep-alive stream as `codes.Unavailable`.
  Before the PR it was `Unknown` (recorded as `issues/etcd-lease-not-primary-unknown-code.md`).
- `LeaseKeepAlive` is the only RPC this changes. The error reaches `togRPCError` unwrapped and from
  only that one place.

**What is proved.** The new spec of `togRPCError`: for the value of `lease.ErrNotPrimary`, it returns
the value of `rpctypes.ErrGRPCLeaseNotPrimary`, whose status code is 14 (`Unavailable`). It is proved
with no `sorry`. It rests on one new package-initialization assumption:
- the map entry, and the code of the new error;
- these are the PR's actual change, so the PR's change is assumed and checked by Go tests, not
  proved from the translation;
- v3rpc's initializer is not proved anywhere in this repository.

So the proof establishes that `togRPCError`'s checks and lookup deliver the entry: neither
`errors.Is` check catches `ErrNotPrimary`, and the lookup returns the entry's error.

**What clients see.**
- **clientv3 does not retry.** Its `KeepAliveOnce` turns the error into the new
  `rpctypes.ErrLeaseNotPrimary`, an `EtcdError`. For an `EtcdError`, `status.Code` is `Unknown`, so
  `isHaltErr` stops the retry loop at once, before the PR as after it. The long-lived `KeepAlive`
  loop retries every 500 ms whatever the code.
- **What does change.** The error value and its text: `rpc error: code = Unknown desc = not a primary
  lessor` becomes `etcdserver: not primary lessor`. The grpc-gateway answer changes too: HTTP 500 /
  `code: 2` becomes 503 / `code: 14`.
- **Older clients spin.** A client built against an older `rpctypes` has no entry for the new text,
  so it keeps the raw `Unavailable` status error. Its `KeepAliveOnce` then retries with no backoff:
  over 1100 renewals in 300 ms against a stub lessor (F2).
- **The integration test does not test the fix.** `TestV3LeaseKeepAliveReturnsUnavailableOnLeaderLoss`
  sees `ErrNoLeader`, not `ErrNotPrimary`, and passes without the fix (F3).

## Changed functions

From the two revisions' diffs, the PR changes no function body and no type. It adds three
package-level variables to `api/v3rpc/rpctypes`, one entry in `rpctypes`' `errStringToError`, and
one entry in `v3rpc`'s `toGRPCErrorMap`.

| Function / variable | Kind | Before (`lean`) | After (this branch) | Outcome |
|---|---|---|---|---|
| `toGRPCErrorMap` (`util.go:35`, entry `lease.ErrNotPrimary: rpctypes.ErrGRPCLeaseNotPrimary`) | behavior change (data) | names only; `grpcErrMap` left its keys open | initializer translated; the entry assumed (`notPrimaryEntry`) | package-init assumption, checked by `TestGRPCError` and the probes |
| `rpctypes.ErrGRPCLeaseNotPrimary`, `ErrLeaseNotPrimary`, `errStringToError`'s entry (`error.go:39,117,186`) | new (data) | — | `ErrGRPCLeaseNotPrimary`'s initializer translated; its code assumed (`notPrimaryEntry`); the others names only | assumption; the cache's `rpctypes` facts (`errStringToError`'s values are `statusErrOk`) still hold of the new entry |
| `togRPCError` (`util.go:99`), whose behavior the map changes | behavior change (through the map) | verified (`e ≠ nil`) | verified, new spec | **new spec, compatible**: `v3rpc.togRPCError.spec_implies_old`; the four KV handlers' proofs rebuilt unchanged in substance (one pattern each) |

**Old spec.** `togRPCError(err)` returns a non-nil error.

**New spec.** It returns a non-nil error, and if `err` is the value of `lease.ErrNotPrimary`, it
returns the value of `rpctypes.ErrGRPCLeaseNotPrimary`, whose gRPC status code is `Unavailable`
(`v3rpc.notPrimaryOut`).

**Where the statements are.**
- The spec: `Spec/go_etcd_io/etcd/server/v3/etcdserver/api/v3rpc/togRPCError.lean`.
- `notPrimaryOut`: `Proof/go_etcd_io/etcd/server/v3/etcdserver/api/v3rpc/InvKV.lean`.
- The proof and `spec_implies_old`: `Proof/.../v3rpc/togRPCError.lean`.

**The old code does not meet the new spec.** Its map has no `lease.ErrNotPrimary` key, so it returns
`status.Error(codes.Unknown, ...)`. The assumption `notPrimaryEntry` is false of it.
`notes/pr-verify/etcd-21684/probe-base.log` shows `Unknown` at `09669450f`.

**Translation.**
- `v3rpc.toml`: `toGRPCErrorMap` is now translated with its initializer, and four packages the
  literal names are added to `imports` (`etcdserver/errors`, `api/membership`, `version`, `lease`).
  - Without `etcdserver/errors` in `imports`, Goose resolved its errors (`errors.ErrNoLeader`, ...) to
    the standard library's `errors` package, and the translation did not compile. That is a Goose
    limitation, recorded in `notes/STATUS.md`.
  - The added imports also give several v3rpc structs (`maintenanceServer`, ...) their translated
    types in place of axiomatized ones.
- `rpctypes.toml`: `ErrGRPCLeaseNotPrimary`'s initializer is translated.
- Both are for a future proof of the package initializers. Nothing proves them yet.

## Caller graph

`togRPCError`'s spec change is compatible, so its callers are unaffected. The four KV handlers'
proofs (`kvServer.Range/Put/DeleteRange/Txn`) rebuilt with the new postcondition dropped. The PR's
behavior matters at the one caller that can pass `ErrNotPrimary`; the reviewer's sweep of the code
found no other.

- **`LeaseServer.leaseKeepAlive` (`lease.go:142-143`)** passes `LeaseRenew`'s error unwrapped.
  It is not translated on `lean`; checked by code reading and the probe `TestProbeLeaseKeepAliveNotPrimaryCode`
  over real gRPC: Unavailable after the PR, Unknown before. Branch `pr-verify/etcd-21960` translates
  and verifies `leaseKeepAlive` for another PR; its spec does not describe the error returned.
- **`EtcdServer.LeaseRenew` (`v3_server.go:503-505`)** is the only producer. It returns
  `lease.ErrNotPrimary` itself, which the map's `==` lookup needs.
  - `lessor.Renew`'s `ErrNotPrimary` (`v3_server.go:528-534`) falls through to forwarding.
  - The forwarding loops never return `ErrNotPrimary`. They end in `ErrTimeout`, `ErrNoLeader` or
    `ErrCanceled`, which are unchanged.
  - The checkpointer's `ErrNotPrimary` (`server.go:402`) stays internal.
  - `LeaseTimeToLive` uses `ErrLeaderChanged`.
- **Clients (exported API).** clientv3's `KeepAliveOnce` and `KeepAlive`, the stream retry
  interceptor (disabled for the keep-alive stream, `withMax(0)`), grpcproxy (through clientv3) and
  the grpc-gateway. These were checked by the probes and the reviewer; they are not specified. The
  user-visible change (new error text and value; new gateway code) is not in a CHANGELOG entry of the PR.

## Trust base

- **New assumption (package initialization): `notPrimaryEntry`** (`Proof/.../v3rpc/Base.lean`, part
  of `grpcErrMap`, so of `v3rpcInit`). It says:
  - `lease.ErrNotPrimary`'s value `ek` is a leaf pointer error without an `Is` method;
  - `M !! ek` is `rpctypes.ErrGRPCLeaseNotPrimary`'s value `ev`, and `statusCode ev = 14`;
  - `ek` is not `context.Canceled`'s value, and `context.DeadlineExceeded`'s value is of another
    dynamic type.

  Why it is believed:
  - the Go literal has the entry;
  - the reviewer checked every later key of `toGRPCErrorMap`: separate `errors.New`s and the two
    context errors, so none equals `ek` (a duplicate would overwrite at run time);
  - `status.Error(codes.Unavailable, …)`'s `GRPCStatus().Code()` is `Unavailable`;
  - the PR's `TestGRPCError` and the probes confirm it.

  It is an assumption like the rest of `v3rpcInit`, not an axiom; `#print axioms` does not show it.
- **Strengthened trust-boundary axiom: `errors.IsDeadlineExceeded.wp_proof`**
  (`Spec/errors/IsDeadlineExceeded.lean`). Its postcondition was `True`. It now says: `true` only if
  some error of the tree has the target's dynamic type, or has an `Is` method that answered `true`.
  - This is Go's `Is`: `==` on interfaces needs equal dynamic types.
  - The first version said "equal to the target". The reviewer showed it false of the model: the
    model's `==` on the empty struct `deadlineExceededError` is `true` for any two values, and
    without Go's typing a tree may hold such a value. It was restated by type before commit
    (`notes/STATUS.md`, "PR etcd#21684").
- **`errors.Is.spec`** (`Spec/errors/Is.lean`) now has Perennial's `errors.wp_Is` postcondition. It
  is proved by `wp_Is`, so no new trust. `read.isStopped`'s proof was adapted to it.
- **`sorry`s**: none added.
- `#print axioms` of `v3rpc.wp_togRPCError` and the collection `etc/tcb-collections/pr-etcd-21684.txt`: see below.

`etc/tcb-report.py --collection etc/tcb-collections/pr-etcd-21684.txt` (roots `togRPCError`, after a
full `lake build` of this branch, 5104 jobs) gives two axioms, and no `sorry`:
- `errors.IsDeadlineExceeded.wp_proof` (strengthened here);
- `status.Error.wp_proof` (unchanged).

These are the same two axioms `togRPCError` rested on, on `lean`. What changed is the statement of
the first, plus the new package-init assumption, which is not an axiom.

`etc/verified-code.py` is unchanged: no function is added, removed or rewritten, and `togRPCError`
is verified before and after.

## Findings

- **F1 (existing code, recorded).** Before the PR, a refused lease renewal answers `Unknown`:
  `issues/etcd-lease-not-primary-unknown-code.md`. The PR fixes it at the gRPC layer; the proof
  confirms the fix under `notPrimaryEntry`. Test: `lease_notprimary_probe_test.go`
  (`probe-base.log` before, `probe-pr-head.log` after).
- **F2 (PR: the claimed client benefit).** clientv3 does not retry `KeepAliveOnce` on the new error,
  and the PR's `errStringToError` entry is what keeps it from spinning.
  - **With the PR**, `ContextError` makes the error an `EtcdError`. `status.Code` of an `EtcdError`
    is `Unknown`, so `isHaltErr` is true and `KeepAliveOnce` returns after one renewal. The same is
    true of every `rpctypes`-known `Unavailable` error (`ErrNoLeader`, `ErrLeaderChanged`, ...):
    `KeepAliveOnce` retries only transport errors.
  - **Without the entry**, as for a client built against an older `rpctypes`, the error stays a raw
    `Unavailable`. `isHaltErr` is then false, and `KeepAliveOnce` retries with no backoff: 1150
    renewals in 300 ms through `clientv3.New`, 2251 over a bare connection
    (`probe-pr-without-errStringToError-entry.log`).
  - Against a real server each retry costs an `ensureLeadership()` (a ReadIndex, up to the request
    timeout), so the rate is lower. It is still a loop without backoff for the duration of the
    caller's context.
  - Mixed versions are normal (a client upgraded after the server), so this is a compatibility
    regression the PR does not mention.
  - **An alternative** with neither problem: return `errors.ErrLeaderChanged` (already `Unavailable`,
    already known to every client's `rpctypes`) from `LeaseRenew`. This is what the server's own
    comment at `v3_server.go:664-665` does for `LeaseTimeToLive`.
- **F3 (PR: its integration test).** `TestV3LeaseKeepAliveReturnsUnavailableOnLeaderLoss` does not
  exercise `ErrNotPrimary`. The surviving follower forwards to the leader and fails with
  `ErrNoLeader`, which was `Unavailable` already. The test passes at the base without the fix
  (`reviewer/pr-integration-test-at-base.log`, `...-with-log.log`). Its doc comment, which claims it
  covers `ErrNotPrimary`, is misleading. The PR's author notes in a comment that the real path needs
  a failpoint. The unit tests (`TestGRPCError`, `TestLeaseNotPrimaryReturnsUnavailable`) do test the
  mapping.
- **Reviewer's other points.**
  - The new `errStringToError` description `"etcdserver: not primary lessor"` is unique.
  - Not part of this PR, and not recorded as an issue: `LeaseTimeToLive`'s forwarding loop
    (`v3_server.go:675-695`) has no sleep between attempts, unlike `LeaseRenew`'s 50 ms. A leader
    answering 500 makes the follower loop until the request timeout.
- **Bug in this repository's spec** (fixed): the first form of the `IsDeadlineExceeded` axiom (above).

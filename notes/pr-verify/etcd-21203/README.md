| `watch_buffer_limit_probe_test.go` | Two tests with a fake gRPC watch server, in package `clientv3`. `TestWatchBufferLimitStallsOtherWatchers`: with `MaxWatcherBufferSize = 2`, a watch whose consumer does not read stalls every other watch on the same gRPC stream (watch B never gets its event). With 0 (no limit), B gets it. `TestWatchBufferLimitResumeLosesEvent`: with `MaxWatcherBufferSize = 1`, a retryable stream error while the substream waits with a received response drops that response, and the resume starts after it, so revision 4 is lost (the consumer sees 2, 3, 5). Both tests fail at the PR head and pass when the limit is 0. | the PR head `1a8852ebc` (upstream checkout), and `mit-pdos/etcd-grove` branch `pr-etcd-21203-goose-lean` (same result) | `cp watch_buffer_limit_probe_test.go <etcd>/client/v3/ && cd <etcd>/client/v3 && go test -count=1 -v -run 'TestWatchBufferLimit(Stalls\|Resume)' .` (upstream at the PR head: `GOTOOLCHAIN=go1.26.4`; the fork: `GOTOOLCHAIN=go1.27.1`) |

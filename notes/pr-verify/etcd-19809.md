## 1. Summary of Changes in PR #19809

PR #19809 refactors the `go.etcd.io/etcd/server/v3/etcdserver/txn` package and its callers in `server/etcdserver/apply` and `server/etcdserver`:

1. **`txn.TxnContext` struct (`server/etcdserver/txn/txn.go`)**:
   Introduces a new exported struct bundling the common dependencies passed to `txn` entry points:
   ```go
   type TxnContext struct {
       Logger                       *zap.Logger
       Lessor                       lease.Lessor
       KV                           mvcc.KV
       TxnModeWriteWithSharedBuffer bool
   }
   ```
2. **Rename of unexported helper `txn` -> `assembleTxnResponse` (`server/etcdserver/txn/txn.go`)**:
   Avoids identifier shadowing when the `TxnContext` parameter in `Put`, `DeleteRange`, `Range`, and `Txn` is named `txn`.
3. **Signature changes in `server/etcdserver/txn`**:
   - `Put(ctx context.Context, txn TxnContext, p *pb.PutRequest)` (previously took `(ctx, lg, lessor, kv, p)`)
   - `DeleteRange(ctx context.Context, txn TxnContext, dr *pb.DeleteRangeRequest)` (previously took `(ctx, lg, kv, dr)`)
   - `Range(ctx context.Context, txn TxnContext, r *pb.RangeRequest, serializable bool)` (previously took `(ctx, lg, kv, r, serializable)`)
   - `Txn(ctx context.Context, txn TxnContext, rt *pb.TxnRequest, skipRangeExecution bool)` (previously took `(ctx, lg, rt, txnModeWriteWithSharedBuffer, kv, lessor, skipRangeExecution)`)
4. **`(*applierV3backend).context()` helper (`server/etcdserver/apply/backend.go`)**:
   Adds a helper method on `applierV3backend` constructing `mvcctxn.TxnContext` from `a.options.{Logger, Lessor, KV, TxnModeWriteWithSharedBuffer}`, used by `applierV3backend.{Put, DeleteRange, Range, Txn}`.
5. **Direct `EtcdServer` callers (`server/etcdserver/v3_server.go`)**:
   Updates `(*EtcdServer).Range`, `(*EtcdServer).rangeStream` (added on `main` after PR #19809 was opened), and `(*EtcdServer).Txn` to construct `txn.TxnContext`.

## 3. Findings Exposed During Formal Verification

### Finding 1 (Low/Performance & Unit-Test Fragility): Unnecessary `ServerFeatureGate.Enabled` Lookup on Every `(*EtcdServer).Range` Call

In `server/etcdserver/v3_server.go:149-156`, PR #19809 changes `(*EtcdServer).Range` from:
```go
get := func() { resp, _, err = txn.Range(ctx, s.Logger(), s.KV(), r, true) }
```
to:
```go
get := func() {
	resp, _, err = txn.Range(ctx, txn.TxnContext{
		Logger:                       s.Logger(),
		Lessor:                       s.lessor,
		KV:                           s.KV(),
		TxnModeWriteWithSharedBuffer: s.Cfg.ServerFeatureGate.Enabled(features.TxnModeWriteWithSharedBuffer),
	}, r, true)
}
```
However, `txn.Range` only ever reads `txn.Logger` and `txn.KV`. It completely ignores `txn.Lessor` and `txn.TxnModeWriteWithSharedBuffer` (because `Range` opens a read-only `mvcc.ReadView`, not a write transaction with a shared buffer).

This has two consequences:
1. **Unnecessary feature-gate dispatch, `atomic.Value.Load()`, and map lookups on every `Range` RPC**: `s.Cfg.ServerFeatureGate.Enabled(features.TxnModeWriteWithSharedBuffer)` (`pkg/featuregate/feature_gate.go:334-343`) performs an interface dispatch plus one or two `atomic.Value.Load()` calls, interface type assertions, and `map` lookups (`f.enabled.Load().(map[Feature]bool)[key]` and, when not overridden by flag, `f.known.Load().(map[Feature]FeatureSpec)[key]`) on every `Range` request, only for `txn.Range` to discard the resulting boolean.
   - Our formal proof in [`Proof/go_etcd_io/etcd/server/v3/etcdserver/EtcdServer__Range.lean`](../../Proof/go_etcd_io/etcd/server/v3/etcdserver/EtcdServer__Range.lean) directly witnesses this: `EtcdServer.Range` must now step through the interface call `s.Cfg.ServerFeatureGate.Enabled(features.TxnModeWriteWithSharedBuffer)` (using the `isServerReq` invariant `Hfg`) to produce `en : bool`, and then pass `en` into `txn.Range.spec` where `shared : Bool` is universally quantified and unconstrained (`∀ (lessor : interface.t) (shared : Bool), ...`).
2. **Nil-dereference risk in unit tests with partial `EtcdServer` structs**: Before PR #19809, `(*EtcdServer).Range` did not access `s.Cfg.ServerFeatureGate`. Unit tests constructing a minimal `&EtcdServer{...}` with `Cfg: config.ServerConfig{}` (where `ServerFeatureGate` is `nil`) would previously succeed on `Range`, and now panic with a nil-interface dereference before calling `txn.Range`.

**Recommendation**: In `(*EtcdServer).Range`, omit `Lessor` and `TxnModeWriteWithSharedBuffer` (or only populate `Logger` and `KV`), matching `(*EtcdServer).rangeStream`:
```go
get := func() {
	resp, _, err = txn.Range(ctx, txn.TxnContext{
		Logger: s.Logger(),
		KV:     s.KV(),
	}, r, true)
}
```

### Finding 2 (Design / Code Hygiene): Over-Broad `TxnContext` Parameter Across Entry Points

As captured by our formal specifications in `Spec/go_etcd_io/etcd/server/v3/etcdserver/txn/`:
- `txn.Range.spec` and `txn.DeleteRange.spec` universally quantify `(lessor : interface.t) (shared : Bool)` with **no preconditions** on `lessor` or `shared`, proving that neither `Range` nor `DeleteRange` ever touches `txn.Lessor` or `txn.TxnModeWriteWithSharedBuffer`.
- `txn.Put.spec` universally quantifies `(shared : Bool)` with **no precondition** on `shared`, proving that `Put` only reads `txn.Logger`, `txn.Lessor`, and `txn.KV`.
- Only `txn.Txn.spec` uses all four fields of `TxnContext`.

Passing `TxnContext` by value (48 bytes on 64-bit architectures: 8-byte pointer + two 16-byte interfaces + 1-byte `bool` + 7 bytes padding) copies unused fields on `Range`, `DeleteRange`, and `Put`, and obscures which dependencies each operation actually requires.

### Finding 3 (Rebase Gap with `main`): File Split and New Call Sites Since PR #19809 Was Opened

PR #19809 was authored against an older revision of `main` (April 2025). Rebasing onto current `main` / `goose-lean` (`bc9c3868ce`) requires:
1. Splitting the `server/etcdserver/txn/txn.go` diff across `txn.go`, `put.go`, `delete.go`, and `range.go` (created when `txn.go` was split by operation).
2. Updating `txn.Count` in `server/etcdserver/txn/range.go:35`, which calls `Range(ctx, TxnContext{Logger: lg, KV: kv}, ...)` and did not exist when PR #19809 was opened.
3. Moving the `(*applierV3backend)` changes from `server/etcdserver/apply/apply.go` to `server/etcdserver/apply/backend.go` (and reading `a.options.{Logger, Lessor, KV, TxnModeWriteWithSharedBuffer}` instead of `a.s.*`).
4. Updating the two `txn.Range` calls in `(*EtcdServer).rangeStream` (`server/etcdserver/v3_server.go:199, 223`) and the benchmark calls in `server/etcdserver/txn/range_bench_test.go:100, 140`.

## The false claim

`ValueStartTime.spec`: for every `ctx` with `context.isContext ctx cd` and every key of type
`traceutil.StartTimeKey`, `ctx.Value(key)` returns `nil` or a `time.Time`. Its argument is a
closed-world one ("only etcd's request path stores under the key, with `time.Now()`",
`v3_server.go:302,374`). But `WithValue.spec` admits `key.ty = traceutil.StartTimeKey.ty` with any
`v` and gives an `isContext` of the result from an `isContext` of the parent, and Go's
`valueCtx.Value(k)` returns `v` at `k == key` (`context.go`, `valueCtx.Value`). So any program can
store a non-time value under the key, and the closed world is not one the axioms describe.

## WithValue's own claims (checked against `context.go` at go1.27.3)

- `c ≠ nil`, a `*valueCtx`: true.
- The `isContext` / `txnCtx` transfer: a `valueCtx`'s `Deadline`, `Done`, `Err` are the embedded
  parent's; `Value(&cancelCtxKey)` compares `c.key == k` across distinct dynamic types (false, no
  panic) and asks the parent, as `isContext`'s `HValue` needs. Perennial's `isContext` reads no
  descriptor's `Values` (only `Done_gn`/`PDone`/`Deadline`), so `{cd with Values := vs}` is harmless.
  `txnCtx`'s `doneNil` case: `Done()` is the parent's, nil too. Survives.
- The `Value` wand: at `k = key`, Go returns `v` (all five admitted key types are empty structs,
  so every value of the type is `key`: "nothing is said of another value" is vacuous); at `nil` or a
  key of another type `==` is false without panic and `value(parent, k)` returns what `parent.Value(k)`
  does for the standard library's contexts. Survives.
- Trace and incoming-metadata clauses: other key types, `Value` falls through to the parent. Survives.

So `WithValue` survives on its own; the flaw is `ValueStartTime`'s closed-world claim, which
`WithValue`'s open precondition makes false.

## What rests on it

`EtcdServer.raftRequest.wp_proof` (`hV`), hence 51 roots / 17 closed theorems (sweep plan, reach

does not panic on a non-time value: the falsity is in the axiom, not a bug in etcd.

## Proposed restatement (not applied)

Even "returns some value, no panic" is not true of every `isContext`: `isContext` is a predicate on
a context's `Deadline`/`Done`/`Err`/`Value(&cancelCtxKey)` and is satisfiable by a user type whose
`Value` panics at other keys (not tried: it needs an `isContext` proof of a user type). Two options:

1. A persistent predicate `startTimeOk ctx` that `ValueStartTime` takes, given by
   `Background`/`WithCancel*`/`WithTimeout*` (standard contexts, from a parent with it) and by
   `WithValue` when `key.ty ≠ StartTimeKey.ty ∨ v = nil ∨ v` is a `time.Time`, from a parent with it;
   the gRPC handler's context would need it from grpc's server axioms.
2. Simpler, if `raftRequest`'s proof needs only that the comma-ok assertion is safe: restrict
   `WithValue.spec`'s StartTimeKey disjunct to a `time.Time` `v` and give `ValueStartTime` a
   premise that the context was built by the axiomatized constructors (option 1's predicate again).

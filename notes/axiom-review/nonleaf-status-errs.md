# `proto.MarshalIRR`'s invalid-UTF-8 errors: `applyErrIs` admits non-context error trees (nonleaf-status-errs)

2026-11-26, branch `grpc-nonleaf-errs/2026-11-26` (dsverify-net lead, for coordinator-E; #18 7185966810,
7185985720). This fixes the open F1 of `errkeys-proto-renewhttp.md`. Design (2) was approved by the lead and
the coordinator on 2026-11-26. It replaces the first plan, which widened `statusErrOk`/`srvErrOk`.

## The defect

`proto.MarshalIRR.spec`'s error arm posts `applyErrIs err`. Until this change that implied `srvErrOk err`, which
needs a leaf error (`errors.isLeafError`), or a `%w` chain of context errors. Go's two invalid-UTF-8 errors are
neither. Both come from protobuf-go v1.36.12, in `$GOMODCACHE/google.golang.org/protobuf@v1.36.12/`:

- **Fast path: `impl.errInvalidUTF8{}`.**
  - It is a field-less struct: `internal/impl/codec_field.go:17`, `type errInvalidUTF8 struct{}`.
  - Its methods are `Error() string`, which returns a constant (`:19`), `InvalidUTF8() bool` (`:20`), and
    `Unwrap() error { return errors.Error }` (`:21`).
  - It is returned by the generated coders, for example `codec_gen.go:5047` in `appendStringValidateUTF8`.
- **Reflective path: `errors.InvalidUTF8(name)`.**
  - It returns `New(...)` (`internal/errors/errors.go:83-85`), which is `&prefixError{s: ...}` (`:20-22`).
  - `prefixError` is `struct{ s string }` (`:24`).
  - `(*prefixError).Error()` returns `prefix + e.s` (`:36-38`). `prefix` is a package variable fixed at
    initialization (`:26-34`).
  - `(*prefixError).Unwrap()` returns `Error` (`:40-42`).
- **The common unwrap target.** `errors.Error` is `errors.New("protobuf error")` (`errors.go:16`): an
  `*errors.errorString` pointer, with no `Unwrap` and no `Is` method.
- **No `Is` methods.** Neither `errInvalidUTF8` nor `*prefixError` has an `Is` method. The only `Is` method in
  `internal/errors` is `(*wrapError).Is` (`:66`), and neither failure path builds a `wrapError`.
- **`proto.Marshal` returns either error unwrapped** (`proto/encode.go:105-116`). Its only check on the error,
  `errors.As(err, &mismatch)` at `:201`, fails for both, so `:204` returns `err` itself.

`etcdserver.processInternalRaftRequestOnce` returns the error as it is (`server/etcdserver/v3_server.go:1095`).
It reaches the gRPC layer through `togRPCError` (`server/etcdserver/api/v3rpc/util.go:98-108`):

- If `errors.Is(err, context.Canceled)` or `errors.Is(err, context.DeadlineExceeded)`, it returns `err` as it is
  (`:100-101`).
- Otherwise it returns `toGRPCErrorMap[err]` if that is present (`:103`), or else
  `status.Error(codes.Unknown, err.Error())` (`:105`).

So the only place `srvErrOk` of such an error is ever used is the pass-through at `:101`, and it never happens
for these errors.

## The fix

All of the trusted text below is in `Proof/go_etcd_io/etcd/server/v3/etcdserver/apply/Base.lean`, unless a
file is named.

1. **`notCtxTree err`** (new; persistent). It is the conjunction of two `errors.noMatchTree` facts:
   - at `context.Canceled`'s value, with the typing `TreeTyped · c`;
   - at `context.DeadlineExceeded`'s value, with the typing `deTyped`.

   **`errors.noMatchTree P err target`** (new, in `Proof/errors/CtxErr.lean`) says: `err` is in an
   `errors.errorIsTree S M target` that has typing `P`, no error of `S` is `target`, and no error of `S` has
   `M`. This is the precedent's shape, factored out.

   `leasehttp.notLeaseNotFound` (`Proof/.../lease/leasehttp/RenewErr.lean`) is now restated over it. The
   statement is the same: `ii ≠ e` is now written `ok ii ≠ ok e`, and `ok` is injective.
2. **`applyErrIs`'s third conjunct**:
   - Before: `srvErrOk err`.
   - After: `srvErrOk err ∨ notCtxTree err`.
3. **`errKeyOk`** gains a fifth disjunct: `k = interface.mkOk impl.errInvalidUTF8.ty #(zero_val impl.errInvalidUTF8)`.
   - For this, the type is translated as its struct: `"errInvalidUTF8"` was added to the `translate` list in
     `Code/google_golang_org/protobuf/internal/impl.toml`, and project `etcd` was regenerated by
     `etc/goose.py`.
   - The type was names-only, with an opaque `underlying`, so its `==` had no semantics. Its methods stay
     names-only.
   - The regeneration also turns the type's two `sorry -- axiomatized type` instances in
     `GeneratedProof/.../internal/impl.lean` into proved ones.
4. **`proto.MarshalIRR.spec`**: the text is unchanged. Its post is now true on both failure paths:
   - `applyErrIs`'s tree: exact relations; the `Unwrap`s go to `errors.Error`; there are no `Is` methods; the
     `TreeTyped`/`deTyped` typings hold. The `errInvalidUTF8` node is a non-pointer and has no
     `deadlineExceededError` type.
   - `errKeyMsg`: `*prefixError` is a pointer key; `errInvalidUTF8{}` is the new key; each `Error()` returns
     one fixed string.
   - `notCtxTree`: `errors.Error` is neither `context.Canceled`'s pointer nor `deadlineExceededError{}`, and
     no `Is` method answers.

   The docstring now records this. No UTF-8 premise was added.

There are no new axioms, premises or opaque definitions. No top-level statement changes, as checked against
every `Spec/**/TopLevelRobustness.lean` and `TopLevelDefs.lean`: none reaches `applyErrIs` or `errKeyOk`.

## Trusted statements whose meaning changes (old → new, with reason)

**How the list was found.** The script `tmp/dsn/nonleaf-scripts/reach3.py`, kept outside the repo, does the
following:
- It computes the fixpoint of the definitions whose bodies mention `applyErrIs`/`errKeyOk`/`errKeyMsg`,
  following short names defined at most twice.
- It checks every `axiom` of the main tree against that set, through the axiom's statement and its imported
  spec file.
- Separately, a scan of every `{{ … }}` precondition found `applyErrIs`/`srvErrIs` only in proved specs:
  `read.isStopped`, `notifier.notify`, `togRPCError`, `kvServer.RangeStream`, and some local proof lemmas.

The axioms it found (15 hits) are listed below.

### Stronger (a precondition holds a contract whose post's `applyErrIs` is now weaker, so the axiom assumes less)

**What the new class adds.** An error the new class admits and the old did not satisfies the old tree
conjunct (exact `Is`/`Unwrap` relations, typings), `errKeyMsg` (a map key whose `Error()` returns one fixed
string), and `notCtxTree`. It is not `srvErrOk`. So it can have `Unwrap` or `As` methods, `GRPCStatus` or
`Format` methods it does not specify, or a non-`stTypedErr` type. The new key is `errInvalidUTF8{}`.

**Why the strengthening is true of Go.** In Go, the consumers of an error value behave as follows:
- `errors.Is` needs only the `Is`/`Unwrap` specs, which the tree conjunct still gives.
- `==` and map lookup are defined on every comparable dynamic type. A field-less struct is comparable and has
  one value (Go spec, "Comparison operators").
- `err.Error()` is covered by `errMsgOk`.
- `fmt` recovers panics in `Error`/`Format`/`String` (`src/fmt/print.go:580`, `catchPanic`, go1.27.3).
- zap's `encodeError` recovers panics too (`go.uber.org/zap@v1.28.0/zapcore/error.go:47-58`).
- The only consumers that rely on `srvErrOk`'s extra facts are grpc's `status.FromError`/`Code`/`Convert`
  (grpc v1.84 `status/status.go:96-146`: `GRPCStatus`, then `errors.As`), which grpc's server applies to a
  handler's error (`server.go:1461-1466`), and the prometheus interceptor. A hypothetical error of the new class
  whose `As`/`GRPCStatus` method panicked could make those panic.

So each axiom below is true for the wider class provided its Go code never hands an error from such a contract
to grpc's `status` functions or to `errors.As` without first passing it through `togRPCError`. `togRPCError` is
proved, so the server only ever sees its post, which is unchanged: `srvErrOk`. This was checked for each axiom.

In Go, none of these contracts (raft's `Propose`, the read notifier, the auth checks, the lessor) ever returns a
non-leaf error. The strengthening is formal: it admits implementations that do. It is sound by the reasons in
the table.

### `errKeyOk`'s new disjunct as an input

`errKeyOk` is taken directly, as a precondition, only by proved code:
- `v3rpc.wp_errKey_eq`, `safeMapKey_errKeys`, `wp_errMap_lookup2(_at)` and `wp_errMapInsert` (`ErrMapKey.lean`,
  `ErrMapInit.lean`);
- `stTypedErr_of_valKey`;
- `togRPCError` (through `srvErrIs`).

New proofs cover the new key:
- `v3rpc.wp_eq_utf`: `==` of `errInvalidUTF8{}` with itself is `true`, from its translated `fields = []`.
- `utf_ne_ptr`, `de_ne_utf`, `ic_ne_utf`: different dynamic types give `false`.

Through `applyErrIs`, the axioms in the table above take it too. Verdict (a) for them: `errInvalidUTF8{}` is
comparable in Go and equal only to itself, so `==` and map lookups on it never panic.

### Unchanged

`statusErrOk`, `srvErrOk`, `grpcErrMethodsOk`, `status.FromError`/`Code`/`Error`/`Errorf`, `errors.IsStatusErr`,
the grpc server and prometheus axioms, and `rpctypes.Error` are unchanged: no receiver of `statusErrOk`/
`srvErrOk` is widened. `statusErrOk ⊢ errStrOk` (`errStrOk_of_statusErrOk`) holds as before.

## Consumers of `applyErrIs` (proof side)

`applyErrIs` is mentioned in about 130 files. They fall into five groups:

1. **Predicate passed on by name** (spec posts, invariants, contracts). These are unaffected: the change is
   inside the definition.
2. **Readers of the tree conjunct** (`applyErrIs_tree`/`_walk`/`_treeDE`/`_walkDE`; the conjunct is
   unchanged):
   - `CompactEnv`, `EtcdServer__Authenticate`, `EtcdServer__LeaseRenew`, `EtcdServer__PromoteMember`,
     `NoSpaceDead`;
   - v3rpc's `LeaseServer__LeaseLeases`, `LeaseServer__LeaseTimeToLive`, `LeaseServer__leaseKeepAlive`,
     `serverWatchStream__recvLoop`, `togRPCError`;
   - apply's `DispatchAdmin`, `DispatchKVL`, `uberApplier__dispatch`;
   - `read/isStopped`.
3. **Readers of `errKeyMsg`**: `api/v3rpc/ServerKV.lean:83` and `InvAuthAdmin.lean:271`. Unaffected: the
   conjunct is the same apart from the wider `errKeyOk`, which they pass on.
4. **Readers of the third conjunct**:
   - `togRPCError` (`applyErrIs_srv`): in the `notCtxTree` arm it calls `errors.Is` with that tree, gets
     `false` both times, and never passes the error through.
   - `SrvCtxWeakLaws.v3rpc.srvErrOk_of_weakErr` (`applyErrIs_srvErrOk_ctx`): its error is a context error,
     which no `notCtxTree` is (`notCtxTree_isCtxErr`).
5. **Producers** (`applyErrIs_nil`, `_leaf`, `_valLeaf`, `_ctxWrap`, and the lemmas built on them: `_of_isCtxErr`,
   `_of_nodeErr`, `_ctxErrorf`, ...): they give the left disjunct (`ileft`), so they are unchanged in strength.

The full VM build is the check of this list.

# etcd-io/etcd#21335: panic: etcdserver: leader changed

- URL: https://github.com/etcd-io/etcd/issues/21335 (filed 2026-02-20, closed 2026-05-07 as "not an
  etcd issue"; label `type/bug`). etcd v3.5.23 embedded in Milvus standalone (follow-up: the
  Milvus issue milvus-io/milvus#47419).
- What happens (from the attached log): a single-member embedded etcd restarts as a follower at term
  5611. Milvus issues a linearizable `Range` (`by-dev/meta/session/id`) at once. The read loop's
  `ReadIndex` finds no leader and is dropped by raft (`stepFollower`); etcd retries after 500 ms. The
  node then elects itself at term 5612, `leaderChanged` fires, and `requestCurrentIndex` returns
  `ErrLeaderChanged` (gRPC `Unavailable`, "etcdserver: leader changed"). Milvus's
  `sessionutil.(*Session).Init` (`session_util.go:308`) panics on that error. Milvus most likely uses
  the in-process client (`useEmbedEtcd=true`), which has no retry interceptor, so the error is not
  retried.

## Classification

**N (not a bug in etcd: the client treats a documented retryable error as fatal).** The
maintainers closed it as Milvus's. `ErrLeaderChanged` is `codes.Unavailable`
(`api/v3rpc/rpctypes/error.go:79`), which the gRPC client's retry policy retries for reads
(`isSafeRetryImmutableRPC`, `client/v3/retry.go:54`). The specs here state the behavior: the read
loop may fail.

- `Read.requestCurrentIndex.spec`
  (`Spec/go_etcd_io/etcd/server/v3/etcdserver/read/Read__requestCurrentIndex.lean`) returns
  `applyErrIs err`, with the index guarantee only when `err = nil`. The leader-change branch
  (`read.go:170-172`, `190-193`) is one of the error exits, and `LinearizableReadNotify`/`Range`
  pass the error through (`read_notify`, `read/Results.lean`).
- The client side: `isSafeRetryImmutableRPC.spec`
  (`Spec/go_etcd_io/etcd/client/v3/isSafeRetryImmutableRPC.lean`) states only "some boolean" (true
  only for `Unavailable`), not that `Unavailable` *is* retried. The in-process client (`v3client.New`,
  `clientv3.NewCtxClient`, `client.go:97`) is not translated. Neither matters for the
  classification.

## Proposal

None (N). A side note: the client's retry specs could state that
an `Unavailable` server error on an immutable RPC is retried (`isSafeRetryImmutableRPC` returns
`true`). That C-err refinement would document the retry that the in-process client Milvus uses does not do. It is
small, but no bug calls for it.

## Findings

None.

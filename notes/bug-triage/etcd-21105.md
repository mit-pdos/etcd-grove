# etcd-io/etcd#21105: etcdutl hashkv panic: no lessor to attach lease

- URL: https://github.com/etcd-io/etcd/issues/21105 (closed 2026-01-22; label `type/bug`).
  Affected: `etcdutl` 3.7.0-alpha.0 (`main`), on any snapshot with a leased key.
- Fix: PR #21106 "etcdutl: fix hashkv 'no lessor to attach lease' panic" (merge `9a2b574b7`,
  2026-01-21): `etcdutl`'s `calculateHashKV` passes a `SimpleLessor` instead of `nil` to
  `mvcc.NewStore`.

What goes wrong: `etcdutl hashkv` opened the snapshot's backend and called
`mvcc.NewStore(lg, b, nil, cfg)`. `NewStore` → `store.restore` rebuilds the index from the
`Key` bucket and, for every key with a lease, panics if `s.le == nil` (`kvstore.go:393-397` at
the pin, unchanged: the fix is in the caller).

## Classification

**F (fixed before the verified code); counterfactually O-pkg, and the call is excluded by
`NewStore`'s premise.** The fix `9a2b574b7` is an ancestor of the pin `107edf7e4`
(`etcdutl/etcdutl/hashkv_command.go:63` passes `&SimpleLessor{}`). The faulty code is `etcdutl`,
which nothing here translates; the mvcc side's panic remains but is unreachable from a caller
that meets `mvcc.NewStore.spec`: it requires `mvcc.isLessor le γl`, whose definition starts
`∃ lp, ⌜le = lease.lessorIface lp⌝` (`Proof/go_etcd_io/etcd/server/v3/storage/mvcc/InvStore.lean:950-951`),
so a `nil` lessor is not admitted. A verified `calculateHashKV` could not have been proved with
`nil` (F+ at the interface), but there is none, and `store.restore` with data is an axiom stated
only for an empty backend (`Spec/…/mvcc/store__restore.lean:2,35`), so the leased-key loop is
not verified either.

Source: `Code/go_etcd_io/etcd/` (no `etcdutl`), the mvcc `Spec/`/`Proof/` files; `verified.txt`
was not produced.

## Proposal

`mvcc-restore-from-backend` (existing): specify and prove `store.restore` on a non-empty backend.
Its spec would state the lease case: every leased key is attached through `isLessor`'s `Attach`
(so a `nil` lessor is excluded by the premise, as today, and the panic branch shown dead). The
`etcdutl` side is O-pkg and small; not worth verifying on its own. Note for upstream (not filed):
`NewStore`'s comment ("It should only be used for testing externally") does not say that `le`
may be `nil` only for a store without leased keys.

## Findings

None (the bug is not in the pinned caller; the mvcc precondition is recorded by `NewStore.spec`'s
premise, and `NewStore` is documented as test-only for external callers, so no `issues/` file).
No bug in this repository's specs.

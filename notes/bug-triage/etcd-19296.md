# etcd-io/etcd#19296: grpc-proxy: subsequent client watchers hang after the auth token expires

- URL: https://github.com/etcd-io/etcd/issues/19296 (filed 2025-01-28, closed 2025-10-18 by the
  stale bot, unfixed; labels `type/bug`, `stage/triaged`, `priority/awaiting-more-evidence`).
  Version v3.5.17. Maintainers called it "a valid issue" and reproduced it (nwnt).
- Reproduction (an e2e test in the report): auth is on with simple tokens and a TTL of 1 s.
  Client A watches `/test` through the proxy. A's token expires. Client B logs in and watches
  `/test` through the proxy. From then on neither A nor B gets events.
- Proposed fix: PR #19033 (open), "use metadata instead of context withvalue in with client auth
  token".

What goes wrong (at the pin, all in `server/proxy/grpcproxy/`): `newWatchBroadcast` passes the
watcher's token to the backend client as a context *value*
(`withClientAuthToken`, `util.go:37-43`; `watch_broadcast.go:66`). `AuthStreamClientInterceptor`
(`util.go:68-75`) attaches that value as per-RPC credentials only when a gRPC stream is *opened*.
The verified client keys its watch streams on the *outgoing metadata*
(`streamKeyFromCtx`, `client/v3/watch.go:1090-1095`), and the token is not there. So every
broadcast of every user shares one backend watch stream, authorized with the token of whoever
opened it, here A. The server checks each new watch with the stream's context
(`isWatchPermitted`, `server/etcdserver/api/v3rpc/watch.go:237-247`). B's watch is therefore
checked with A's expired token and refused. The client closes B's channel after a final
`Canceled` response (`addSubstream` sets the stream's `closeErr`, `client/v3/watch.go:467-470`;
`closeSubstream`, `:494-495`). B's broadcast is then dead and keeps taking watchers (etcd#21813).
Its `nextrev` is reset to 1 by that final response, so `coalesce` can also move A's receivers into
it. That accounts for "both A and B hang" (see `etcd-21813.md`).

## Classification

**O-pkg** (O-path in kind; secondary: the dead-broadcast defect of etcd#21813). The faulty code
is the proxy's (`withClientAuthToken`, `AuthStreamClientInterceptor`, the broadcast), which is
not translated: no `Code/` module, and no row in the inventory
(`/shared/etcd-grove-triage/coord/verified.txt`). It is present at the pin `107edf7e4`. The
verified functions on the path behave as their specs allow:

- `streamKeyFromCtx.spec` returns "some string" (`Spec/go_etcd_io/etcd/client/v3/streamKeyFromCtx.lean`,
  "the watcher's safety does not need two calls on one context to agree");
- `serverWatchStream.isWatchPermitted` and `authStore.AuthInfoFromCtx` (both verified) have specs
  without identity: some auth info, or some error.

This is the mechanism of `issues/etcd-inproc-watch-shared-auth.md` (etcd#17502), with the gRPC
proxy in the role of the in-process `v3election` client. Watches of different users share a
client watch stream, because the caller's token is not in the outgoing metadata, and the server
authorizes them all as the stream's first user. Here the first user's token has expired, so the
effect is a refusal, and the proxy turns that refusal into a silent hang.

## Proposal: `inproc-client-auth-identity` (see `etcd-17502.md`)

The same proposal, with its scope widened from the in-process client to the proxy. Give the auth
specs an identity (`authOf ctx`; `isWatchPermitted` returns `nil` iff `permitted (authOf (stream
ctx)) range`). Then state that every backend request the proxy makes on behalf of a client RPC
with context `c` is authorized as `authOf c`. For the watch, that makes "watchers share a client
stream only if they have the same `authOf`" a premise of `watcher.Watch`, which the proxy at the
pin violates. With PR #19033's metadata, `streamKeyFromCtx` separates the streams and the premise
holds. The expiry half needs the token-lifetime model that the proposal already names for
etcd#17623. Cost: as for that proposal (medium), plus translating the proxy's `util.go` (75 lines)
and the watch path (`grpcproxy-watch-relay`, see `etcd-21813.md`), which the hang needs as well.

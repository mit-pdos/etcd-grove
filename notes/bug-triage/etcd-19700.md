# etcd-io/etcd#19700: panic: runtime error: comparing uncomparable type `map[string]interface {}`

- URL: https://github.com/etcd-io/etcd/issues/19700 (closed 2026-02-04; labels `type/bug`,
  `stage/triaged`)
- Affected: `client/v3/naming/resolver` (the gRPC naming feature) with grpc-go v1.71.0, when an
  endpoint's `Metadata` is a map.
- Fix: on grpc-go's side, grpc/grpc-go#8227 (merged 2025-04-16; `pickfirstleaf` no longer compares
  `Address.Metadata`). On etcd's side, commit `84862dbd6` ("Remove the use of grpc-go's Metadata
  field", 2026-01-27, closing #19706): `convertToGRPCEndpoint` no longer copies
  `Endpoint.Metadata` into `gresolver.Address.Metadata`. That commit is an ancestor of the pin
  `107edf7e4` (`git merge-base --is-ancestor`: yes). At the pin, `resolver.go:109-123` sets only
  `Addr`, and `go.mod` has grpc v1.84.0.

What went wrong: etcd's resolver passed the user's `endpoints.Endpoint.Metadata` (any type; a map
after a JSON round trip through etcd) as grpc's deprecated, experimental `Address.Metadata`.
grpc-go 1.71's pick-first balancer compared addresses with `==`, which panics on an uncomparable
dynamic type.

## Classification

**F− (O-pkg; the panic is in a dependency).** The fix is in the pin. Counterfactually, nothing here
covers it: `client/v3/naming/{resolver,endpoints}` are not translated, and grpc-go's balancer is
outside every trust-boundary spec. Goose's model would make the interface `==` panic, but only if
the code were translated, which neither etcd's resolver nor grpc's balancer is. The bug came from
a dependency's change to an experimental API (etcd-io/etcd#15145), not a logic error in etcd.

## Code path

| Go function | State |
|---|---|
| `naming/resolver.resolver.watch` → `convertToGRPCEndpoint` | not translated |
| `naming/endpoints` (`Endpoint.Metadata`) | not translated |
| grpc-go `resolver.ClientConn.UpdateState` → `pickfirstleaf` address comparison (the panic) | outside the trust base |

## Proposal

None counted. A verified resolver would sit on a trust-boundary spec of grpc's
`resolver.ClientConn.UpdateState`. That spec would have to name the premise ("addresses' `Metadata`
comparable", or after `84862dbd6` "unset"), which is the kind of dependency-version assumption the
trust base should record. That is too little benefit for the cost of translating the naming
packages.

## Findings

None: fixed before the pin; no `issues/` file; no bug in this repository's specs.

# etcd-io/etcd#17265: etcd 3.4.29 panic: nil pointer dereference

- URL: https://github.com/etcd-io/etcd/issues/17265 (closed 2024-01-20; labels `type/bug`,
  `release/v3.4`)
- Affected: 3.4.29 (and earlier 3.4) with `--logger=capnslog` (the 3.4 default), when the
  gRPC gateway fails to register.
- Fix: PR #17270 on `release-3.4` (commit `9009d3ec7`, merge `d441d74c0`), in 3.4.30.

What goes wrong: in 3.4 the serving context's zap logger `sctx.lg` is `nil` under capnslog.
`embed/serve.go`'s `serveCtx.serve` logged the `registerGateway` failure (and the two
`configureHttpServer` failures) with `sctx.lg.Error(...)`, a nil `*zap.Logger` →
`zap.(*Logger).check` dereferences nil. The fix checks `sctx.lg != nil` and falls back to
`plog`. Why `registerGateway` failed (the root error) was not pursued.

## Classification

**F (release-branch only; `main` never had it), counterfactual O-pkg.** The bug exists only in
3.4's dual-logger code. On `main`, and at the pin `107edf7e4`, `newServeCtx`
(`server/embed/serve.go:102-108`) replaces a nil logger with `zap.NewNop()`, and capnslog is
gone, so `sctx.lg` is never nil (the same `sctx.lg.Error("registerGateway failed", …)` at
`serve.go:157` is safe there). Counterfactually, `embed` is not translated (`verified.txt` lists no
`server/v3/embed` function, not even names), so nothing here would have looked at it: F−, gap O-pkg.

## Code path

| Go function | State |
|---|---|
| `embed.(*Etcd).serveClients` → `serveCtx.serve` → `registerGateway` | not translated (3.4: `embed/`; `main`: `server/embed/`) |
| `zap.(*Logger).Error` on a nil receiver | outside (zap is names-only here) |

## The counterfactual (step 5)

Any Goose-verified `serveCtx.serve`, even with the trivial spec `{{ True }} serve … {{ True }}`,
would have excluded the panic. A method call through a nil `*zap.Logger` needs the logger's
points-to, which a nil pointer cannot provide. So the bug class is "unverified glue code", not a
weak spec. The proposal is translating and verifying `embed`'s serving code with a crash-freedom
spec, the same shape as `verify-rafthttp-handlers` but in another package. That is about 400
lines of `serve.go`, dominated by HTTP/gRPC/TLS library axioms, for little safety value. Not
proposed as a slug: on `main` the nil-logger case is closed by construction (`newServeCtx`).

## Findings

None: not present on `main` or at the pin. No bug in this repository's specs.

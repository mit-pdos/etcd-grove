# etcd-io/etcd#14631: `concurrency.NewSession` hangs after the etcd server is stopped (SIGSTOP)

- URL: https://github.com/etcd-io/etcd/issues/14631 (closed 2025-06-22 by the stale bot; labels
  `type/bug`, `help wanted`, `stale`, `release/v3.5`)
- Affected: client v3.5.5 (reported); unchanged at the pin.
- Fix: none. PR #16385 (open) adds a session option bounding session creation; the maintainers'
  diagnosis (fuweid): the client's default call option `grpc.WaitForReady(true)` queues the RPC
  until a connection is ready, and with a connection that is ready but whose peer is frozen the
  RPC waits for the HTTP/2 response; both are bounded by passing a context with a deadline
  (`WithContext`). Related: #13344 (expose the call options).

What goes wrong: `NewSession(client)` (`client/v3/concurrency/session.go:41`) uses the client's
context (`client.Ctx()`, no deadline) unless `WithContext` is given, and calls
`client.Lease.Grant(ops.ctx, ttl)` (`:50`). `lessor.Grant` (`client/v3/lease.go:222`) calls the
gRPC stub with `l.callOpts`, which include `defaultWaitForReady = grpc.WaitForReady(true)`
(`client/v3/options.go:29,63`). With every endpoint stopped (or the connected one frozen; the
report sets `DialKeepAliveTimeout` but not `DialKeepAliveTime`, so gRPC keepalive pings are off),
the call never returns.

## Classification

**O-fn (secondary C-live; arguably N: behavior by design, bounded by a caller's deadline).** The
path is at the pin unchanged. The blocking call is `lessor.Grant`, which is not translated
(`Code/go_etcd_io/etcd/client/v3.toml` lists no `lease.go` function), and below it gRPC's
`WaitForReady` wait, at the trust boundary. The verified caller `NewSession` assumes
`isEtcdLease`, whose `Grant` is a partial-correctness triple: a `Grant` that never returns meets
it, and so does a `NewSession` that never returns. Even with the lessor verified, the hang would be
C-live: no spec here states termination.

Source of verification states: no `verified.txt`; the `.toml`, `Spec/`, `Proof/` files.

## Does the spec exclude it?

`NewSession.spec` (`NewSession.lean:32-42`): from `isEtcdSessionClient` and a cancelable options
context, *if it returns*, either `nil` with an error or a session. The hang is a run that does not
return: every Hoare triple holds of it. The premise `isEtcdLease` (`InvEtcdTxn.lean:1123-1134`)
has the same form for `Grant`, and is true of the real lessor (it returns an error or an ID ≠ 0
whenever it returns), so not A-axiom. gRPC's `Invoke` axiom is likewise partial: it does not
promise that a call with `WaitForReady` and no deadline returns, so not A-axiom either. What the
user expected (an error when the cluster is down) is a termination property; the code gives it
only when the caller's context has a deadline, which `NewSession`'s documentation does not say.

## Proposal: `verify-client-lessor` (the safety part); the hang itself is liveness

As in `etcd-22081.md`, translating and verifying the lessor would make `Grant`'s call options part
of a spec (`Grant` passes the caller's `ctx` and the client's `callOpts` to the RPC unchanged), so
that `NewSession`'s spec can state which context bounds it: with `WithContext(ctx)`, the only
blocking call is an RPC under `ctx`. That `ctx`'s deadline makes it return is gRPC's liveness,
outside Iris-style partial correctness (record, do not attempt). A cheaper action is
documentation: `NewSession` blocks until a member is reachable unless `WithContext` gives a
deadline (or #16385's option). Cost of the lessor proof: medium to large, shared with #22081 and
#22094.

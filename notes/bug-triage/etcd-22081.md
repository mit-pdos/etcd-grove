# etcd-io/etcd#22081: `closeRequireLeader` pairs keep-alive channels with the wrong contexts

- URL: https://github.com/etcd-io/etcd/issues/22081 (open; label `type/bug`)
- Affected: every version since 2017 (`8024a0d15f`); present on `main` and at the pin.
- Fix: none merged. PR #21872 (closed unmerged) and #22087 (open) make the one-line fix
  `ka.ctxs[newIdx]` → `ka.ctxs[i]`. Follow-up bug in the same function: #22094
  (`etcd-22094.md`).

What goes wrong: `lessor.KeepAlive` (`client/v3/lease.go:280`) registers each subscriber of a
lease as index `i` of two parallel slices `ka.chs`/`ka.ctxs`. On `ErrNoLeader` from the lease
stream, `recvKeepAliveLoop` (`:456`) calls `closeRequireLeader` (`:383-418`), which closes the
channels of subscribers whose context carries `WithRequireLeader`, then compacts both slices
with `newCtxs[newIdx] = ka.ctxs[newIdx]` (`:413`) instead of `ka.ctxs[i]`. After a removed
subscriber, every survivor gets its predecessor's context and the last survivor's context is
dropped. `keepAliveCtxCloser` (`:349-380`), which closes the channel at the index of the cancelled
context, then closes the wrong channel or none. Reproduced at the pin (test in
`issues/etcd-lease-requireleader-ctx-misaligned.md`): after removing `A` from `[A, B, C]`,
cancelling `C` closes nothing.

## Classification

**O-fn (secondary C-live, for the verified caller `Session`).** The bug is in the pinned code
(line 413 unchanged at `107edf7e4`), but `client/v3`'s lessor is not translated at all
(`Code/go_etcd_io/etcd/client/v3.toml` translates a list of functions, none of `lease.go`; only
the `Lease` interface type is there), while other functions of `client/v3` are verified (the KV
client, the watch client, the retry interceptor). Its verified caller `concurrency.Session`
assumes the lessor's contract `isEtcdLease`, whose `KeepAlive` promises nothing of the channel
(`isChanAny`), and its specs are partial correctness: the bug's visible consequence on a session
(a `Close` that never returns, a session ended by another subscriber's cancel) meets them.

Source of verification states: `verified.txt` was not available; states read from
`Code/go_etcd_io/etcd/client/v3.toml` (what is translated), and `Spec/`, `Proof/`,
`Proof/go_etcd_io/etcd/client/v3/concurrency/Link.lean`.

## Does the spec exclude it?

The lessor has no spec of its own. What the verified code assumes of it is `isEtcdLease`'s
`KeepAlive` clause (`InvEtcdTxn.lean:1135-1140`): an error, or a channel with `isChanAny γ ch`
("a receive yields any value or the close: the stream may end at any time",
`notes/decisions.md` "Leases without liveness"). The two outcomes of the bug for a session whose
keep-alive survives a require-leader removal:

1. its channel is closed by another subscriber's cancel: the session's goroutine sees the close,
   closes `donec`, and `Done` fires early. `isChanAny` allows a close at any time, and nothing in
   `isSession` ties `donec` to the session's own cancel. Admitted.
2. its own context is dropped from `ka.ctxs`: `Close`/`Orphan` cancel the context, then wait on
   `donec`, which closes only when the keep-alive channel does; the lease keeps being renewed (the
   channel is still in `ka.chs`), so it never does while the client lives. `Session.Close.spec`
   is a Hoare triple whose postcondition `sessionDone s γ` holds only on return: a call that never
   returns meets it. Admitted (C-live).

So the real lessor does meet `isEtcdLease` (nothing is promised), the premise is not false (not
A-axiom), and the mutual-exclusion results (`mutex_exclusion`, `election_exclusion`,
`concurrency/Results.lean:104,153`) are unaffected: they do not depend on the lease staying alive
or ending. What the user expected — cancelling a `KeepAlive` context closes that call's channel
(the interface documentation, `lease.go:130-131`) — is stated nowhere.

## Proposal: `verify-client-lessor`

Translate and verify `client/v3/lease.go` (about 650 Go lines: `KeepAlive`, `keepAliveCtxCloser`,
`closeRequireLeader`, `recvKeepAliveLoop`, `recvKeepAlive`, `deadlineLoop`, `sendKeepAliveLoop`,
`Grant`, `Revoke`, `Close`, with gRPC's lease stream at the trust boundary) against a stronger
`isEtcdLease`:

- a lock invariant of `lessor.mu`: for each `id`, `len ka.chs = len ka.ctxs`, and a ghost map from
  each live registration `j` (allocated by `KeepAlive`) to its pair `(ch_j, ctx_j)` with
  `ka.chs[i] = ch_j ↔ ka.ctxs[i] = ctx_j`, every channel in `ka.chs` open and owned by the map;
  `l.keepAlives[id]` present → `ka.chs ≠ []` (this conjunct catches #22094);
- `KeepAlive` returns, with the channel, a token `kaReg j ctx ch`, and the safety stand-in for "the
  channel closes after cancel": `keepAliveCtxCloser`'s spec (run on cancel) ends with
  `kaClosedOrGone j`, i.e. `ch_j` is closed, never another registration's channel;
- `Session`'s spec then gains: `Orphan` returns once the session's channel is closed, with the
  closer's token; the liveness itself (`Close` returns) stays outside partial correctness.

The misaligned `ka.ctxs[newIdx]` breaks the pairing conjunct at `closeRequireLeader`'s
compaction loop, so the proof would fail exactly at line 413. Cost: medium to large (goroutines,
timers modelled as nondeterministic wake-ups, maps of slices; the stream is an axiom like
`watchGRPCStream`'s); `Session`'s proofs re-run with the stronger `isEtcdLease`.

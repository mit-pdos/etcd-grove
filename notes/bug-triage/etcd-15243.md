# etcd-io/etcd#15243: `MemberList` doesn't work after adding a new member to a one-node cluster

- URL: https://github.com/etcd-io/etcd/issues/15243 (closed 2023-02-27; label `type/bug`)
- Affected: the 3.5 client (3.5.7). The reporter first suspected a regression of #9949.
- Outcome: a maintainer (ahrtr) calls it expected behavior. Closed by PR #15261 ("clientv3: support
  serializable `MemberList` operation", merge `da4bf0f76`, 2023-02-27), a feature, not a fix.

What happens. On a healthy one-member cluster `{A}`, `member add B` without starting B. The
configuration becomes `{A, B}` and its quorum is both members. The 3.5 client's `MemberList`
sends `Linearizable: true`. The server's `EtcdServer.MemberList` (`server.go:1663`) then calls
`s.read.LinearizableReadNotify`, which needs a read index confirmed by a quorum. B is not
running, so the call times out. `get` with `--consistency=s` still works.

## Classification

**N** (works as intended; the request became a feature). The decisive fact: the linearizable
read needs a quorum of `{A, B}`, which does not exist while B is down. The member list is
answered only after the read barrier (`server.go:1664-1667`). The serializable option that the
reporter wanted is in the pin: `client/v3/cluster.go:125-127`, `Linearizable:
!opt.serializable`.

| Go function | State | Spec |

The verified read-index specs document what the maintainer says. A read index is released only
when a quorum of the current configuration has acknowledged the leader's heartbeat
(`readOnly.recvAck`/`maybeAdvance`, `raft.Step`'s `ReadOnlySafe` case). The fork's single-voter
shortcut (`issues/raft-readindex-singleton-stale.md`) does not apply, because `{A, B}` has two
voters. Unavailability while there is no quorum is the specified behavior; the specs are partial
correctness, so a timeout meets them. The reporter's other question was whether adding a member
that is not running should be allowed. It is a policy question: `mayAddMember` refuses it under
`--strict-reconfig-check` unless the cluster has one member, which is the reporter's case and
is deliberate (`cluster.go` `IsReadyToAddVotingMember`).

## Proposal

None (class N). Related and already proposed: `membership-read-barrier` (that the member set a
linearizable `MemberList` returns is the applied log's configuration).

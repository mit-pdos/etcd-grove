# etcd-io/etcd#19778: Missing deadline for LeaseGrant when creating session

- URL: https://github.com/etcd-io/etcd/issues/19778 (closed 2026-07-12 by the stale bot; label
  `type/bug`). Reported against 3.5.12, by code reading (and an interceptor showing the RPC has no
  deadline).
- Report: `concurrency.NewSession` calls `client.Lease.Grant(ops.ctx, ttl)` with the session's
  context, by default the client's (`client.Ctx()`), which has no deadline; if the RPC hangs,
  `NewSession` blocks forever. `Session.Close` bounds its `Revoke` by the TTL; the reporter asks for
  the same in `NewSession`.
- Fix: none merged. PRs #20022 and #20994 (a `context.WithTimeout` around the `Grant`) were closed
  unmerged. A commenter pointed at the existing mechanism; `WithContext`'s documentation at the pin
  (`client/v3/concurrency/session.go:147-151`) says it "is useful for canceling NewSession and Close
  operations immediately without having to close the client".

The code at the pin is the reported one (`session.go`, `NewSession`: `client.Lease.Grant(ops.ctx,
int64(ops.ttl))`).

## Classification

**N (the caller controls the deadline through the documented `WithContext`; secondary C-live).**
Nothing is wrong in what `NewSession` returns; the complaint is that it may not return. The function
is verified (`Spec/go_etcd_io/etcd/client/v3/concurrency/NewSession.lean:32`, proved, `wp_NewSession`
in the package's `Link.lean`), and its spec is a partial-correctness triple: a call that never
returns meets it. The `Grant` it calls is the trust-boundary contract `isEtcdLease`
(`Proof/go_etcd_io/etcd/cache/v3/InvEtcdTxn.lean:1121`), which promises what a returned `Grant`
gives (an error or an ID other than `NoLease` with `etcdReached` of its header revision), not that it
returns: `notes/decisions.md:1476`, "Leases without liveness". If upstream had judged it a bug, the
class would be C-live.

## The argument (step 4)

The observed behaviour — `NewSession` blocked in `Grant` — is a non-terminating execution. The
spec's postcondition is about returned values only, so it admits it whatever `Grant` does; the
`Grant` contract does not say `Grant` returns, and nothing says a context with a deadline makes it
return (Perennial's context specs, `context.isContext`, describe `Done`/`Err`, not the gRPC call's
reaction to them). A caller-supplied deadline (`WithContext(ctx)` with `WithTimeout`) is the
documented remedy; the proposed fix would only change the default.

## Proposal

None (class N). The closest verification of the liveness concern, should it matter: a safety
stand-in on the `Grant` contract, "if the context's `Done` is closed, the call returns `ctx.Err()`
or a result", which would let `NewSession`'s spec say "with a context that has a deadline, it
returns an error or a session" only together with a termination argument — outside Iris-style
partial correctness. Not worth a slug now.

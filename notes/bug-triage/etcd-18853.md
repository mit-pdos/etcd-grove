# etcd-io/etcd#18853: Close of already closed channel causes a panic

- URL: https://github.com/etcd-io/etcd/issues/18853 (closed 2025-12-28 by the stale bot; labels
  `type/bug`, `stale`)
- Affected: v3.5.9 and v3.5.12 (embedded etcd, illumos). No fix and no PR. The reporter later
  suspected their own service had called `Stop`, and so `Etcd.Close`, twice, and could not
  reproduce it.

What goes wrong: `embed.(*Etcd).Close` (`server/embed/etcd.go:413-485` at the pin) does its
shutdown in `e.closeOnce.Do(...)`, but closes `e.errc` after it, outside the `Once`: `if e.errc !=
nil { close(e.errc) }` (`:481-483`). `errc` is never set to `nil`, so a second `Close` panics with
"close of closed channel". The code is unchanged at the pin `107edf7e4`.

## Classification

**O-pkg (the cause is probably the embedder's double `Close`, an N-ish misuse).** `server/embed`
is not translated (no `Code/go_etcd_io/etcd/server/v3/embed*`, nothing in `verified.txt`). No spec
here says anything about `Etcd.Close`. The panic needs a second `Close`, which the reporter's
framework probably made. `Close`'s documentation ("Close gracefully shuts down all
servers/listeners") does not say whether a second call is allowed. The `sync.Once` suggests it was
meant to be, and the `errc` close breaks that.

## Code path

| Go function | State |
|---|---|
| `embed.(*Etcd).Close` (the double `close(e.errc)`) | not translated |
| `EtcdServer.Stop`/`HardStop` it calls | names-only trust boundary (server's `Link.lean` axioms) |

## Proposal: `verify-embed-close`

Specify `embed.(*Etcd).Close` with a persistent handle: `{isEtcd e} e.Close() {True}`, callable
any number of times and from any goroutine. The `closeOnce` owns the shutdown resources (the
`errc` channel's close token included). At the pin the proof fails at `close(e.errc)` on the
second call, because the token is gone. Cost: medium. `embed` would need translating (`Close`,
`stopServers`, the listeners' `Close` as trust boundary, about 100 Go lines), with `EtcdServer.Stop`
and `HardStop` staying axioms. Low priority. The same handle would anchor the server lifecycle
specs that `crash-restart-model` needs.

## Findings

None for `issues/` (`embed` is not translated). It is a probable bug at the pin (`Close` is not
idempotent). An issue file would be reasonable if `embed` is ever translated. No bug in this
repository's specs.

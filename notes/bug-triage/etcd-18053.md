# etcd-io/etcd#18053: etcd watcher doesn't read older events

- URL: https://github.com/etcd-io/etcd/issues/18053 (closed 2024-05-22, the day it was filed, by
  the reporter).
- Affected: reported on v3.5.0; no fix, no PR.

The report: `cli.Watch(ctx, "", clientv3.WithRev(1000))` on a store at revision 75 000 delivers no
event. The maintainer's answer, which the reporter confirmed: without `clientv3.WithPrefix()` the
watch is on the single key `""`, which the reporter never wrote. With the prefix option, the events
arrive.

## Classification

**N** (a misuse of the API: no bug). The decisive fact is that a watch with no range end covers one
key, and the server reads an empty key as the single key `"\x00"`. The v3rpc watch model states this
exactly. `createRangeOk` (`Proof/go_etcd_io/etcd/server/v3/etcdserver/api/v3rpc/InvWatchStream.lean:181-185`)
gives the range a create request registers: the key is `if c.key = [] then [W8 0] else c.key`, and
`r.end? = none` (one key) when `c.rangeEnd = []`. `serverWatchStream.recvLoop` is verified against
it (`Proof/.../v3rpc/serverWatchStream__recvLoop.lean`, a `theorem`, linked at `Link.lean:435`). The
mvcc watch then delivers only events whose key the range covers (`wgCovers` in
`Spec/go_etcd_io/etcd/server/v3/storage/mvcc/rangeEvents.lean`). No events is the specified outcome.

Source of verification states: `verified.txt` was not produced. The states were read from the
`Proof/` files and `Link.lean`.

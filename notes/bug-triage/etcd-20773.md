# etcd-io/etcd#20773: lease comparison in txn bug

- URL: https://github.com/etcd-io/etcd/issues/20773 (closed 2026-10-08; labels `type/bug`,
  `help wanted`, `stage/triaged`)
- Affected: `etcdctl` v3.7.0-alpha.0 and earlier (also #14845, 2022); v3.6 reproduced.
- Fix: PR #21422 (merge `097f74206`, 2026-07-28): `b35f739fa` "fix(txn): parse lease ID as hex in
  comparison" (`etcdctl/ctlv3/command/txn_command.go`) and `3d7833c26` (a more informative
  panic message in `client/v3/compare.go`'s `mustInt64`). Backport to 3.6: PR #22542.

What goes wrong (pre-fix): `etcdctl txn`'s `ParseCompare` passed the comparison's operand, a
`string`, unparsed for the `lease` target: `clientv3.Compare(clientv3.LeaseValue(key), op, val)`.
`Compare` reads a lease operand with `mustInt64orLeaseID`, which panics on anything but a
`LeaseID`, `int` or `int64` (`panic: bad value`). The fix parses the operand as hex
(`strconv.ParseInt(val, 16, 64)`) and passes the `int64`.

## Classification

**F (fixed before the verified code), O-pkg; counterfactual F+ at the `client/v3` boundary.**
The fix `097f74206` (and `b35f739fa`) is an ancestor of the etcd pin `107edf7e4`
(`git merge-base --is-ancestor`: yes). The buggy code is in `etcdctl`, which nothing here
translates (`Code/go_etcd_io/etcd/` has `api`, `cache`, `client`, `pkg`, `server`). But the panic
is in `clientv3.Compare`, which is verified, and its spec has a premise the buggy call breaks: a
proof of the pre-fix `ParseCompare` against `Compare.spec` could not discharge `cmpArgOf .lease v`
for a `string` `v`. So the existing spec would have excluded the bug in any verified caller; it
went through because the caller is not verified.

Source of verification states: `verified.txt` was not produced; states read from `Spec/` and
`Proof/` (`Proof/go_etcd_io/etcd/client/v3/`).

## The counterfactual (step 5)

`Compare.spec` (`Spec/go_etcd_io/etcd/client/v3/Compare.lean:28-33`) has the precondition
`⌜cmpOpOf result = some op ∧ cmpArgOf m.target v x⌝`; its docstring: "anything else panics, which
the caller rules out". `cmpArgOf .lease v x` (`Proof/go_etcd_io/etcd/client/v3/InvCmp.lean:107-112`)
requires `v` to be an `int64`, `int` or `LeaseID` interface value. The pre-fix call passes
`interface.mkOk go.string #val`: no `n` satisfies it, so the `wp_apply Compare.wp_proof` step of a
`ParseCompare` proof fails. **F+**, conditional on the caller being verified. (The model of what
a lease comparison means, `cmpKv`'s `.lease` case, `InvEtcdTxn.lean:110-115`, is unaffected.)

**Still at the pin (code reading, not reproduced; `etcdctl` is not translated, so no `issues/`
file):** `ParseCompare` (`txn_command.go:182-236`) does not validate the operator it scans with
`%s` before calling `Compare`, whose default case is `panic("Unknown result op")`
(`client/v3/compare.go`). `etcdctl txn` with `ver("k") >= "1"` should panic the same way; the
same premise, `cmpOpOf result = some op`, excludes it in a verified caller.

## Proposal: `verify-etcdctl-txn-parse`

Specify and prove `etcdctl`'s txn parsing (`ParseCompare`, `ParseRequestUnion`, `readCompares`,
`readOps`: about 150 Go lines) against the verified `client/v3` builders (`Compare`, `OpGet`,
`OpPut`, `OpDelete`, `With*`): the postcondition "returns an error or a `Cmp` whose model is
`compareM m op x`", which forces `cmpOpOf`/`cmpArgOf` at each call. Needs specs (or axioms) of
`fmt.Sscanf` with `%q`/`%s`, `strings.SplitN`, `strconv.ParseInt`, and translating `etcdctl`'s
`command` package (cobra names-only). Cost: small to medium, mostly the translation and the
standard-library contracts; the proofs are a case split per target.

# etcd-io/etcd#18096: etcd panic: assertion failed: Page expected to be: 36312, but self identifies as 0

- URL: https://github.com/etcd-io/etcd/issues/18096 (closed 2024-07-19, no response from reporter;
  `type/bug`, `area/bbolt`)
- Affected: v3.5.11 (bbolt v1.3.8). The node was powered off and on, and etcd then failed to start:
  `bolt.Open` → `loadFreelist` → `freepages` → `checkBucket` found an all-zero page that a bucket
  referenced. `etcdutl check` passed, and `etcd-dump-db` could not read the file. A later commenter
  hit the same panic in containerd's bbolt after a kernel panic. ahrtr: "Most likely the page wasn't
  successfully synced to disk even the system call returned success."
- Fix: none (the environment's `fdatasync`, by diagnosis).

## Classification

**A-model (crash and disk durability); secondary O-pkg (bbolt's crash-safe commit, the WAL and
bootstrap).** The failure needs a power loss. Nothing here models crashes, and the claim to
check, that a bbolt commit is durable once `Commit` returns, is in bbolt (not translated) and
depends on the file system honoring `fdatasync`. bbolt's `Commit_kv` axiom (`Spec/go_etcd_io/bbolt/
Tx__Commit_kv.lean`) states only the in-memory contract: the contents are committed. The server's
startup path (`OpenBackend`, `newBackend`, bootstrap) is not verified, and `bolt.Open`'s axiom
(`Open_kv.lean`) takes `fileHolds path D` as the caller's assumption. A torn or unsynced page is
exactly a file that holds no `D`.

## Proposal: `fs-crash-model`

A file-system model in which unsynced data can be lost at a crash and page writes can tear. bbolt's
`Commit` writes pages, `fdatasync`s, writes the meta page and `fdatasync`s again. Under that
model `Open` after a crash returns the last committed `D` or the one before. That is
`bbolt-kv-contract` with crash semantics. Cost: large. It needs crash semantics in Perennial's Lean
port first. A file system that acknowledges `fdatasync` without persisting stays outside any proof:
it is the model's assumption, to be stated, and here it is the likely cause.

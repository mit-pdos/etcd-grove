## How to work here (learned this run)

- **`etc/lean-check.py` gave false "0 errors" under load**; `lake build <module>` is the check of
  record. Build only the modules you change (a full build is hours and blocks others).
- The worktree's `.lake/build` was seeded by copy from the main checkout (disk is ~90% full: do not
  make more copies). Perennial's copy had ~17 stale trusted-code modules; `lake build` rebuilt them.
- Several agents shared this worktree, each owning files; commit only your paths (`git add
  <paths>`), never `git add -A`; retry on `index.lock`.
- Go: `GOTOOLCHAIN=go1.27.1`; driver tests take ~3 s per `Main(2000)` run under `-race`; pass
  `-timeout 90m` for 200 runs.
- The user's standing rules (memory): one canonical spec per function; never weaken a reviewed or
  frozen spec without asking; minor spec fixes the spec skill decides are fine to make and report;
  show candidate specs as Lean text when asking; commit and push requested changes.

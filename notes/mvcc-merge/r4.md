## Finding: `LogNoLease` of the KV model is true

The merge dropped strict M1's `hnl : LogNoLease (kvModel γr.kv A')` as false under lease-expiry. It is
not: the server's KV model attaches no lease to a put (`KVModelRestore.kvRaftOf_restorable`,
`SnapRecvOn.kvRaftOfOn_restorable`; `kv_applied_step` states `LogNoLease x.log`), and `lean` itself
relied on it (`leasesKnown_restore` through `logNoLease_restore`). Leases are granted and revoked (the
lessor's records, restored by `Recover`), but no key is attached to one. So `KV.Restore`'s pending
items are none and its `leaseOwn … L ∅` is met at any `L`, in particular `Recover`'s live set `Lr`.

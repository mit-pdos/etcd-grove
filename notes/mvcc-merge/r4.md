## Finding: `LogNoLease` of the KV model is true

The merge dropped strict M1's `hnl : LogNoLease (kvModel γr.kv A')` as false under lease-expiry. It is
not: the server's KV model attaches no lease to a put (`KVModelRestore.kvRaftOf_restorable`: the model
of a plain log from a lease-free start is lease-free; `kv_applied_step` states `LogNoLease x.log`), and
`lean` itself used it (`SnapApplyKVLemmas.leasesKnown_restore` through `logNoLease_restore` of
`restoreLogOk`). Leases are granted and revoked (the lessor's records, restored by `Recover`), but no
key is attached to one. So `KV.Restore`'s pending items are none and its `leaseOwn … L ∅` is met at
any `L`, in particular `Recover`'s live set `Lr`.

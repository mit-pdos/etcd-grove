# Review: S5 Draft traced specs (`TracedHooksDraft.lean`), round 1

Reviewed at commit `2a36dffec3` plus an uncommitted change in the working tree. The change makes
`LineEffect`/`PhaseStep` take a parsed previous line `ln0 : Etcdraft.Line` instead of an event
`e0`. Line numbers below are the working tree's. The file checks
(`etc/lean-check.py -q`: 0 errors).

Judged against `.claude/skills/spec/PRINCIPLES.md`. Most weight went to the hard rules (sound, complete,
one spec per function). These are package-internal specs (the Scope rule), so the API-abstraction
preferences count for little here.

## Context the findings depend on

- **At HEAD every traced instance is vacuous.** `ownRaftPhys` still requires
  `⌜TraceLoggerOk rv.traceLogger'⌝` unconditionally (`InvRaftPhys.lean:1089`;
  `ownRaftPhysC_traceLogger`, `:1838-1841`, hands out a nil logger). `trCap (some _)` and
  `TraceFire (some _)` both carry `r.traceLogger ↦□ tl ∗ ⌜tl ≠ nil⌝`. Persistent points-to
  agreement then gives `ownRaftPhysCV … ∗ trCap (some …) ⊢ False`. Every traced triple here is
  therefore provable at HEAD by contradiction. Q8 (a) changes `Htl` to `TraceLoggerOkS s.tr tl`.
  Until that lands, no traced proof means anything. Say so in the file's header, so that nobody
  "proves" one early.
- The global theorem (lifting a `LineEffect` to `simInv`'s σ) has not been stated yet. Several
  findings below are about what `LineEffect` must carry for that theorem to be true.

## What is good

- **Q8's shape is right.** The mode is part of the state (`s.gh.tr`), there is one statement per
  function, and `trCap none = emp` and `TraceFire none = ⌜TraceLoggerOk⌝ ∗ Q` hold by `rfl`
  (`trCap_none`, `traceFire_none`). For `maybeCommit` the untraced instance really is
  `raft.maybeCommit.spec`, up to `∗ emp`.
- **The TaDa shape.** `TraceFire`'s update is exactly the shape of the logger's contract
  (`isTraceLogger`, `InvTrace.lean:196-201`): the caller supplies the update, and the logger stays
  generic.
- **`NodeEvOf` matches `traceEvent` field by field** (`state_trace.go:166-181`; `hardState()`,
  `raft.go:504-510`):
  - term, vote and commit come from the hard state; `lastIndex()` is `plastIndex`;
  - the role string matches;
  - msg, cc and props are all `none` (`traceNodeEvent` passes nil, nil);
  - the voters are any permutation, weaker than `Slice()`'s sorted order (`quorum/majority.go:109-116`).
    That is a harmless margin.
- **`MsgEvOf` matches `makeTracingMessage`** (`state_trace.go:134-160`) for every non-snapshot type.
- **`sendEvt` and `recvEvt` match Go's switches** (`state_trace.go:295-313`, `324-335`). That
  includes the pre-vote types, which Go does not trace. `MsgSnap` (which Go does trace) is excluded
  by the `tr.isSome → ty ≠ .snap` premise, so `sendEvt .snap = none` is only ever used untraced,
  where it is sound.
- **The hook points are where Go traces them.** `traceSendMessage` runs after the append
  (`raft.go:592-593,598-599`), and the fields `SendEvOf` reads are the same at `s` and
  `sendMsgs s out`. `traceReplicate` runs before the append (`raft.go:849`), with one event per
  normal entry, all at the same `s`. `traceCommit` is deferred (`raft.go:794`), so it sees the
  committed state, as `traceCommit.tracedSpec` says.
- **`AdvancesTo a n` is well-defined.** `advanceCommitIndex` reads only server `i`'s variables and
  config (`Spec.lean:264-277`), so `AdvancesTo` is a fact about `a` alone. It is exactly the
  hypothesis that `simRun_commit` takes (`TraceSimMatch.lean:80-92`).
- **`maybeCommit` traces even when it returns false.** The deferred `Commit` line is logged either
  way. `AdvancesTo` with `max` covers the no-change case (the `false` branch still needs
  `advanceCommitIndex_eq`'s no-change half, as the notes say).
- **`TraceFireN` models the loop faithfully.** It nests one update per normal entry, and
  `clientRequestIfLogged` checks no post-state (`Trace.lean:367-368`). So all n `Replicate` lines,
  logged at the same `logSize`, are each accepted.
- **The previous-line change (`e0` → `ln0`) fixes a HEAD bug.** At HEAD, `∀ e0` included events
  that fail to parse, which made `LineEffect` false and `PhaseStep` unprovable for any non-empty
  `Φ`/`E`. That finding is **stale at the working tree**.

## First tier (wrong or unusable)

**F1. `traceNodeEvent.tracedSpec` is unsound for an out-of-range `evt` (hard rule: sound).**
- *Evidence.* `evt.String()` indexes a 19-element slice (`state_trace.go:53-74`). For
  `uint.nat evt ≥ 19` (a negative `int` included) Go panics on the non-nil path, before the logger
  is called (`:172`). The spec quantifies `∀ evt` (`TracedHooksDraft.lean:249-254`). `NodeEvOf evt`
  is then empty, so `TraceFire (some _) tl ∅ Q` is trivially suppliable, and the triple promises
  `RET #()` where Go panics.
- *Affects.* Only the statement: every caller passes a constant.
- *Fix.* Add the pure premise `⌜uint.nat evt < evtNames.length⌝` to the precondition.

**F2. `traceReceiveMessage.tracedSpec` cannot be applied at most of `raft.Step`'s receipts (hard
rules: complete, one spec per function).**
- *Evidence.* `raft.Step` calls the hook on every message (`raft.go:1112`), including types with
  `mtypeOf = none`:
  - `MsgHup` and `MsgBeat` (`raft.go:873,903`);
  - `MsgUnreachable` and `MsgTransferLeader` (`rawnode.go:530,542`);
  - the storage responses stepped at `Advance`;
  - `MsgTimeoutNow`.
- The traced spec requires `mtypeOf ms.msg.Type' = some ty` (`TracedHooksDraft.lean:307`). The
  existing `traceReceiveMessage.spec` has no such premise, so the untraced instance is not
  `X.spec`.
- *Fix.* Drop the binder `ty` and the premise, and index the gate by
  `(mtypeOf ms.msg.Type').bind recvEvt`: `none` gives `TraceFireOpt … none Q`. Keep the snapshot
  exclusion as `s.gh.tr.isSome → mtypeOf ms.msg.Type' ≠ some .snap`.

**F3. `traceSendMessage.tracedSpec` and `raft.send.tracedSpec` exclude two of `send`'s message
types (hard rules: complete, one spec per function).**
- *Evidence.* `raft.send.spec` admits `MsgTimeoutNow` and `MsgTransferLeader` (both
  `mtypeOf = none`; `SendOk`'s third arm). The traced spec adds `mtypeOf m.Type' = some ty`
  (`TracedHooksDraft.lean:371`, likewise `:295`).
- *Affects.* `sendTimeoutNow` (`raft.go:2059`), the `MsgTransferLeader` forward in `stepFollower`,
  and `send`'s own call of the hook. These callers cannot use the traced spec in either mode, so its
  untraced instance is strictly weaker than `raft.send.spec`.
- *Fix.* As in F2: `match (mtypeOf m.Type').bind sendEvt with | some evt => ∀ mm ∈ out,
  PhaseStep … | none => Φ → Φ'`.

**F4. The phases carry none of the facts that every per-line step needs, so `traceCommit` and
`maybeCommit` cannot be proved and `send`'s `PhaseStep` cannot be discharged (hard rule: complete).**
- *Evidence.* Every step lemma in `TraceSimMatch.lean` takes:
  - `(elements cfg.incoming).Perm C` and `cfg.outgoing = ∅`;
  - `id ∈ C`, and for a message `m.dst ∈ C`;
  - `uint.Z s.term`, `s.logst.committed` and `plastIndex` below `2^63`.
- Examples: `simRun_commit`, `:80-92`; `simRun_msgApp`, `:1072-1086`.
- These facts are what `validatePostStates` (`Trace.lean:338-342`: conf, membership) and `gInt`
  need. `SimIdle` (`TracedHooksDraft.lean:90-92`) does not mention raft's configuration `c` at all;
  it is a separate argument of `ownRaftPhysCV`. `trCap` (`:211-218`) relates nothing to `c` either,
  and `simInv` says nothing of raft's state.
  - **`traceCommit`'s proof**: even inside the AU, with `simInv` open, there is no source for
    `c ≡ C`, so the `Commit` line's conf check cannot be shown.
  - **`PhaseStep`** is pure and quantifies `∀ C`, so it sees only what `Φ C cs P` says. The bounds
    the plan puts in `simInv` are invisible to it.
- *Affects.*
  - `maybeCommit`'s proof (it must build `traceCommit`'s phase);
  - every caller of `send` that must prove `PhaseStep`: `bcastAppend`, `sendHeartbeat`,
    `campaign`, `appendEntry`, the vote handlers.
- *Fix.* Put the facts in the share's phase (or in `trCap`), stated where they are constant:
  - `SimIdle C c s cs P` (or a `trCap` clause, `trCap` taking `c`) with
    `(elements c.incoming).Perm C ∧ c.outgoing = ∅`;
  - `idAbs id ∈ confAbs C`;
  - the spec-side bounds `a.currentTerm < 2^63`, `a.commitIndex < 2^63`, `a.log.length < 2^63`.
    Through `SimServerR` these give raft's bounds; `simInv` keeps them per σ.
  - A message's `dst ∈ C` is then the caller's own fact (from the tracker), inside its proof of
    `PhaseStep`.

**F5. `LineEffect`'s local state validates and acts on the wrong server for lines whose
`from`/`to` is not their `nid`, so the planned global lift is false of `LineEffect` as defined.**
This answers the brief's question whether the local state misrepresents anything an action reads.
- *Evidence.* `locSt` sets every server to `a` (`:151-152`). The message actions are keyed by the
  line's endpoints, not its `nid`:
  - `requestVoteIfLogged`/`appendEntriesIfLogged` check `isMessageEvent … i j` with
    `from == i` (`Trace.lean:296-298`, `352-353`) and validate the post-state of server `from`
    (`:356`);
  - `receive` acts on `m.dest = ln.to` (`Spec.lean:504-507`).
- Locally `from`'s server is `a`, so a line with `from ≠ nid` passes against `a`. `LineEffect`
  then reports `tsF.s.s ln.nid = a'` (unchanged) and attributes the new pending message (source
  `from`) to node `nid`'s `P'`. Globally the action is validated against σ.s from, a different
  server. So "σ' is σ with node `i` replaced by `(a', P')`" does not follow.
- Raft's real events always have `from = nid` (send) and `to = nid` (receive). But `LineEffect`
  does not say so, and the global theorem has to be true for every `LineEffect`.
- *Fix.* Add to `LineEffect`: `ln.ev.msg.isSome → (if isReceiveName ln.ev.name then ln.to else
  ln.from) = ln.nid`. Also add that the other fields of `tsF.s` (`server`, `reconfigCount`) are
  `locSt`'s. `applySimpleConfChange` can bump `reconfigCount` (`Spec.lean:314-316`), and
  `LineEffect` currently drops it.

**F6. `PhaseStep`'s `∀ ln0` cannot be met for `BecomeFollower` lines.**
This answers the brief's question whether quantifying over any previous line is right. For every
line kind except `BecomeFollower` it is, because nothing else reads `ln0`.
- *Evidence.* `skipUnusedLogline` and `stepDownToFollowerIfLogged` read the node's previous line
  (`Trace.lean:502-528`). If `ln0` is a higher-term receive, the line is a skip. Any other `ln0`
  is a `StepDownToFollower`, which returns `none` for a follower (`Spec.lean:333-336`).
- After the receive line's `UpdateTerm` the server is already a follower. A `ln0` that is not that
  receive then gives no successor, so `LineEffect` is false and `PhaseStep` is unprovable for
  `becomeFollower`'s callers (the receive paths of `Step`).
- *Affects.* `becomeFollower.tracedSpec` (not yet written) and every phase-step lemma for
  `BecomeFollower`.
- *Fix.* Make the previous line part of the phase: a handling phase records the receive line; the
  global theorem supplies the node's actual previous line in `L`. `LineEffect` then takes that line,
  not `∀`. Keep `PhaseStep`'s `∀ ln0` only as a shorthand for lines that do not read it, and say so.

## Second tier

**S1. Three styles of gate for one job.**
- *Evidence.* The hooks take a raw update (`TraceFire`), so each caller must build an AU: open
  `simInv`, apply the global lift, `trace_append`. `traceCommit`/`maybeCommit` take
  function-specific phases. `send` takes `PhaseStep` and builds the AU itself.
- *Affects.* Callers of `traceBecome*`, `traceReplicate` and `traceReady` (`becomeX`,
  `appendEntry`, `acceptReady`) would each repeat the AU construction. That is caller burden.
- *Fix.* State the global theorem now as the one Iris law between them:
  `trCap tr r id Φ ∗ ⌜PhaseStep E Φ Φ'⌝ ⊢ TraceFire tr tl E (trCap tr r id Φ')`, with a `TraceFireN`
  form. Then every hook path is one `wp_apply`, and `traceCommit` is an instance of it.

**S2. `PhaseStep`'s `∃ a` is the wrong polarity for its consumer** ("a bridge stated from its
consumer's goal").
- *Evidence.* The global theorem has σ.s i, with `toC σ.server (σ.s i) = cs`, but `PhaseStep`
  gives an effect from some `a` with that `toC`. Bridging needs a congruence lemma: `LineEffect`
  is invariant under `toC`-equality. That is true only because the actions read `matchIndex` on
  the servers alone.
- The callers' proofs are lemmas over any `a` anyway.
- *Fix.* `∀ a, toC (confAbs C) a = cs → ∃ a' P', LineEffect … ∧ Φ' …`.

**S3. Messages and phantoms.**
- `PhaseStep` fixes `M = M' = []`, so it cannot express a `Ready` line, which moves `P` into
  `messages`. Its docstring should say "lines that touch neither bag but by a send".
- `Ready(i)` also moves node `i`'s phantoms (`pendingFrom i`, `Spec.lean:323-327`). These are in
  `simInv`'s `phP`, not in `P`, so the global lift must move them to `phM` itself.
- A receive of a lower-term request puts its phantom reply into the local `P'`. No `Φ'` of the
  `SimIdle` form (`P = pendAbs outbox`) can absorb it. The receive phase must split `P'` into the
  outbox part and the phantom part, so `LineEffect` should return the phantom separately.

**S4. `NextChain` drops `stepLine`'s fuel** (`lineFuel`, `Trace.lean:591-592`; the plan's Q7).
The global lift must show the chain's length is at most `lineFuel` of the global state. For
non-receive lines the length is 1. For an append receive it is 1 plus the truncations; say so in the
docstring.

**S5. `traceNodeEvent` needs `ownRaftPhysCV` whole, which its traced callers do not all have.**
- *Evidence.* `traceInitState` in `newRaft` calls it on a struct literal. The notes list this site
  (and `switchToConfig`) as needing lent fields.
- *Affects.* Untraced, the early nil return hides the problem. In a traced cluster `newRaft`'s
  path has no `ownRaftPhysCV`.
- *Fix.* Before the traced spec replaces `traceNodeEvent.spec`, either take the read fields as
  parameters (term, vote, commit, lastIndex, voters, role) or give `traceInitState` its own route
  through `traceEvent`. In either case, check every caller against "one spec per function".
  - Related: `send`'s current proof calls the hook with the queue accessor's wand `Hback` still
    open (`raft__send.lean:197-212`). The traced proof must close `Hback` first. That is feasible,
    since the append is already stored.

**S6. Unneeded resources in `TraceFireOpt … none`** ("no unneeded premise").
- *Evidence.* For an untraced type, Go returns after the nil check and the switch, and never calls
  the logger. Both modes need only `Q` (and the logger field, already in the precondition), yet
  `TraceFireOpt` requires `⌜TraceLoggerOk⌝` untraced and `traceDir ∗ isTraceLogger ∗ ⌜tl ≠ nil⌝`
  traced (`:227-229`).
- *Affects.* `TraceFireN`'s base case inherits the same extras.
- *Fix.* `TraceFireOpt … none Q := Q`.

**S7. The "untraced instance is `X.spec`" claim is inexact.**
- *Evidence.* The header says so (`:17-18`), but for the hooks the traced precondition adds
  `ownRaftPhysCV` (and `msgOwn` for the message hooks). So `X.spec` implies the untraced instance
  (by framing), not the converse.
- *Fix.* Say it in the docstring, and check it against each caller (it matters for S5).

**S8. `SendEvOf` is reused for the receive event and leaves the properties unconstrained.**
- *Evidence.* `traceReceiveMessage` passes `nil` properties (`state_trace.go:338`); `SendEvOf`
  leaves them free. This is harmless, because the checker reads `prop` only for `ChangeConf` lines
  (`Trace.lean:162-167`, `179-181`).
- *Fix.* Rename it `MsgLineOf` (it is no longer send-specific). State the margin: Go writes
  `match`/`next` only for a sent `MsgApp`, and no properties on a receive.

**S9. Shape.**
- The pure premises of `raft.send.tracedSpec` and the message hooks are Lean implications before
  the triple. The preference is `⌜…⌝` conjuncts inside the precondition; convert them when the
  statement is next changed.
- In traced mode `maybeSendSnapshot` must discharge `ty ≠ .snap` before the triple. It can only do
  so by opening `trCap` to reach `SimIdle`'s `LogShapeOk`, which is awkward. Inside the
  precondition this would be `⌜s.gh.tr.isSome → …⌝`, discharged after `trCap` is destructured.

## Ranking by need of revision

1. `raft.send.tracedSpec` with `PhaseStep`/`LineEffect`: F3, F4, F5, F6, S2, S3.
2. `traceReceiveMessage.tracedSpec`: F2 (unusable at most of `Step`'s receipts).
3. `traceCommit.tracedSpec` and `raft.maybeCommit.tracedSpec`: F4 (unprovable without `c ≡ C`).
   The rest of each is good.
4. `traceNodeEvent.tracedSpec`: F1 (unsound, trivial fix) and S5.
5. `traceSendMessage.tracedSpec`: F3 (and S6, S8).
6. `traceReplicate.tracedSpec`: S6 only.
7. `traceBecomeFollower/Candidate/Leader.tracedSpec` and `traceReady.tracedSpec`: correct as
   hooks. Their callers' burdens are S1, and F6 for `becomeFollower`.

No bug in the Go code was found; nothing for `issues/`. The repository was not modified.

## First tier

### F1. Every send and receive line's premise is false: `MsgEvOf` leaves `rejectHint` free, and `NumsBelow` bounds it

**Evidence.**
- `TraceEv.NumsBelow` requires `uint.nat m.rejectHint < K` of the event's message
  (`TraceSim.lean:181`). `mainPure` needs it: `Event.Bounded` has `numOk m.rejectHint`
  (`Rep.lean:201`).
- `MsgEvOf` (`TracedCap.lean:118-121`) constrains `typ, term, frm, to, entries, logTerm, index,
  commit, reject`, and not `rejectHint`.
- So `SendEvOf evt id s c m` (`:125-133`) holds of the logged event with its `rejectHint` replaced by
  any `w64`, including `2^64 - 1`.
- Hence `∀ e, SendEvOf evt id s c mm e → TraceEv.Ok K e` is false for every `K ≤ 2^61` whenever
  `SendEvOf` is inhabited, which is whenever the hook logs.

**Callers affected.**
- `raft.send.tracedSpec`'s traced premise (`TracedHooksDraft.lean:250-252`) cannot be discharged
  for any message of a traced type: the traced `send` is unusable.
- `trCap_fire`, `trCap_fire_any` and `trCap_fire_booted` instantiated with `sendGate`'s predicate are
  equally unusable.
- So is `trCap_fire_recv` with `recvGate`'s (`:160-163`, also `SendEvOf`). That is every receive line
  `raft.Step` will log.

The amendment adds an `Ok` lemma only for node events (`nodeEvOf_ok`, `:316`). There is no
`sendEvOf_ok`, which is why nothing caught this.

**Go.** `makeTracingMessage` writes `RejectHint: m.GetRejectHint()` (`state_trace.go:158`).
`traceMsgOf` records it (`TracedMsg.lean:50, 54`), and `absMsg` carries it as `Msg.rejecthint`
(`Defs.lean:189`). The value is bounded in Go: a rejecting `MsgAppResp`'s hint is
`min(m.Index, lastIndex)`, and other messages have 0.

**Repair.**
- Add `tm.rejectHint = m.rejecthint` to `MsgEvOf` (a Draft vocabulary change, part of this
  re-freeze). `msgEvOf_traceMsgOf` re-proves by the same `rfl`s.
- Add `sendEvOf_ok`, stated from `s.term`, `s.logst.committed`, `plastIndex`, and the message's
  `term`, `index`, `logterm`, `commit`, `rejecthint` and `entries.length` below `K`.
- Write the traced `send` premise for one real message, e.g. a rejecting `MsgAppResp`, before
  re-freezing.

### F2. `ConfsWithin 3` has no source a caller holds; the law can derive it

**Evidence.**
- `nodeEvOf_ok` and `nodeEvOf_okBoot` take `(elements c.incoming).length ≤ 3` (`TracedCap.lean:319,
  337`), and their docstring says it is "the caller's, from ... the cluster".
- I found no such fact in the capability, in `simInv` or in raft's ghost. A grep for `length ≤ 3` in
  raft's proofs finds only these two lemmas and two unrelated loop invariants.
- `trCapB` holds `(elements c.incoming).Perm C` and `tn.voters = C` (`:717`), but nothing bounds
  `C.length`. The three-voter premise is planned on `cluster_alloc`
  (`notes/trace-validation-sim.md:688-690`) but is not stored anywhere a hook's caller can read it.
  This is marked uncertain only in that a later allocation could store it.

**Callers affected.** Every traced call site, raft's handlers included: `raft.Step`'s, `Ready`'s,
`maybeCommit`'s.

**Mechanism vs. need.** "3" is the workload's number, written into raft's laws and its invariant
(`SimEvents`, `TraceSim.lean:275`). `mainPure` takes any `n < numBound` (`MainPure.lean:323`).

**Repair.** Take the configuration bound out of the caller's premise.
- `TraceEv.Ok` drops `ConfsWithin`.
- Each law derives `e.conf.1.length = C.length` from `trCapB`'s `Perm C`, through the event
  predicates' `conf` conjunct.
- `SimEvents` keeps `ConfsWithin C.length` (`SimEvents C L`).
- `MainSim` takes `(C.length : Int) < numBound`, which `Main` knows of its peers, or `simInv` holds
  `C.length ≤ 3` from the allocation.
- The one list the law cannot see is an `ApplyConfChange`'s `propCC.newconf` (`CCEvOf`'s `cn`). Keep
  only that as a premise, `(elements cn.incoming).length ≤ C.length`, in `OkBoot`; in the workload
  the bootstrap's new configurations are prefixes of `C`.

### F3. The `K ≤ 2^61` premise rests on a receipt bound nothing states

**Evidence.**
- The docstrings say `K` comes "from the time receipts" (`TracedHooksDraft.lean:94`;
  `TracedCap.lean:313-315`).
- The receipts give a term at most `M ≤ k + 1` (`InvNodeChan.lean:192-194`) and an index at most
  `receiptBound + |reBoot|` (`Ghost.lean:2487`). Today's only bound is
  `receiptBound GF ≤ 2^64 - 2` (`InvNodeChan.lean:194`, `InvApi.lean:542`).
- For `uint.nat s.term < 2^61` and `plastIndex < 2^61`, a traced call site needs about
  `receiptBound GF + |C| < 2^61`. No statement, premise or note in the amendment records this. The
  sim notes still say `2^62 - 2` (`notes/trace-validation-sim.md:681`), which was correct before Q12
  moved `numBound` to `2^61`.

**Callers affected.**
- Every traced call site, so the premise cannot be discharged as the docstrings say.
- `MainSim`'s header lists what stays outside the simulation (bootstrap facts, event count), but not
  this.

**Repair.**
- State it where the bound is owned: the traced cluster's allocation premise (or the traced
  adequacy theorem) fixes `receiptBound GF + 3 < 2^61`, gated by `tr.isSome`.
- Give the handlers a law from `termLB`/`isEntryR` to `uint.nat _ < traceNumBound`.
- Name it in `MainSim.lean`'s header as owed, and correct the sim notes' `2^62 - 2`.

### F4 (uncertain). A receive line's message fields have no named source at the receiver

**Evidence.**
- `trCap_fire_recv`'s premise asks `NumsBelow K` of the received message's fields (`term`,
  `entries`, `logTerm`, `index`, `commit`, `rejectHint`).
- `raft.Step`'s handler has `termLB` of the message's term (`InvNodeChan.lean:549`) and
  `isMessage γ.raft (absMsg …)` (`:535`).
- I did not check whether `isMessage` gives receipt-backed bounds for a `MsgAppResp`'s index and
  hint, or a heartbeat's commit. Nothing in the amendment says how the receiver discharges them.
- Every such message entered the bag from a send line whose event was `Ok`. So the simulation could
  carry the bound itself: `simInv` keeps "every bag message's numbers are below the bound", and the
  receive line's event matches its bag message. That works for the fields `recvPred` ties to the
  message; `rejectHint` is not in `Etcdraft.Msg`, so it would still be the caller's.

**Repair.** Before re-freezing, either:
- name the receiver's source (a law of `isMessage`, with the field list); or
- split `NumsBelow` into the event's own numbers (the caller's) and its message's (kept by `simInv`
  for the fields the bag fixes, the caller's for the rest).

## Second tier

- **S1. `K` is a dead parameter, and `2^61` a literal.**
  - In every statement `K` appears only in `K ≤ 2^61 → ∀ e, E e → Ok K e`, chosen by the caller per
    call. Because `NumsBelow` is monotone (`numsBelow_mono`), this is equivalent to
    `∀ e, E e → Ok (2^61) e`.
  - Seven laws, three Draft statements, the three derived `traced` theorems and both hook gates gain
    a binder and a conjunct for nothing.
  - Repair: one named constant, `traceNumBound : Nat := 2 ^ 61` (`@[word_unfold]`, with a lemma
    `(traceNumBound : Int) = Etcdraft.numBound`). Then `TraceEv.Ok e` without `K`, the premise
    `∀ e, E e → e.Ok`, and `SimEvents`'s `NumsBelow traceNumBound`.
  - Likewise use `Etcdraft.bootLogBound` for the literal `2 ^ 40` in `EvBootLogOk`
    (`TraceSim.lean:243`), which its docstring names.
- **S2. `OkBoot`'s `logSize ≤ 3` is the supplier's mechanism** (`TraceSim.lean:198`). The receiver
  (`BootLogsOk`) needs `< bootLogBound`, and `simEvents_snoc_boot` only uses it for that
  (`by omega`). Repair: state `uint.nat e.logSize < Etcdraft.bootLogBound`. The bootstrap call sites
  prove it from `|peers|`, so the workload's 3 leaves raft's statements (F2 does the same for the
  configurations).
- **S3. The interfaces were not regenerated** (repository policy; blocks landing, CI fails).
  - `TraceSim.lean` gained a public section, but `interface/Proof/go_etcd_io/raft/v3/TraceSim.txt`
    has none of it (no `InScope`/`SimEvents`; last changed in `971b78a5a6`).
  - The four modules newly listed in `etc/api/raft.txt:151-154` have no interface files.
  - Run `etc/gen-interface.py etc/api/raft.txt` after `lake build`, then `--check --layout` and
    `etc/api-check.py`.
- **S4. The API widening exposes internals.**
  - `TraceSimGhost`, `TraceSimBag` and `TraceSimLemmas` become importable so that `MainSim` can
    state `simInv_end`. That makes `simInv`'s body (ghost names, bags, `Bt`) and two lemma files
    raft's API.
  - `MainSim` needs only `simInv` (opaque), `traceAuth`, `simInv_end`/`simInv_main` and `SimEvents`.
  - Repair, per "Package APIs": a sealed API module (`TraceSimApi`) that imports them non-publicly,
    marks `simInv` `@[no_expose]` for clients and exports `simInv_end`. List only that module.
- **S5. `simInv_main`'s conclusion re-quantifies the trace it was given** (`MainSim.lean:60-68`). The
  premise fixes `t` with `newTrace … = .ok t`, and the conclusion says `∃ t, newTrace … = .ok t ∧ …`
  again; `mainPure_of_sim` has the same shape (`:42-48`). Repair: conclude of the given `t`
  (`t.CheckTraceOk true ∧ (∀ res, CheckTraceRel t true res → res = {ok := true}) ∧ TraceAccepts …`,
  plus the two `NewTrace` premises), or take the bootstrap facts as `∃ t, …` and keep the `∃` once.
- **S6. The amendment departs from plan Q13 without recording it.**
  - Plan Q13 (a) (`notes/trace-validation-plan.md:784-795`) chose "a ghost event counter the laws
    increment" and `logSize ≤ 3` in `Ok`.
  - The amendment drops the counter: the count goes through the recorder (`MainSim.lean:13-15`).
    Plausible, if the recorder's `TraceEvent` spec takes a receipt per event, which no statement
    says yet.
  - It also moves `logSize ≤ 3` into `OkBoot`.
  - No notes changed in the commit. Record both in the Q13 entry and in `notes/STATUS.md`, and name

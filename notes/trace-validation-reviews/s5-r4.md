## First tier (wrong or unusable for the closed theorem)

### D1. `quorumLog_appendEntriesAlreadyDone`'s `hcfg` has no source in a receipt's `FxPresR`

**Principle:** "every premise has a source the client sees".

**Evidence.**
- `quorumLog_commitTo` and `quorumLog_appendEntriesAlreadyDone` take
  `hcfg : σ.getConfig i = σ.getConfig m.source` (`TraceSimSpecInv.lean:1862`, `:1926`). The
  docstring's source is "`SimServerR`: every server's is the voters' `confAbs C`" (`:1920-1921`).
- But `SimServerR` is only the receiving node's. It comes through the caller's phase `Φ` and
  `σ.s (idAbs id) = a`.
- `FxPresR` (`TracedHooksDraft.lean:566-578`) is proved for every `σ` with `simFx γ C σ`,
  `σ.server = confAbs C` and the receiver's server. Nothing in that list mentions the sender's
  configuration:
  - `simFx` (`:383-385`) has `allFacts`, `msgFacts`, `SpecInv`, `QuorumLogF` and `MsgsUniq`;
  - `srvFacts` (`TraceSimFacts.lean:285-299`) has no `config`;
  - none of `SpecInv`'s ten clauses (`TraceSimSpecInv.lean:154-156`) has one.
- `simInv`'s shares (`A !! i = toC …`, `TraceSimGhost.lean:217`) would give it, but they are not
  among `FxPresR`'s hypotheses.

So for a receiver whose commit index rises, `QuorumLogF` at the new state is unprovable.

The premise cannot just be dropped. `quorumLog_commitTo` needs the sender's quorum condition to be
over the receiver's configuration.

**Callers affected.** Every follower receipt that raises its commit index, through `FxPresR`:
- `lineEffect_heartbeatRecv`, `recvAt_heartbeat`: the specification's heartbeat `CommitTo`
  (`Spec.lean:419`), on every heartbeat after the leader's commit index moved;
- `lineEffect_appRecv`, `lineEffect_appRecvU`: accepted appends with `m.commit > committed`.

**Fix.** Add a pure clause to `SpecInv`:

    CfgFixed σ : ∀ j ∈ σ.server, (σ.s j).config = { incoming := σ.server, outgoing := [], learners := [] }

- It holds at `simInit` (`TraceSimGhost.lean:158`).
- No action in scope changes `config`. `ApplySimpleConfChange` under `AccIdle` reapplies the same
  configuration (`applySimpleConfChange_idle`); `reconfigure` is out of scope (P3).
- `hcfg` then follows from `σ.server = confAbs C` for both servers.

**Done (2026-11-09, branch `trace-check-d1`).** `CfgFixed` is `SpecInv`'s eleventh clause
(`TraceSimSpecInv.lean`), as above. The congruence and one-server-update lemmas take the configuration
kept (`hG`); `specInv_init` is now at `init server server`; `cfgFixed_simInit` (`TracedHooksDraft.lean`)
is `rfl`. `specInv_applySimpleConfChange` is the `AccIdle` successor (`accSrv`'s match indices; only
`DurS` reads them). `quorumLog_commitTo` takes `CfgFixed σ` in place of `hcfg`;
`quorumLog_appendEntriesAlreadyDone` has no configuration premise, and neither has
`specInv_advanceCommitIndex` (round 2's A8 premise, now derived).

Alternatively, add the same clause to `simFx`. In either case, correct `:1920-1921`.

### D2. `BecomeLeader`'s four hypotheses have no stated derivation, and `hcw` cannot come from the present lemmas

**Principle:** "every premise has a source the client sees" (round 3's B6, for another line).

**Evidence.**
- `specInv_becomeLeader` takes `hfreshLog`, `hfreshMsg`, `hfreshReq` and `hcw`
  (`TraceSimSpecInv.lean:1310-1314`). The header lists them as "what the simulation supplies"
  (`:28-30`).
- Unlike `LeaderComplete` for `UpdateTerm`/`Timeout`, no lemma derives them from `simFx` and the
  node's ghost. `grep` finds no use outside `specInv_becomeLeader`.
- `hfreshReq` follows from `CandS`' first clause, `msgFacts`' `isLeader` and `isLeader_unique`.
  That route is plausible but not written down.
- `hcw` ("every server of term `T` has its commit index within `i`'s log") cannot come from the
  stated lemmas:
  - In the pre-state, `i` is a candidate, so `CommitInDurable`/`CommitWithinLeader` say nothing
    about it.
  - `allFacts_leaderCompleteness` quantifies over `σ.currentLeaders`, which `i` is not.
  - Applied to the post-state, it needs `CommitWithinLeader` of the post-state: the conclusion.
  - The underlying `commit_in_leader` takes `hlen : tm = T → c ≤ |G'|` (`TraceSimFacts.lean:333`),
    keyed on the server's term `tm`, not on the certificate's.
  - For a server of term `T`, `tm = T` always holds, so the lemma demands `hcw` itself. Its proof
    uses `hlen` only when the certificate's term `t` is `T` (`:358-360`). For `t < T` it goes
    through `lc_core` without it.
- **Uncertain:** whether raft's ghost at `traceBecomeLeader` (`raft.go:978`, after `reset` and the
  state change, before the empty entry's append) excludes a `cq γ T n G` reaching past `i`'s
  campaign log. It should: no entry of `T` is recorded yet. But I found no lemma saying so.

**Caller affected.** `becomeLeader`'s traced statement: the `BecomeLeader` line's `FxPres`, in every
election.

**Fix.**
- Restate `commit_in_leader`'s `hlen` as keyed on the certificate's term (`∀ t n G, cq γ t n G → t =
  T → c ≤ |G'|`), or add a variant.
- Prove one lemma for the line, from what `becomeLeader` holds at the hook:
  `isLeader γ i T`, `isCamp γ i T F0`, `leadFull γ T F0`, the term-log authority and `votesTbl`, with
  `allFacts`, `msgFacts` and `SpecInv σ`. Its conclusion is the four hypotheses.
- Until then, name in `specInv_becomeLeader`'s docstring the raft fact each hypothesis comes from.

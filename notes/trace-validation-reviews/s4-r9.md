## First tier

### F1. The gated `storBnd` must leave `c = 0` free, or the harness's storage cannot be built

**The claim.**
- sim.md:544-545: "`storBnd`'s permit conjunct reads `⌜γ.reTrace = none⌝ ∨ permit`".
- P2 (sim.md:389-392): "a logger-gated conjunct of the generic storage bound `storBnd`".
- Neither exempts `c = 0`.

**The evidence.**
- The current `storBnd γ K c := ∃ k, ⌜c ≤ k⌝ ∗ nodeAppliedLb γ K k` (`InvNodeRule.txt:24-25`) holds at
  `c = 0` from `nodeAppliedLb_zero`.
- `MemoryStorage`'s invariant needs `J.B 0`: `memStorInvP ms γs J := memStorLock ms γs ∗ J.B 0 ∗ inv …`
  (`interface/Proof/go_etcd_io/raft/v3/InvMemstorage.txt:325`). Every client proves it at creation
  (`kvJ_B0`, `KVStorageInstance.lean:277`, used at `:453`).
- `isStorageP`'s bound must also cover `storCompacted st 0`, which is free
  (`storCompacted_zero`, `InvStorage.lean:114`; `FirstIndex` produces `storCompacted st (fi−1)`, `:273`).
- With the conjunct as written, in a traced cluster `J.B 0 = storBnd γ K 0` demands the permit,
  which the allocation never hands out. So the harness can construct neither its `MemoryStorage`
  nor `isStorage`.
- Round 7's S1 asked for "for every `c > 0`" (`s4-r7.md:139`). Round 8 cited it as present
  (`s4-r8.md`, "The permit in `storBnd`"). It is in no revision:
  `git show <rev>:notes/trace-validation-sim.md | grep storBnd` for `7567d95ff2`, `99486dd27e`,
  `965c97cb79` shows only the two lines quoted above.
- Raft's own use is unaffected: every `ErrCompacted` branch gives `c ≥ 1` (`InvStorage.lean:253`,
  `:265`).

**Who it affects.** Layer D (the harness's storage, so `Main`). Q6 (6)/(7) as worded.

**Repair.** `storBnd γ K c := (∃ k, ⌜c ≤ k⌝ ∗ nodeAppliedLb γ K k) ∗ (⌜c = 0 ∨ γ.raft.reTrace = none⌝ ∨ permit)`.
State the same in P2 and Q6.

### F2. The gate is half-moved: the constructors are not tied to `reTrace`, and the other gates still key on the logger

**The claim.**
- Revision 9's header: "the gate is a cluster field `reTrace`".
- The text still gates on the per-node logger:
  - P2 "with a logger" (sim.md:389-390);
  - the budget "each `Node.Propose` with a non-nil logger" (:408);
  - P7 "not called with a logger" (:419);
  - the tokens "gated on a non-nil logger" (:515-516);
  - "Layer B's other premises enter through the API … gated on a non-nil logger" (:537), with
    `RestartNode`/`ProposeConfChange` "with a logger" (:540-541);
  - the non-`dup` allocation "with a logger" (:555);
  - plan Q6's header: "gated on a non-nil trace logger".
- The constructors' premise is `isTraceLogger γt cv.TraceLogger'` with "`γt` a new binder;
  `isTraceLogger_nil` for a nil logger, any `γt`" (:476-479). It is not tied to `γ.reTrace`.
- Round 8's S1 asked for both "With a logger, `StartNode` requires `γ.reTrace = some γt`" and "the
  other gates key on the same field". Neither is in the text.

**The evidence.** Two configurations that the contracts as written admit:

1. **A nil-logger node in a traced cluster.** Nothing forbids it: `simNode` is "owned only with a
   logger" (:478), and `isTraceLogger_nil` takes any `γt`.
   - Its `Propose` takes no credit (:408), but its `MsgProp` is forwarded
     (`DisableProposalForwarding = false` is a `StartNode` premise, `StartNode.txt`).
   - A traced leader appends it (`stepLeader`'s `MsgProp` → `appendEntry`, `raft.go:830-864`).
   - The leader's invariant "entries appended this term ≤ credits spent + 1 < `MaxInflightMsgs`"
     (P5, :409) then has no credit to consume. The traced leader's proof is stuck.
   - `RestartNode` with a nil logger of a node first started traced does the same, and evades P1's
     gate.
2. **A logger node in an untraced cluster** (`γ.reTrace = none`).
   - The client may compact (the `⌜reTrace = none⌝` disjunct), so `maybeSendSnapshot` is live.
   - The node's `traceSendMessage` then fires on a `MsgSnap` (`state_trace.go:303-304`), and
     `simInv` cannot step it.
   - `simNode γt i` (:207) is not indexed by `γ`, so `StartNode` cannot even relate `γt`'s `simInv`
     to the node's raft ghost.

In both cases a contract of raft's (the leader's `Step`, the send hook) is unprovable as stated.
Soundness of the exported law is not at risk, because its premise asks for every peer's bootstrap
lines. The contract is.

**Who it affects.**
- Raft's increment-2 proofs: `Propose`/`appendEntry`'s budget and the send hook.
- Q6 as put to the user, whose header and item (7) disagree.

**Repair.** One clause on each constructor, then one word everywhere:
- `StartNode` takes `cv.TraceLogger' ≠ nil ↔ γ.raft.reTrace ≠ none`. With a logger it takes
  `γ.raft.reTrace = some γt` and `isTraceLogger γt`.
- `RestartNode` takes `γ.raft.reTrace = none`.
- Then "with a logger" and "in a traced cluster" coincide on every running node, so P2, P5, P7,
  :515-516, :537-541, :555 and Q6's header can say "in a traced cluster".
- Alternatively, index `simNode`/`simInv` by `γ`. The biconditional is still needed for the budget.

## Second tier

### S1. The allocation law is circular as written; give the order

**The claim** (sim.md:470-474): "the allocation law (it takes raft's `γ`, … `γ.reTrace = some γt`):
`γt` with `traceAuth`, `traceFrag`, `simInv` …".

**The evidence.**
- `reTrace` is "pure data, fixed at allocation", like `dup` and `snapLoc`.
- `cluster_alloc` takes those as inputs: `(dup : Bool) (sl : w64 → Option GName)`, post
  `⌜γ.dup = dup ∧ γ.snapLoc = sl ∧ …⌝` (`interface/Proof/go_etcd_io/raft/v3/InvNodeRule.txt:50-58`).
- So `γt` must exist before `γ`. A law that both requires `γ.reTrace = some γt` and allocates `γt`
  cannot be proved: Iris allocates only fresh names.

**Repair.** Three steps:
1. The trace allocation makes `γt` with what does not need `γ`: `traceAuth`/`traceFrag` at `[]`,
   the cursors, the budget, the `simNode`s at `σ_init`. `σ_init` depends only on the peers.
2. `cluster_alloc` gains `(tr : Option GName)` with `γ.reTrace = tr` in its post (and `dup := false`).
3. A law establishes `simInv γt γ` from step 1's authorities and step 2's `γ`. The `|peers| ≤ 3`
   premise goes on step 1 or step 3.

### S2. "Untraced clients need no witness" is slightly too strong: they need one pure fact

**The evidence.**
- `kvJ_bnd` is `memBnd (kvJ γ K) c ⊢ storBnd γ K c` by `rfl` for every `γ`
  (`KVStorageInstance.lean:273-275`; `KvrStorageApi.lean:275-276`; `KdStorageApi.lean:148-149`).
- The server builds `storBnd` from `nodeAppliedLb` (`EtcdServer__compactRaftLog.lean:119,130`).
- After F1's conjunct, each of these needs `⌜γ.raft.reTrace = none⌝` (or `c = 0`) in hand. That is a
  hypothesis threaded from `cluster_alloc`'s post (S1 step 2) to the lemma and its users. It is not
  a resource, but it is not nothing.

**Repair.**
- Q6's "the existing clients (nil logger) carry nothing new" becomes "carry the pure fact
  `γ.raft.reTrace = none` from `cluster_alloc`".
- Alternatively, raft exports `storBnd_untraced : ⌜γ.raft.reTrace = none⌝ → (∃ k, …) ⊢ storBnd γ K c`.

### S3. The gate re-creates raft's no-snapshot mode (`reNoSnap`); say whether it revives or retires it, and how `Ready`'s empty snapshot is proved

**The evidence.**
- Raft had exactly this mode: `RaftNames.reNoSnap` (`Protocol/Ghost.lean:344-352`: "no node sends a
  `MsgSnap`"). Its storage cap was `NsCap = storCap st 1`.
- It was dropped at U8 v2 (2026-10-29) because "the new storage contract (`isStorageP`) bounds
  compaction only by what raft applied" (`InvRaftPhys.lean:845-851`, `StepGhostMode.lean:411-431`,
  `ApiVocab.lean:170-171`).
- Its plumbing is still there:
  - the outbox fact `γ.reNoSnap = true → ∀ x ∈ o, x.ty ≠ .snap` (`LemmasReadyR.lean:236,260,297`,
    `InvRawnodeReady.lean:552,647,662,1341`, `InvRawnode.lean:2884`);
  - `snapshotCert`'s `⌜γ.raft.reNoSnap = false⌝` (`InvApi.lean:1497`). `snapshotCert` is sealed
    (`InvNode.txt:261`) and sits inside `readySnap`'s `some` branch;
  - `StaticNames`/`StartNode` fix `reNoSnap = false` (`InvApi.lean:894`, `StartNode.lean:411`).
- F1's permit in `storBnd` is the new-contract replacement for the dropped cap. With
  `reNoSnap := reTrace.isSome`, F1's `Ready` law comes almost for free: `readySnap … (some l)` holds
  `snapshotCert`, hence `⌜reNoSnap = false⌝`, a contradiction. It would be exported as a law next to
  `readySnap_bootLen` (`InvNode.txt:63-66`) rather than as a change to `Ready`'s spec.
- The note says neither this nor which route raft takes to "no `MsgSnap` ever stepped". The
  candidates are round 8's token route (no `MsgSnap` in `simInv`'s bag, which opens `simInv` at
  every receipt) and the outbox/`isMessage` route above (raft-local, no `simInv`).

**Repair.** One paragraph in P2:
- Decide: revive `reNoSnap` (set from `reTrace`, with the permit as its cap), or delete its remnants
  and build the new mode.
- Name the route, and state the empty-snapshot result as a law on `readySnap`.

## Third tier

- **T1.** "(with a single voter, the bootstrap's commit)" (sim.md:351-352) rests on round 8's
  "`campaign` wins before any `Ready`". That is not v3.7.
  - `campaign` sends the self vote as a `MsgVoteResp` to itself, through `msgsAfterAppend`
    (`raft.go:1070-1078`), stepped at `Advance`.
  - Every win, a single voter's included, is therefore after the campaign's `Ready`. Drop the
    parenthetical; the general argument covers it.
- **T2.**
  - Wording: "the leader's own entry `E_T − 1`" (sim.md:341) means its own *match*.
  - State the self clause in full, in both places:
    "`matchIndex[l][l]` is `E_T − 1` until `l` receives its first self-acknowledgement of term `T`
    (at `Advance`), after which it is `≥ E_T` and that response is in `l`'s set".
  - "Until its self-acknowledgement" is ambiguous between the `AppendEntriesToSelf` line (the
    send) and the receipt.
- **T3.** The hand-off clause (sim.md:525-527).
  - "At most one per link, set at the hand-off" needs the clause written inside the send's atomic
    update. That is available: `stepWithWaitOption`'s proof sends with `handshake_send_au`
    (`node__stepWithWaitOption.lean:83`). It also needs `simInv` to know the run loop consumed the
    previous one.
  - Simpler: a per-link *set* of pending positions, each `> frontier`. It is stable, because the
    frontier advances only to a stepped position, below every later one, and it needs no
    "at most one".
  - Also say what happens at the run loop's filter (`node.go:394-397`: a response from a `From`
    without progress is dropped without `raft.Step`). It is dead in a traced cluster, since
    `Bootstrap` applies every peer (`bootstrap.go:79`) and every bag message is from a peer, but the
    clause's "consumed at `raft.Step`" should say so.
- **T4.** "Proposals' size needs no limit: `MaxSizePerMsg` is unlimited and the harness's entries
  are small" (sim.md:548-549) gives the wrong limit.
  - `appendEntry`'s drop is `increaseUncommittedSize` (`raft.go:2101`), bounded by
    `MaxUncommittedEntriesSize`.
  - The harness leaves that at 0, which raft turns into `noLimit` (`raft.go:313-315`).
  - A refused proposal also logs nothing, so the simulation needs no premise either way.
- **T5.** Round 8 F1's third bullet was not done. P2 does not say that `handleReady`'s
  `CreateSnapshot`/`Compact` branch is dead by `DefaultCConfig`'s `SnapshotEvery = 0`
  (`concurrent.go:104-107`, `:330-336`), a layer-D fact. Nor does P2 mention the empty-snapshot law
  (F1 of round 8, S3 here).
- **T6.** `storBnd` takes `γ : Cluster` (`InvNodeRule.txt:24`), so the conjunct reads
  `γ.raft.reTrace`. Say "a `RaftNames` field, read through `Cluster.raft`", as `dup` is
  `Cluster.dup` over `RaftNames.dup`.

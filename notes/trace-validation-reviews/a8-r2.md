## Checks against the checker and the Go code

I re-did each of these myself, not taking round 1's word for them.

- **`newTraceWith` at a non-server** (`etcdraft/Tla/Trace.lean:204-256`).
  - `last i` is `getD 0`, so `serverOf` reads `lines.getD (0 - 1)`, the first line. That is a voter's
    `InitState`, at position 0 (`raft.go:469`, `traceInitState` before `confchange.Restore`).
  - `cfgOf`/`bconfOf` give `[]`, and `lb.ev.log = 0` gives an empty log. The result is `bootJunk`
    (`TraceSimGhost.lean:153`), field by field.
  - `newTrace_simInit` (`TraceSimEnd.lean:122`) goes from `newTrace_of_bootDone`'s literal
    `{ simInit C with s := fun i => if … then (simInit C).s i else bootJunk }` to `simInit C` through
    `simInit_s_nonvoter`. This is machine-checked.
- **Raft's last bootstrap event under `StartNode`.**
  - `setupNode` (`node.go:250-265`) calls `Bootstrap`, which runs `becomeFollower(1, None)` and then one
    `applyConfChange` per peer (`bootstrap.go:52-80`).
  - Each `applyConfChange` goes through `switchToConfig` (`raft.go:1952-1971`), whose first statement is
    `traceConfChangeEvent` (`:1981`). A follower returns at `:2012`, so it logs nothing else.
  - `newNode` logs nothing. `go n.run()` comes after `setupNode`. Before the harness's `app` goroutines
    exist, `run` can only arm `readyc`; `traceReady` is in `acceptReady` (`rawnode.go:437`).
  - So when `setupNode` ends, the segment is exactly `|C|+4` lines, the last at `BootEvAt C id (|C|+3)`.
  - `Bootstrap`'s error path only warns (`node.go:259-261`). `StartNode.gatedSpec`'s precondition rules
    it out: `restartStorage … []` and `bootMarshal`.
  - Duplicate peers are excluded by `nodeBootU`'s `ps.Nodup` (`InvApiBoot.lean:53`).
- **The harness** (`concurrent.go:151-231`).
  - The `StartNode`s run sequentially on the main goroutine (`:157-176`), so `□ [∗list] i ∈ vs,
    startDone γ i` is collectable before `return c, nil`.
  - The loop also calls `RestartNode` with the same `TraceLogger` for `ExtraNodes`. Those nodes' events
    would break `BootSegs`'s "every event is a voter's". `Workload` pins `cfg.ExtraNodes' = 0`
    (`Spec/.../tracecheck/RunConcurrent.lean:53`), so `FullCConfig` (`concurrent.go:111-117`) is
    outside the verified workload. This is consistent, and no finding.
- **Soundness of the witness against a client that allocates `dn`.**
  - The harness allocates `monoListAuthOwn tn.dn 1 []` itself (`HarnessAlloc.lean:115`), and
    `bootDone`'s body is visible: `TraceSimGhost` is importable, `etc/api/raft.txt:152`.
  - Even so, a client cannot forge `bootDone tn i`. `Cluster.traceSim_alloc` consumes the full
    authority at `[]`, and an index witness exists only for an element the authority holds. A mono list
    authority cannot shrink back to `[]` after an append that would mint one.
  - `traceDir` agreement pins `tn`.
- **The minting law** (`TracedHooksGlobal.lean:1445-1490`).
  - The proof opens `simInv`, reads the flag `false` from `Bt` (so `¬ booted`), and gets `BootDone` from
    `bootDone_of_last`. It appends `id` to `Dn` and returns the index witness at `Dn.length`.
  - The capability is returned with the same `Λ` and the same last event `x`, so the law can be applied
    again.
  - No Go bug found. Nothing for `issues/`.

- **(2nd, new) Two premises that are not needed: `hne : vs ≠ []` and `hlen : vs.length < 2 ^ 40` on the
  client end law.** (PRINCIPLES: "No unneeded premise"; "No constant or conjunct whose reason you do not
  know"; Size.)
  - **`hne`.** The law already takes `nodeBoot γ N vs ctxs id`, and `nodeBootU`'s pure part has
    `id ∈ ps` (`InvApiBoot.lean:53`), so `vs ≠ []` follows. The Draft's proof discards that part
    (`icases Hb with ⟨⟨-, ⟨%HNs, -⟩, -⟩, -⟩`, `TracedApiDraft.lean:259`).

    `gInt_nat : n < 2 ^ 40 → gInt (W64 n) = n` (`TraceSimBootFacts.lean:758`, used at `:780,782`).
    `gInt` is `sint.Z` (`TraceSim.lean:41`), so `n < 2 ^ 63` suffices. `nodeBootU` gives
    `(ps.length : Int) < 2 ^ 62`. The `2 ^ 40` is the bootstrap gate's constant (`TraceEv.OkBoot`'s
    `logSize < 2 ^ 40`), borrowed here as slack.
  - **Who pays.** `bootEnd`, `runOk_at_end` and `runOver_intro` (`HarnessEnd.lean`) carry both, and the
    future `RunConcurrent` proof must discharge them. That is trivial for `[1,2,3]`, but they are client
    API premises with no need.
  - **Restatement.**
    - Weaken `newTrace_of_bootDone`/`newTrace_simInit`/`simInv_end_bootDone`'s `hCl` to
      `C.length < 2 ^ 62`, or derive it inside.
    - In `Cluster.traceSimInv_bootEnd`, take `id ∈ vs` and the length bound from `nodeBoot`'s pure
      part.
    - Drop `hne`/`hlen` from `Cluster.traceSim_bootEnd`, `bootEnd`, `runOk_at_end` and
      `runOver_intro`.
  - This is not first-tier: the harness can meet both.
  - Uncertain: I did not check that `2 ^ 62` goes through `word` at both use sites.
- **(2nd, cosmetic)** `newTrace_simInit` concludes `server ∧ initSrv ∧ init`, while
  `simInv_end_bootDone`, `Cluster.traceSim_bootEnd` and `BootFacts` use `init ∧ server ∧ initSrv`. So

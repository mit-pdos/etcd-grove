## First tier

### F1. `RestartNode` in an untraced cluster still admits a non-nil logger, whose hooks raft cannot prove

**The claim.**
- sim.md:561: "`RestartNode` takes `γ.raft.reTrace = none`".
- sim.md:488-490: "the constructors' premise (Q1) becomes `isTraceLogger γt cv.TraceLogger'` inside the
  triple (`γt` a new binder; `isTraceLogger_nil` for a nil logger, any `γt`)".
- Plan Q1 (plan:47-49) names the constructors: `NewRawNode`, `StartNode`, `RestartNode`.
- Plan Q6 (3): "`isTraceLogger γt …` in the constructors' premise".
- Only `StartNode` gets the biconditional `cv.TraceLogger' ≠ nil ↔ γ.raft.reTrace ≠ none` (sim.md:559-560).

**The evidence.**
- `RestartNode` today takes `TraceLoggerOk cv.TraceLogger'` (`RestartNode.txt:24`), which means `tl = nil`
  (`InvLogger.lean:72`). Under Q1's increment 2 it takes `isTraceLogger γt tl` with `γt` free, so a
  non-nil logger is admitted.
- With `reTrace = none`, nothing ties that `γt` to `γ`.
- Every hook of that node must hand its logger `AU⟨∀ L, traceAuth γt L⟩⟨traceAuth γt (L ++ [e]), Q⟩`
  (sim.md:455-456). Raft cannot commit that update:
  - `traceFrag γt` is held "in lockstep" by `simInv γt` (sim.md:471-473). It has to be an exclusive
    fragment, or the exported law "from `simInv γt ∗ traceAuth γt L`" could not pin `L`.
  - In an untraced cluster raft owns no `simInv γt` for this `γ`.
- This is round 9 F2's second configuration ("a logger node in an untraced cluster", s4-r9.md), reached
  through `RestartNode` instead of `StartNode`. Round 9's own repair named only `reTrace = none` for
  `RestartNode`, and revision 10 copied it.
  - The `MsgSnap` half of round 9's argument applies too: an untraced cluster may compact
    (`⌜reTrace = none⌝` in `storBnd`), so `maybeSendSnapshot` is live and `traceSendMessage` fires.
  - The plain hooks (`InitState` in `newRaft`, every `traceBecome*`) are already enough.
- The harness is not affected: its `RestartNode` branch (`concurrent.go:172-173`) is dead under
  `DefaultCConfig` (`ExtraNodes = 0`). The exported contract is affected: `RestartNode.spec`'s proof is
  stuck on the first hook.

**Who it affects.**
- Raft's increment-2 proof of `RestartNode` (and of `NewRawNode`/`newRaft`, the internal constructors it
  calls).
- Q6 (3)/(8) as put to the user.

**Repair.** One clause, either form:
- `RestartNode` keeps increment 1's premise `TraceLoggerOk cv.TraceLogger'` (a nil logger) beside
  `γ.raft.reTrace = none`. Q1's "the constructors' premise becomes `isTraceLogger`" then names only
  `StartNode`.
- Or `RestartNode` takes the same biconditional as `StartNode`, which with `reTrace = none` gives a nil
  logger.

Say it in sim.md:488-490, sim.md:561, and Q1 and Q6 (8). `NewRawNode` has no importable spec
(`etc/api/raft.txt` lists only `StartNode`/`RestartNode`, :39-41), so its premise follows its callers'.

## Second tier

### S1. The permit must be persistent, and refutable by raft; say what it is

**The claim.** "a permit the allocation never hands out" (sim.md:397-398). `storBnd`'s third disjunct is
`permit` (sim.md:564). Nothing more is said of it.

**The evidence.**
- Every `MemoryStorage` client's `J.B` must be persistent: `MemJust.B_pers` (`InvMemstorage.txt:267`) and
  `memBnd_pers` (`:157`).
- Raft's `memStorage_isStorage` instantiates `isStorageP`'s `Bnd` with `memStorJ`'s `B`
  (`MemstorageApi.lean:44-46`, `:84-95`). The kv clients prove `memBnd (kvJ …) c ⊢ storBnd γ K c`
  (`KVStorageInstance.lean:273-275`).
  - So in a traced cluster, `storBnd γ K c` for `c > 0` is a persistent proposition.
  - An exclusive token, the natural reading of "a permit never handed out", would make it
    non-persistent. `storBnd` could then no longer serve as any `MemJust`'s `B`.
- Raft must also derive `False` from the permit. It meets `storBnd γ K c` with `c ≥ 1` through
  `Hbound : □ ∀ c, storCompacted st c ={⊤}=∗ Bnd c` (`InvStorage.lean:282`) at every `ErrCompacted`, and
  needs a contradiction there to make `maybeSendSnapshot` dead.
  - A persistent permit is refutable only against something raft holds. If the permit is an agreement
    fragment, the counter-fragment has to sit in raft's own persistent state (`isCluster`, `nodeBoot`).

**Who it affects.**
- Raft's increment-2 proof of the sender half (`maybeSendSnapshot` dead).
- The harness's `MemJust`.

**Repair.**
- State `permit := ⌜False⌝`, so the conjunct is `⌜c = 0 ∨ γ.raft.reTrace = none⌝`. This is persistent and
  refuted by `reTrace = some γt`.
- Or keep a named permit and say "persistent, refuted by raft against `X`". A future traced cluster with
  compaction would change the definition anyway.

### S2. The untraced clients' list: the server's `compactRaftLog` needs nothing, raft's own `memStorage_isStorage` does

**The claim** (sim.md:565-567): the pure fact is taken by "the `rfl` proofs of `kvJ_bnd`, `KvrStorageApi`,
`KdStorageApi` and the server's `compactRaftLog`". Plan Q6 (8): "from a law raft exports".

**The evidence.**
- `compactRaftLog` never builds `storBnd`. It calls `Compact` at raft's `memStorJ γr.cl K`
  (`EtcdServer__compactRaftLog.lean:113-118`, `:125-130`), whose `B k` is `nodeAppliedLb γ K k`
  (`MemstorageApi.lean:44`), and discharges it by `nodeAppliedLb_mono`. That is unaffected by the gate.
  (Round 9's S2 said the same of `:119,130`; that was its error.)
- Where `memStorJ` meets `storBnd` is raft's exported law `memStorage_isStorage`
  (`MemstorageApi.lean:84-95`):
  - It states `memStorInv ms γs γ K -∗ memStorReg ms γs -∗ isStorage γ K (memStorIface ms)`, and its proof
    needs `memBnd (memStorJ γ K) c ⊢ storBnd γ K c`.
  - With the gate it is **false as stated** for a traced cluster: `nodeAppliedLb γ K c` holds for some
    `c > 0` (the bootstrap entries are applied), and `storBnd` refuses it.
  - It is importable (`etc/api/raft.txt:90`, `MemstorageApi`), printed in raft's `Results.lean:455`, and
    used by the server (`NodeStart.lean:322`).
- The kv clients' `kvJ`/`kvrJ`/`kdJ` also have `B k := nodeAppliedLb γ K k` (`KvStorage.lean:436`, etc.).
  The note is right that their `*_bnd` lemmas take the fact.

**Who it affects.**
- Raft's API: one exported law changes statement, which is a diff in `interface/` for the user.
- The server, at `NodeStart.lean:322`, not at `compactRaftLog`.
- The harness: it cannot use `memStorJ`/`memStorage_isStorage`/`memStorInv_alloc`. It needs its own `J`
  (T3).

**Repair.**
- Replace "the server's `compactRaftLog`" by "raft's `memStorage_isStorage` (`MemstorageApi.lean:84`; the
  server takes it at `NodeStart.lean:322`), which gains `⌜γ.raft.reTrace = none⌝`".
- Alternatively, change `memStorJ`'s `B` to `storBnd γ K`. The server's `compactRaftLog` then takes the
  fact instead.
- List the changed law in Q6 (8).

### S3. Reviving `reNoSnap`: name the three places it changes

**The claim** (sim.md:568-572): "raft proves it by reviving its no-snapshot mode `reNoSnap` (…, dropped in
U8 v2, its plumbing still there: the outbox's 'no `.snap`', `LemmasReadyR.lean:236`, and `snapshotCert`'s
`⌜reNoSnap = false⌝`, `InvApi.lean:1497`) as `reNoSnap := reTrace.isSome`".

**The evidence.**
1. **`StartNode`'s premise pins the mode off.**
   - `nodeBoot` is `nodeBootU` (`InvApiBoot.lean:50-57`), which carries `∃ g, ModeDec γ … g`.
   - `ModeDec` includes `DecNames`, which includes `γ.raft.reNoSnap = false` (`InvApi.lean:170-174`).
   - `StartNode.lean:411` uses it (`Hns : γ.raft.reNoSnap = false := Hmr.1.2.2.2.1`).
   - With `reNoSnap := reTrace.isSome`, a traced cluster's `nodeBoot` is unsatisfiable until `DecNames`
     drops or weakens that conjunct.
   - The same holds of `UniNames.noSnap` (`InvApi.lean:2047-2051`) and of `api_sentSnapCert`'s
     `Hns : γ.raft.reNoSnap = false` (`InvApi.lean:2015`).
   - Internal and sealed (`nodeBoot` is `(sealed)`), so this is not first tier, but it is not "plumbing
     still there".
2. **The receiver half has no clause.**
   - The outbox fact (`InvRawnode.lean:2884`) is the sender's.
   - What a receiver sees is `isRaftMsg` (`ApiVocab.lean:423-428`), which today has no
     `reNoSnap = true → type ≠ MsgSnap`. `StepGhostMode.lean:411-415` records that it once did.
   - `qCert` (`InvRawnodeReady.lean:552`) makes the certificate *vacuous* in the mode. It does not make a
     `MsgSnap` impossible.
   - Without the clause, a node stepping a `MsgSnap` in the mode restores it, and its next `Ready` must
     produce `readySnap … (some l)`, hence `snapshotCert`, hence `reNoSnap = false`: stuck.
   - So `isRaftMsg` (public vocabulary, `ApiVocab`) or `isMessageC` gains the clause, fed by the outbox
     fact at `Ready`.
3. **`reNoSnap_ok : reNoSnap = true → reBootRaw ≠ []`** (`Ghost.lean:352`) becomes
   `reTrace.isSome → reBootRaw ≠ []`.
   - `cluster_alloc` then needs the premise `tr.isSome → boot ≠ []` (`InvNodeRule.txt:50-58` takes
     `boot`, possibly `[]`).
   - The harness allocates with the bootstrap log (`StartNode` needs `nodeBoot`, the `boot ≠ []` branch),
     so it is met. The law must say so.
- Also: `NsCap` (`InvRaftPhys.lean:852`) is now `⌜ns = false⌝`. In the mode it must become "the storage
  never compacted past 0". That follows from `isStorageP`'s `Hbound` and S1's refutable permit, and is not
  stored.
- **Uncertain:** whether the mode's node-level facts (`LogNsOk`, `PrLo`, `ownRaftGhost_ns_last`) were
  ever proved for the dynamic mode `ModeDec` puts `StartNode`'s clusters in. The mode was introduced with
  the static allocation `ownRaftGhost_alloc_boot` (`Protocol/Facts.lean:1725-1745`, `reTracked = some cfg`).
  The generic allocation takes `ns` for any `dyn` (`Facts.lean:1365-1380`), but I did not check the step
  proofs. The old mode capped compaction at 1 (`Next ≥ 2`). The gate caps it at 0, which needs only
  `Next ≥ 1`, so the facts should be simpler.

**Who it affects.** Raft's increment-2 proofs (S5's estimate); not the user's Q6, except `isRaftMsg` if it
is the public vocabulary that changes.

**Repair.** One sentence in the gate paragraph: "the revival relaxes `DecNames`'s `reNoSnap = false`
(`nodeBoot`), adds `reNoSnap = true → type ≠ MsgSnap` to the message facts (`isRaftMsg`, from the outbox
fact), and `cluster_alloc` takes `tr.isSome → boot ≠ []`".

## Verdict

**No first-tier finding.** Every amended statement is true, is provable from what its callers hold, and
is enough for them:

  (`per.find?` misses, `getD 0`), so `lines.getD (0 - 1)` reads the first line, a voter's `InitState`:

  (`TraceSimBootFacts.lean:548`) proves exactly this form. `bootInit_eq` (`TraceSimEnd.lean:151`)
  rewrites it to `simInit C`.
- **Other readers of `simInit`.**
  - `SimRun`/`linesTrace` (`TraceSimGhost.lean:214,220`), `simRun_first`'s `(simInit C).violated`
    (`TraceSimRun.lean:109`) and `TraceSimMatch.lean:3422-3436` all re-elaborate.
  - The proofs that read a server at a voter (`specInv_simInit`, `cfgFixed_simInit`,
    `srvFacts_simInit`, `simFx_simInit`, `keptFrom_simInit`, `msgsShape_simInit`) now go through
    `simInit_s_voter`.
  - `simInit_state` and `committedL_simInit` stay premise-free: both branches are followers, and
    `bootJunk`'s log is empty.
  - No proof depended on a non-voter's server being a voter's. The change makes `SimRun` start from
    the state TLC actually starts from.
- **The last bootstrap event.** `StartNode` (`node.go:271`) runs `setupNode`: `NewRawNode`, then
  `rn.Bootstrap(peers)`, then `newNode`, then `go n.run()`.
  - `Bootstrap` (`bootstrap.go:52-80`) logs `becomeFollower(1)` (position 3). It then calls
    `applyConfChange` once per peer, each through `switchToConfig`, whose first statement is
    `traceConfChangeEvent` (`raft.go:1981`). For a follower `switchToConfig` returns at `raft.go:2012`
    without logging anything else.
  - `newNode` logs nothing.
  - So the last bootstrap event is `ApplyConfChange` at position `|C|+3`, which is
    `BootEvAt C id (|C|+3)`; the `k+4` arm needs `k < |C|`, which holds because `vs ≠ []`.
  - Bootstrap's error paths cannot happen under `StartNode.gatedSpec`'s precondition, so the witness
    can be minted at the end of `setupNode`: `restartStorage … []` gives `LastIndex = 0`,
    `nodeBoot` carries `bootMarshal` (`InvBoot.lean:16`), and `vs = pv.map Peer.ID'`, so `peers ≠ []`.
- **The law's premise `hΛ` is dischargeable.** `hΛ` quantifies over the capability's `C` through `Φ`.
  A caller pins `C = vs` with `trCapB_pinDir` (`TracedRaftStepRecv.lean:1074`) and agreement with its
  own `traceDir` (`startTrace` gives `tn.voters = vs`). This is the same pattern as
  `trCap_fire_boot`'s `BootNext C` premise, and it answers design-r1's S4.
- **The harness can meet the end law's premise.** `RunConcurrent` (`concurrent.go:157-176`) calls the
  three `StartNode`s sequentially on the main goroutine, before any `app` starts. Each call's post
  gives a persistent `startDone γ i`, so the main goroutine holds `□ [∗list] i ∈ vs, startDone γ i` at
  `return c, nil`.
  - `traceDir γd tn` and `Cluster.trace γ = some γd` come from `harness_alloc`
    (`HarnessAlloc.lean:153-156`).
  - `vs ≠ []` and `vs.length < 2^40` hold for `[1,2,3]`. They are not implied by `hC` because
    `numBound = 2^61`.

    `simInit C := … s := fun i => if i ∈ confAbs C then bootSrv C else bootJunk`, and

### `TraceNames`, `bootDone`, `simInv`'s new clause (`TraceSimGhost.lean:128,314,328-349`)

Good:
- **The deviation from the design (a mono list rather than a ghost map) is right.**
  - The design's `ghostMapElem tn.dn i DfracDiscarded ()` would need the key to be absent at insertion.
    So a second `trCapB_bootDone` on the same node would need either a membership case split or a
    persistent copy of every element kept in the invariant.
  - `monoListAuthOwn_update_app [id]` plus `monoListIdxOwn_get` mints a witness on every application,
    with no case split. Duplicates in `Dn` are harmless: they are ghost, and the clause is a `∀ i ∈ Dn`.
  - `AllG GF` covers the functor, so there is no new instance binder.
  - Record the deviation where A8.2 is written. `notes/trace-check-design.md` §2.2 and §5.3 still say
    `ghostMapAuth tn.dn 1 ∅` and `ghostMapElem`.
- **Soundness of the clause.**
  - It is established at allocation with `Dn = []`.
  - It is kept by every law that extends `L`, through `bootDn_snoc` → `bootDone_snoc`. The argument
    is right: an extension would put a `|C|+5`-th element in the segment, and `BootSegs` would then
    require `BootEvAt C i (|C|+4)`, whose arm needs `|C| < |C|`.
  - It is kept with `L` unchanged in `trCapB_perm` (design-r1 S11) and the end laws.
  - Lean checks that every `simInv` re-establisher carries `Dn`. They all elaborate.
- `bootDone` is persistent, and its instance is exported.

No findings.

### `trCapB_bootDone.statement` (`TracedCap.lean:1295`) and its proof (`TracedHooksGlobal.lean:1442`)

Good:
- This is the design's statement.
- It **can be applied repeatedly**: the capability is returned unchanged, and the mono list appends
  freely.
- It is **sound**: a witness exists only if `bootDone_of_last` proves `BootDone`. That needs all of:
  - the flag unset, so the node is not booted, so all its events are bootstrap-named (by
    `simRun_parse`) and its segment is all of its events;

  - `BootSegs` placing `x` at position `len-1`;
  - `bootEvAt_unique` (reused, as design-r1 S2 asked) fixing `len = |C|+4`.
- The witness cannot be minted for an incomplete segment.
- The conclusion `∃ tn, traceDir γd tn ∗ bootDone tn id` is literally `startDoneB` at a traced cluster.
  The future `setupNode` proof needs no glue.
- The mask is `↑(simNS γ) ⊆ E`, a subset premise.

Findings:
- **(2nd, optional) The premise's shape.** `hΛ : ∀ C cs P o, Φ C cs P → Λ o → …` makes the caller
  pin `C` first. That is a few lines with `trCapB_pinDir`, and it is consistent with
  `trCap_fire_boot`.
  - Alternative: take the caller's `traceDir γd tn` and state `hΛ` at `tn.voters`, which `startTrace`
    gives as `vs`.
  - Keep the current form unless the `setupNode` proof finds the pinning costly.

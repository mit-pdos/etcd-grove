# etcd-grove (Lean)

This branch verifies **etcd** — starting with its Raft implementation — in Lean,
using the Lean port of Perennial (branch `lean` of
[mit-pdos/perennial](https://github.com/mit-pdos/perennial)), which is a Lake
dependency (`lakefile.toml`, pinned in `lake-manifest.json`). Perennial has the
framework and the Goose translator; this repository has the Goose translation of
etcd-raft (`EtcdRaft/`), of etcd's `cache` package (`EtcdCache/`), and the proofs.

It is a port of the Rocq development on branch `main` (`new/proof/go_etcd_io/raft/
election_proof/`). The Rocq notes on `main` (`notes/`) still describe the proof:
its design, the false statements found so far, what raft actually does. Read them
there (`git show main:notes/STATUS.md`); this branch's `notes/` only records what
is specific to the Lean port.

## Read the notes first

- `notes/STATUS.md` — where the port is.
- `notes/decisions.md` — how the Rocq structure maps to Lean, and why.

Before you finish, update `notes/STATUS.md` if anything moved.

## Layout

`EtcdGrove/Raft/` mirrors the Rocq directory `new/proof/go_etcd_io/raft/election_proof/`:

- the shared definitions (`Protocol`, `Defs`, `Inv*`, `StepLemmas`), outside the
  spec/proof discipline (predicates, pure lemmas);
- `Spec/<fn>.lean`: the one Hoare triple of a Go function, as `def <fn>.spec : Prop`;
- `Proof/<fn>.lean`: `theorem <fn>.wp_proof (callee specs …) : <fn>.spec`
  (an `axiom` at the trust boundary, `sorry` if unfinished); it imports only the
  `Spec` files of its callees;
- `Link.lean` (generated by `etc/gen-link.py`): links every proof to its callees'
  proofs (`theorem <T>.wp_<M> : <fn>.spec`); `Results.lean` states the protocol-level
  results.

## Trust base

`etc/tcb-report.py` reports what the proof rests on (needs `lake build`): the
`sorry`s and axioms the results depend on, the exported results (linked results no
other proof uses), and the definitions their statements are written in terms of. Run
it when you need the report; don't commit its output (`-o` writes a file), which goes
stale as the proof changes. `etc/tcb-report.py --check` exits 1 if this repository's
axioms or `sorry`s differ from `etc/tcb-baseline.txt`; when you add or remove one on
purpose, rerun with `--check --update`.

## How much is verified

`etc/verified-code.py` accounts for how much of raft's and etcd's Go code is verified
(needs `lake build` and `go`): every Go function is verified, unfinished, assumed,
translated or not translated, counted in functions and Go code lines, per package and
per file. It takes the projects from `etc/goose.py` and reads the Go sources of the
translated forks (in `.lake/go-src/<project>`, cloned or fetched at the pinned
revision), the translations in `EtcdRaft/` and `EtcdCache/`, and this repository's
proofs (`EtcdGrove.Raft.Link`, `EtcdGrove.Cache.Link`) from `.lake/tcb.json` (shared with `etc/tcb-report.py`; `--reuse` skips
re-running Lean). It prints plain text (`--markdown` for Markdown;
`-o FILE` writes Markdown if FILE ends in `.md`). Like the TCB report, don't commit
its output.

## The Goose translations

Two Lake libraries hold Goose translations by the pinned Perennial's translator, each
of a fork at the revision pinned in `etc/goose.py`. They are generated: never edit
the `.lean` files by hand.

- `EtcdRaft/{Code,GeneratedProof}/go_etcd_io/raft/`: etcd-raft (the fork
  `upamanyus/etcd-raft`), as the `EtcdRaft` library (modules
  `EtcdRaft.Code.go_etcd_io.raft.v3`, ...).
- `EtcdCache/{Code,GeneratedProof}/{go_etcd_io/etcd,k8s_io,google_golang_org}/`: etcd's `cache` package
  (the fork `upamanyus/etcd`, branch `goose-lean`; branch `goose` is the Rocq
  side's), with bodies, and the types and names
  only of the packages it uses (`client/v3`, `api/v3/{mvccpb,etcdserverpb,
  v3rpc/rpctypes}`, `k8s.io/utils/third_party/forked/golang/btree`, protobuf's
  `runtime/protoimpl`, `internal/impl` and `internal/pragma`), as the
  `EtcdCache` library (modules `EtcdCache.Code.go_etcd_io.etcd.cache.v3`, ...).
  Types Goose cannot translate are axiomatized, and their generated instances are
  `sorry -- axiomatized type`; no proof uses them yet.

goose's `-lean-root` maps every non-standard-library Go path a translation reaches to
its library, keeping the modules out of the `Perennial.*` names (which Lake resolves
to the Perennial library); standard-library packages are Perennial's.
`etc/goose.py` regenerates both (after bumping the Perennial or a fork pin, or
editing the Goose configuration `<lib>/Code/**/*.toml`; `--project NAME` for one);
`etc/goose.py --check` exits 1 if they differ from what the pinned translator
produces, and CI runs that check before the build. `--src NAME=DIR` (or
`$ETCD_SRC`, `$ETCD_RAFT_SRC`) translates from a local checkout of the fork instead
of cloning the pin, e.g. for a pinned revision not yet pushed; the output says so,
and `--check` then requires the checkout to be at the pinned revision. To try a
translator change before it is in Perennial, `etc/goose.py --perennial ../perennial`
regenerates with that checkout's translator, and
`lake build --packages=<file>` (a JSON list with
`{"type": "path", "name": "perennial", "dir": "../perennial", ...}`) builds against
it.

## Building

`lake build` (needs the `elan` toolchain in `lean-toolchain`).

`etc/build-report.py build [LAKE_ARGS…]` runs `lake build` and then reports on it:
wall and CPU time, parallelism over time, the critical path (with Lake's idle time
per step), the unlimited-cores bound, the slowest modules and where the CPU went.
CI (`.github/workflows/lean.yml`) runs the build this way and puts the report on
the run's summary page. `etc/build-report.py` alone reprints the latest report,
`--list` lists the recorded builds (`.lake/build-report/`).

# Index of the issues

Every file in this directory, one row each, in alphabetical order: what kind of finding it is,
where it stands upstream (the file's front matter, `upstream:`; `etc/issues-status.py` has the
links), and the one or two things most worth knowing to decide whether to open it: the impact,
what it takes to reach it, or the code fault. The findings judged not to be issues (and documentation parked for now) are in
[nonissues/](nonissues/README.md), with an index of their own. Priorities are in [RANKING.md](RANKING.md); the
details, reproduction and fix are in each file.

Add a row when a file is added, and update the row when its upstream state or its assessment
moves. A row's assessment is as of the date in its file; "fork" is the verified fork
(`upamanyus/etcd` `goose-lean`, `etc/goose.py`'s pin).

Kinds: **safety** (a core guarantee broken: lost or wrong committed data, linearizability, a
lock or leadership held twice, watch events skipped), **crash** (a panic or a process exit),
**wrong result**, **liveness** (a hang or a stall), **race** (a data race), **precondition** (an
unstated precondition, no bug for a caller that keeps it), **docs** (documentation the code
contradicts or does not state), **metric**, **test code**.
